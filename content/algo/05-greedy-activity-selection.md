# E05. 탐욕 선택과 반례: 종료가 가장 이른 활동 고르기

## 개요·필요성·선수·목표
한 강의실에서 시간이 겹치지 않는 활동을 최대한 많이 진행하려 한다. 모든 조합을 만들지 않고 지금의 한 선택을 확정하는 탐욕 알고리즘을 배운다.
선수는 배열·구조체·함수, E02의 정렬된 입력 계약이다. 예상25분. 목표는 종료가 가장 이른 활동을 고르는 이유, 반례로 잘못된 기준을 깨는 법, 입출력 보존 계약을 설명하고 구현하는 것이다.
범위는 종료 시각 오름차순으로 주어진 활동0~16개다. 이번 원고와 비공개 GCC 계약은 준비 단계이며 화면·퀴즈·제출/재제출 연결은 다음 실행에서 인수한다.

## 이론: 탐욕 선택
각 활동은 반열린 구간 `[start, finish)`다. 앞 활동이 시각4에 끝나면 다음 활동은4에 시작할 수 있다.
종료 시각이 가장 이른 호환 활동을 고르면 뒤에 남는 시간이 가장 길다. 입력이 finish 오름차순이므로 왼쪽부터 훑으며 `start >= last_finish`인 활동만 선택한다.
선택한 활동의 finish만 경계로 갱신한다. 겹쳐서 버린 활동은 다음 선택의 경계를 바꾸지 않는다.

## 이론: 교환 논증과 불변식
어떤 최적해의 첫 활동보다 탐욕 활동이 더 늦게 끝나지 않는다. 최적해의 첫 활동을 탐욕 활동으로 바꿔도 이후 활동은 그대로 들어간다. 따라서 탐욕 선택을 포함하는 최적해가 존재한다.
반복문의 불변식은 “지금까지 본 활동에서 선택 목록은 서로 겹치지 않고, 마지막 종료 시각 뒤의 공간을 최대한 남긴다”다.
이 설명은 활동 수 최대화에 대한 것이다. 총 사용 시간이나 가치 합을 최대화하는 문제에는 같은 기준을 그대로 쓰면 안 된다.

## 반례: 그럴듯한 기준 깨기
가장 이른 시작을 고르면 `[0,10)` 하나가 `[1,2) [2,3) [3,4)` 세 개를 막는다. 시작이 빠르다는 사실은 뒤 공간을 보장하지 않는다.
가장 짧은 활동도 항상 정답은 아니다. 길이가 짧아도 가운데를 차지해 앞뒤 두 활동을 동시에 막을 수 있다.
반례는 작은 입력, 두 답의 선택 과정, 목표값 차이를 함께 적는다. 단순히 “틀린다”고 쓰는 것보다 명세가 무엇을 최대화하는지 드러낸다.

## 도식: 정렬→호환 확인→선택
다음 표는 공개 예제의 한 번 순회다. 독자 도식은 실행 애니메이션이 아니라 손으로 추적하는 표다.
| 인덱스 | 구간 | 직전 종료 | 판단 |
|---:|---|---:|---|
| 0 | [1,4) | 없음 | 선택 |
| 1 | [3,5) | 4 | 겹침, 건너뜀 |
| 2 | [0,6) | 4 | 겹침, 건너뜀 |
| 3 | [5,7) | 4 | 선택 |
| 4 | [8,9) | 7 | 선택 |
| 5 | [5,9) | 9 | 겹침, 건너뜀 |

## 계약: 정렬·용량·보존
`select_activities(activities,count,selected_indices,capacity,selected_count)`는 성공1·거부0이다.
count는0~16이고 각 start는 finish보다 작다. 입력은 finish 비감소 순서다. 종료가 같으면 먼저 나온 활동을 먼저 검토한다.
count>0이면 두 배열은 NULL이 아니고 capacity는 count 이상이어야 한다. selected_count는 항상 필요하다. 빈 입력은 배열 두 개가 NULL이어도 성공하고0을 기록한다.
성공하면 고른 원래 인덱스를 선택 순서대로 쓰고 나머지 출력 칸과 입력을 보존한다. 거부하면 유효한 입력·출력·selected_count를 모두 보존한다. 배열 영역은 서로 겹치지 않아야 한다.

## 완성 프로그램: 직접 컴파일
아래는 관찰용 main을 포함한다. 제출에는 main과 stdio 출력 없이 구조체 선언·선택 함수만 넣는다.
```c
#include <stdio.h>
#include <stddef.h>
struct Activity { int start; int finish; };
int select_activities(const struct Activity activities[], size_t count,
                      size_t selected_indices[], size_t capacity,
                      size_t *selected_count) {
    if (selected_count == NULL || count > 16 || capacity < count
        || (count > 0 && (activities == NULL || selected_indices == NULL))) {
        return 0;
    }
    for (size_t i = 0; i < count; ++i) {
        if (activities[i].start >= activities[i].finish
            || (i > 0 && activities[i - 1].finish > activities[i].finish)) {
            return 0;
        }
    }
    size_t written = 0;
    int last_finish = 0;
    for (size_t i = 0; i < count; ++i) {
        if (written == 0 || activities[i].start >= last_finish) {
            selected_indices[written++] = i;
            last_finish = activities[i].finish;
        }
    }
    *selected_count = written;
    return 1;
}
int main(void) {
    const struct Activity items[] = {{1,4},{3,5},{0,6},{5,7},{8,9},{5,9}};
    size_t selected[6] = {0};
    size_t count = 0;
    if (!select_activities(items, 6, selected, 6, &count)) return 1;
    printf("count=%zu\n", count);
    for (size_t i = 0; i < count; ++i) printf("%zu%c", selected[i], i + 1 == count ? '\n' : ' ');
    return 0;
}
```
컴파일: `gcc -std=c11 -Wall -Wextra -Wpedantic -Werror example.c -o example`。실행: Linux/macOS `./example`, Windows `.\example.exe`.

## 출력과 이유
```text
count=3
0 3 4
```
인덱스0은4에 끝난다. 1·2는 시작이4보다 작아 버리고, 3은5에 시작해 고른다. 이어7 이후에 시작하는4를 고른다.
함수는 활동 값이 아니라 원래 인덱스를 돌려주므로 호출자는 이름·장소 같은 별도 정보와 다시 연결할 수 있다.

## 흔한 오류·중간 점검
끝과 시작이 같은 활동을 겹친다고 판단, 버린 활동의 finish로 경계 갱신, 정렬되지 않은 입력 묵인, 검증 전에 출력 수정이 흔한 오류다.
중간 점검: `[1,4)` 뒤 `[4,6)`은 가능한가? 가능하다. 반열린 구간에서 시각4는 앞 활동에 포함되지 않는다.

## 핵심 요약·퀴즈
퀴즈: 활동 수를 최대화할 때 다음 선택 기준은? ①가장 이른 시작 ②가장 짧은 길이 ③가장 이른 종료 ④가장 늦은 종료. 정답③.
정렬된 입력의 선택은 시간 O(n), 추가 작업 공간 O(1)이며 결과 배열은 호출자가 제공한다. 정렬까지 함수가 맡는 별도 명세라면 O(n log n)이 필요하다.

## 직접 풀기·실제 테스트·개선
기초: 유효성 검사와 첫 활동 선택을 작성한다. 응용: 공개 예제를 표로 추적하고 선택 인덱스를 예측한다.
도전: 빈 입력·음수 시각·같은 종료·끝점 접촉·잘못된 구간·역순·부족한 용량·반복 호출을 검사한다. 10사례는 입력과 여분 출력, 거부 시 count 보존도 확인한다.
실패 사례가 나오면 선택 경계와 비교 연산자를 기록하고 수정한 뒤 전체를 재제출한다. 기능 검사는 교환 논증 자체를 증명하지 않으므로 반례와 불변식도 말로 설명한다.
