# F02 — 변수 바인딩·가변성과 스칼라 형

## 개요·필요성·선수·목표
접수 건수처럼 바뀌는 값과 기준값처럼 보존해야 하는 값을 구별하자. Rust의 let과 mut는 그 의도를 선언에 드러낸다.
선수: F01의 함수·인자·반환값·Cargo 테스트. 예상25분. 목표는 불변 바인딩, 재대입, 가림, i32와 bool을 작은 함수로 설명하고 검사하는 것이다.
이번 범위는 정수 증감과 0 이상 판정이다. 반복·분기 설계, 소유권·참조, 문자열 입력 처리는 다음 단원으로 넘긴다.

## 이론 — 바인딩과 재대입
let before = 3;은 before라는 이름을 값에 연결한다. 기본적으로 이 바인딩에는 다른 값을 다시 대입할 수 없다.
let mut current = start;는 current에 재대입하겠다는 뜻이다. current += step;은 기존 값에 step을 더해 같은 바인딩에 저장한다.
mut가 없는데 +=를 쓰면 실행 중 실패하는 것이 아니라 컴파일 단계에서 거부된다. 컴파일 오류와 테스트 단언 실패는 고치는 순서가 다르다.

## 이론 — 정수와 불리언을 구별하기
i32는 부호 있는 32비트 정수이고 bool은 true/false다. value >= 0의 결과는 정수가 아니라 bool이다. C의 참·거짓 정수 표현과 그대로 혼동하지 말자.
이 실습의 start와 step은 각각 -1000 이상1000 이하(양끝 포함)다. 합도 -2000 이상2000 이하라 i32로 표현할 수 있다. is_nonnegative는 i32 전체 범위에서 비교한다.
임의 정수의 덧셈이 언제나 안전하다는 뜻은 아니다. 범위를 넘는 산술의 일반 처리는 이번 계약 밖이며 다음 오류 처리 주제에서 다룬다.

## 도식 — 호출자의 값과 지역 바인딩
독자 정적 도식 키: rust-binding-copy. before=3을 인자로 넘겨 지역 current에 복사하고 current += -5 뒤 -2를 반환한다.
호출자 before는 여전히3이다. 여기서 i32는 Copy 형이다. 이 예를 모든 Rust 값이나 모든 C/Rust 인자 전달의 비용 규칙으로 일반화하지 않는다.

## 이론 — 가림은 같은 바인딩의 수정이 아니다
let label = 4; 뒤 let label = label > 0;은 같은 이름으로 새 바인딩을 만든다. 뒤의 label은 bool이다.
재대입은 기존 바인딩의 형을 바꾸지 않지만 새 let으로 가리면 다른 형을 사용할 수 있다. 둘 중 무엇을 썼는지 이름만 보지 말고 let이 다시 있는지 확인한다.

## 완성 프로그램 — 두 함수를 main에서 사용하기
다음은 완성 프로그램이다. 실습 제출에는 main을 빼고 pub 함수 두 개만 작성한다.
```rust
pub fn next_count(start: i32, step: i32) -> i32 {
    let mut current = start;
    current += step;
    current
}
pub fn is_nonnegative(value: i32) -> bool {
    value >= 0
}
fn main() {
    let before = 3;
    let after = next_count(before, -5);
    println!("{} {} {}", before, after, is_nonnegative(after));
    let label = 4;
    let label = label > 0;
    println!("{}", label);
}
```

## 실제 출력과 단계별 이유
```text
3 -2 false
true
```
3+(-5)=-2다. 함수의 지역 current만 바뀌어 before는3이다. -2 >= 0은 false, 새 label의 4 > 0은 true다.
rustc --edition=2021 -Dwarnings example.rs -o example로 컴파일하고 실행한다. 프로젝트에서는 F01의 cargo test 흐름을 재사용한다.

## 흔한 오류 — 선언과 결과를 나눠 확인하기
mut를 빼고 current += step을 쓰면 E0384 진단을 읽고 변경 의도에 맞게 선언을 고친다. 숫자0을 bool 대신 반환하면 형이 맞지 않는다.
value > 0은 0을 잘못 제외한다. step을 무조건1로 바꾸거나 결과를0으로 보정하면 음수 입력에서 틀린다.
반환할 마지막 식에 세미콜론을 붙이면 그 블록의 반환 의미가 달라진다. 이 함수에서 원하는 것은 i32 또는 bool 결과다.

## 중간 점검·퀴즈·핵심 요약
기존 퀴즈: 재대입 가능한 바인딩은? let mut / var / dynamic / constant. 정답은 let mut다. 기존 선택 번호와 사용자 퀴즈 키는 유지한다.
before=3, step=-5 뒤 before와 반환값은? 3과-2다. 요약: 기본 불변→변경 의도에 mut→다시 let이면 새 바인딩→비교 결과는 bool.

## 직접 풀기 — 기초·응용·도전
기초: next_count의 두 인자와 반환형을 쓰고 지역 값에 step을 반영한다. 응용: is_nonnegative로 음수·0·양수를 나눈다.
도전: 1000+1000과 -1000+(-1000), 증감 상쇄, 반복 호출을 확인하고 이전 호출 결과가 다음 호출을 오염시키지 않게 한다.
채점은 반환값을 검사한다. 올바른 불변 식 start + step으로 구현해도 통과한다. mut 사용 여부를 문자열 검색으로 강요하거나 코드를 실행하지 않고 정답으로 인정하지 않는다.
