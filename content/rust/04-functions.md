# Rust 함수·반환값과 단위 테스트

## 개요·필요성·선수 지식·학습 목표
반복되는 계산을 이름 있는 함수로 분리하면 호출자는 의도를 읽고 테스트는 작은 계약을 검증할 수 있다. F01의 Cargo 테스트, F02의 바인딩, F03의 식을 안다고 가정한다. 이번 목표는 매개변수와 반환형을 읽고, 마지막 식으로 값을 반환하며, 보조 함수를 독립적으로 테스트하는 것이다.

## 이론 1 — 함수 시그니처와 매개변수
`fn line_total(unit_price: u32, quantity: u32) -> u32`에서 이름 뒤 괄호는 입력, `-> u32`는 출력의 형이다. Rust 매개변수는 각 형을 반드시 적는다. 이 단원은 세 입력 모두 `0..=1000`만 사용하므로 곱과 덧셈은 `u32` 범위 안이다.

## 이론 2 — 문과 식, 마지막 식 반환
Rust 함수 본문의 마지막 식은 세미콜론 없이 쓰면 반환값이 된다. `unit_price * quantity`는 `u32` 식이다. 뒤에 세미콜론을 붙이면 값이 없는 단위 값 `()`이 되어 선언한 반환형과 맞지 않는다. 조기 종료가 필요할 때는 `return value;`도 쓸 수 있지만 여기서는 꼬리 식이 가장 간결하다.

## 이론 3 — 작은 함수의 조합과 테스트 경계
`checkout_total`은 상품 합계를 직접 다시 계산할 수도 있지만 `line_total`을 호출하면 이름과 책임이 선명하다. 단위 테스트는 공개 함수 둘을 따로 부르며 0, 1, 일반값, 상한을 확인한다. 공개 예제 하나만 맞춘 상수 반환은 다른 사례에서 실패한다.

## 정적 도식 — 인수에서 반환값까지
`checkout_total(250, 2, 80)`은 먼저 `line_total(250, 2)`를 호출해 `500`을 받고, 배송비 `80`을 더해 `580`을 반환한다. 화살표는 호출과 값 반환의 논리적 흐름이며 실제 스택 배치를 약속하지 않는다.

## 계약 — 구현할 두 함수
- `line_total(unit_price, quantity)`는 두 입력의 곱을 반환한다.
- `checkout_total(unit_price, quantity, shipping)`는 상품 합계와 배송비의 합을 반환한다.
- 입력은 `0..=1000`, 함수는 출력만 반환하고 외부 상태를 바꾸지 않는다.
- 서버 전용 10개 테스트가 두 함수와 경계를 독립적으로 검사한다.

## 완성 프로그램
```rust
pub fn line_total(unit_price: u32, quantity: u32) -> u32 {
    unit_price * quantity
}

pub fn checkout_total(unit_price: u32, quantity: u32, shipping: u32) -> u32 {
    line_total(unit_price, quantity) + shipping
}

fn main() {
    println!("{}", line_total(250, 2));
    println!("{}", checkout_total(250, 2, 80));
    println!("{}", checkout_total(900, 0, 0));
    println!("{}", checkout_total(1000, 1000, 1000));
}
```

## 출력 예측과 이유
출력은 차례로 `500`, `580`, `0`, `1001000`이다. 세 번째는 수량이 0이라 상품 합계와 배송비가 모두 0이다. 마지막은 `1000 × 1000 + 1000`이다.

## 오류 패턴과 점검 순서
반환 식 뒤 세미콜론을 붙여 `expected u32, found ()`가 나면 마지막 식을 확인한다. 배송비가 빠지면 상품 합계 검사는 통과해도 결제 합계 검사는 실패한다. 매개변수 순서, 반환형, 보조 함수 결과, 경계값 순으로 좁혀 본다.

## 퀴즈
1. `-> u32`는 무엇을 약속하는가? 2. 마지막 식의 세미콜론을 빼는 이유는? 3. `line_total`을 따로 테스트해야 하는 이유는? 답: 반환형, 식의 값을 반환하기 위해, 결제 합계의 다른 계산과 분리해 결함 위치를 찾기 위해서다.

## 직접 풀기와 개선 과제
먼저 스타터의 두 `0`을 계약에 맞는 식으로 바꾸고 `cargo test --offline`을 실행하라. 통과 뒤 `discounted_total(unit_price, quantity, discount)`을 추가하되 할인액이 상품 합계를 넘지 않는다는 사전 조건을 문서로 적어 보라.

상품 단가·수량·배송비를 가진 여러 줄을 계산하는 작은 라이브러리를 설계하라. 각 계산을 작은 함수로 나누고 0, 일반값, 상한을 포함한 독립 테스트를 작성한다. 입출력은 계산 함수 밖에 둔다.
