# F03. 조건·반복·식과 범위: 멈추기 전 짝수 누적

## 개요·필요성·선수·목표
횟수가 달라지는 자료를 매번 손으로 더할 수는 없다. 조건으로 필요한 값만 고르고, 중단 경계에서 반복을 끝내는 작은 함수를 만든다.
선수는 F01의 Cargo/함수 테스트와 F02의 let·mut·u32·bool이다. 예상25분. 목표는 조건의 참/거짓, 값을 만드는 if, 반복 범위의 끝, break와 continue의 차이를 추적하고 구현하는 것이다.
이번은 원고·독자 도식·서버 전용10사례 계약 준비다. F03 정의와 허용 목록을 명시적으로 주입한 개발용 서버의 API를 검사하지만 일반 실행 명령과 학습 화면에는 아직 연결하지 않는다. 화면·운영자 CLI·제출/재제출 연결은 다음 회차 인수 대상이다.

## 이론: 조건에는 bool이 필요하다
C의 if(n)처럼 정수를 그대로 조건으로 쓰지 않는다. Rust에서는 n != 0처럼 bool을 만드는 비교를 쓴다.
n >= stop은 중단 경계를 만났는지, n % 2 != 0은 홀수인지 묻는다. 참일 때 어느 블록으로 가는지 먼저 말로 읽자.

## 이론: if 식과 마지막 식
let end = if limit > 1000 { 1000 } else { limit };는 선택한 값을 end에 저장한다. 두 갈래는 같은 u32 값을 만든다. 바깥 세미콜론은 let 문을 끝낸다.
함수의 마지막 sum은 반환할 값이다. sum;으로 바꾸면 그 블록의 마지막 값이 정수 합계가 아니므로 선언한 반환형과 맞지 않는다. 반환값을 고르는 식과 일을 수행하는 문장을 구별하자.

## 이론: for와 끝을 포함하는 범위
0..end는 end를 제외하고, 0..=end는 end를 포함한다. end=4라면 후자는0·1·2·3·4를 방문한다. 0도 짝수지만 더해도 합은 바뀌지 않는다.
먼저 end를1000 이하로 제한해 범위가 최대1001개가 되게 한다. u32::MAX를 받은 뒤에야 커다란 반복 안에서 제한하는 방식은 피한다.
while은 조건이 참인 동안 반복한다. 반복 변수를 직접 갱신해야 한다. loop는 별도 종료 조건이 없으면 계속 반복하므로 이번 첫 구현은 범위가 보이는 for로 시작한다.

## 이론: break와 continue
break는 지금 반복 전체를 끝낸다. continue는 현재 회차의 나머지만 건너뛰고 다음 후보로 간다. 둘을 바꾸면 첫 홀수에서 합계를 일찍 끝내 버린다.
먼저 n >= stop이면 break한다. 그다음 홀수라면 continue한다. 두 조건을 모두 지나온 짝수만 sum에 더한다. 조건이 거짓이면 바로 다음 검사나 누적 단계로 이어진다.

## 도식: 선택하고 건너뛰고 끝내기
독자 정적 SVG 키는 rust-control-flow다. limit10·stop7에서 방문과 합계의 변화를 읽는다.
후보0 → 더하기0 → 후보1 건너뜀 → 후보2 더하기2 → 후보3 건너뜀 → 후보4 더하기6 → 후보5 건너뜀 → 후보6 더하기12 → 후보7 중단.
점검: 후보7은 홀수라서만 빠지는가? 아니다. stop에 도달해 반복 전체를 끝내므로 후보8도 더하지 않는다.

## 계약: 포함 상한과 제외 중단점
제출 함수는 sum_even_before이며 매개변수 limit·stop, 반환값은 모두 u32다. 모든 u32 입력을 받는다.
끝은 limit과1000 중 작은 값이다. 0부터 끝까지 포함하되 stop 미만인 짝수의 합을 반환한다. stop0이면0, stop이 끝보다 크면 끝까지 검사한다.
1000 제한은 Rust 언어의 규칙이 아니라 이 과제의 작업량 계약이다. 모든 결과는 최대 2+4+…+1000 = 2×(1+…+500) = 250500으로 u32에 들어간다.
stop-1을 먼저 계산하지 않는다. stop0에서 부호 없는 뺄셈의 문제를 만들지 않고 n >= stop으로 직접 비교한다. 파일·네트워크·전역 가변 상태·외부 크레이트는 필요 없다.

## 완성 프로그램: 직접 컴파일
아래는 main 포함 관찰용 완성 프로그램이다. 제출에는 main·println! 없이 pub 함수만 넣는다. 스타터도 컴파일되지만 정답은 아니다.
```rust
pub fn sum_even_before(limit: u32, stop: u32) -> u32 {
    let end = if limit > 1000 { 1000 } else { limit };
    let mut sum = 0;
    for n in 0..=end {
        if n >= stop {
            break;
        }
        if n % 2 != 0 {
            continue;
        }
        sum += n;
    }
    sum
}
fn main() {
    let limit = 10;
    let stop = 7;
    println!("{}", sum_even_before(limit, stop));
    println!("{}", sum_even_before(4, 10));
    println!("{}", sum_even_before(u32::MAX, u32::MAX));
    println!("{limit} {stop}");
}
```
example.rs로 저장하고 rustc --edition=2021 -Dwarnings example.rs -o example로 컴파일한 뒤 ./example을 실행한다. Cargo 제출 계획은 기존 edition2021·의존성 없음·오프라인·경고 실패 정책을 사용한다.

## 실제 출력과 이유
```text
12
6
250500
10 7
```
첫 줄은0+2+4+6, 둘째는 포함 상한4까지0+2+4다. 셋째는 큰 입력을1000으로 먼저 제한한 합이다. 마지막은 F02처럼 함수 호출 뒤에도 호출자의 두 정수 값이 그대로임을 관찰한다.
공개 예제의12는 함수 반환값이다. 테스트 하네스가 이를 단언하므로 제출 함수가 숫자를 출력하는 방식으로 대체하면 안 된다.

## 흔한 오류·중간 점검
포함 범위를 제외 범위로 쓰기, stop 자체까지 더하기, continue를 break로 바꾸기, 합계 대신 개수 증가, 상한 제한을 잊기, 마지막 반환 식 뒤 세미콜론이 흔한 오류다.
limit4·stop10의 답은6, limit10·stop4의 답은2다. 같은4라도 limit은 포함하고 stop은 제외한다. 두 입력을 서로 바꾸지 말자.

## 핵심 요약·퀴즈
선택한 끝 → 후보 반복 → 중단 비교 → 홀수 건너뛰기 → 누적 → 마지막 식 반환으로 요약한다.
퀴즈: limit10·stop4에서 합계에 들어가는 양의 정수는? ①2 ②2·4 ③1·3 ④2·4·6·8·10. 정답①이며4는 중단점이라 제외한다.

## 직접 풀기·실제 테스트·개선
기초: end를 if 식으로 구하고 sum을 가변 변수로 만든다. 응용: 0..=end와 두 조건을 연결해 함수로 반환한다.
도전: 0/1, 짝수·홀수 limit, 짝수·홀수 stop, 정확한1000, 초과 입력과 u32::MAX, 반복 호출을 예측한다.10사례는 이런 경계와 오답을 구분한다.
실패 사례의 n·현재 합·break/continue 여부를 표로 기록하고 수정→전체 재제출한다. for 문법 사용 여부나 시간 복잡도 자체를 결과 검사만으로 증명하지 않으며 같은 계약의 while 구현도 허용한다.

## Mini Project
