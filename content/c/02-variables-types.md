# 변수·자료형·연산자: 값을 계산하기 전에 계약을 정하기

## 단원 개요

변수를 만들고 값을 바꾼 뒤 두 정수의 합을 입력받아 출력한다. 이어 7 / 2와 (double)7 / 2의 차이를 예측한다. 표준의 최소 범위와 구현별 표현 방식은 접힌 심화에서 선택해 읽는다.

## 필요한 이유

`double result = 7 / 2;`를 보고 3.5를 예상할 수 있다. 하지만 오른쪽 식은 먼저 정수끼리 계산해 3을 만든다. 저장할 변수를 `double`로 정했다고 이미 사라진 소수부가 복구되지는 않는다.

같은 이유로 결과 변수만 넓은 형으로 바꾸면 앞선 좁은 형의 넘침이 해결된다고 생각해서도 안 된다. 선언을 읽을 때는 저장 객체를, 식을 읽을 때는 피연산자의 형과 연산 순서를 확인한다.

## 선수 지식

- 첫 C 단원의 헤더, `int main(void)`, 블록과 세미콜론
- `printf`로 출력하고 종료 상태를 확인하는 방법
- 코드 조각과 완성 프로그램의 구분

입력 코드의 `&a`는 우선 “`scanf`가 기록할 객체 `a`를 지정한다”로 이해해도 된다. 주소와 포인터의 내부 관계는 뒤에서 자세히 다룬다.

## 학습 목표

1. 변수를 초기화하고 대입 뒤의 값을 예상한다.
2. 정수 나눗셈과 계산 전 변환의 차이를 실행으로 확인한다.
3. 입력 두 개가 준비됐는지 확인하고 기존 합 문제의 경계를 테스트한다.

구현별 크기·최소 범위·정밀도·변환의 세부 계약은 심화에서 선택해 읽는다.

## 핵심 이론

### 1. 객체와 이름

```c
int count = 3;
```

이 지역 변수 정의는 `int` 값을 저장할 객체를 마련하고 이름 `count`로 접근하게 한다. 선언은 이름과 형식을 알리는 역할이고, 이 정의에서는 객체도 생긴다. `3`은 초기값이다. “변수는 상자”라는 비유는 시작점이지만 실제 객체에는 형·수명·범위·표현 방식 같은 규칙도 있다.

| 구분 | 예제에서의 의미 |
| --- | --- |
| 이름 | `count` |
| 형 | `int` |
| 현재 값 | `3` |
| 저장 공간 크기 | 이 구현의 `sizeof count` |

### 2. 초기화와 대입

```c
int count = 3;      // 정의하면서 초기화
count = count + 1; // 기존 객체에 새 값 대입
```

대입은 오른쪽의 현재 `count`를 읽어 식을 계산한 뒤 결과를 왼쪽 객체에 저장한다. `count = count + 1`은 수학의 등식이 아니다. 기존 값이 3일 때 새 값 4로 상태가 바뀐다.

```c
int a = 3;
int b = a;
a = 9;
```

이 조각에서 `b`는 여전히 3이다. 대입은 값을 복사하지 두 이름을 같은 객체로 합치지 않는다.

### 3. 초기화하지 않은 지역 변수

`main` 안의 자동 지역 변수 `int score;`가 자동으로 0이 되는 것은 아니다. 초기화 없이 읽으면 불확정 값을 다루게 되며 정의되지 않은 동작으로 이어질 수 있다. “쓰레기 값이 나온다”는 결과를 보장처럼 가르치지 않는다.

선언 직후 값을 정하거나, 입력 함수가 기록에 성공했음을 확인한 뒤에만 사용한다. 전역·정적 저장 기간 객체의 초기화 규칙은 다르며 후속 범위·저장 기간 단원에서 분리해 다룬다.

### 4. 정수 자료형의 최소 보장

정수는 `int`, 더 큰 합이 필요한 뒤의 반복 실습은 `long`을 사용한다. 담을 수 있는 범위는 형과 환경에 따라 다르므로 이번 합 실습은 작은 입력으로 제한한다.

<details>
<summary>심화: 정수 자료형의 최소 보장</summary>

| 형 | C11이 적어도 보장하는 표현 범위 | 실제 확인 |
| --- | --- | --- |
| `signed char` | -127~127 | `SCHAR_MIN`, `SCHAR_MAX` |
| `short` | -32767~32767 | `SHRT_MIN`, `SHRT_MAX` |
| `int` | -32767~32767 | `INT_MIN`, `INT_MAX` |
| `long` | -2147483647~2147483647 | `LONG_MIN`, `LONG_MAX` |

위는 모든 환경의 정확한 경계값이 아니라 **최소 보장**이다. 현재 컴파일러는 더 넓은 범위를 제공할 수 있다. 정확한 값은 `<limits.h>`로 확인한다. `int`가 항상 32비트이거나 `long`이 항상 64비트라고 생각하지 않는다.

`char`, `signed char`, `unsigned char`는 구분되는 형이다. 평범한 `char`가 부호 있는 쪽인지 없는 쪽인지는 구현에 따라 다를 수 있다.

</details>

### 5. C의 바이트와 `sizeof`

자료형의 정확한 바이트 크기를 외울 필요는 없다. 필요할 때 현재 환경의 `sizeof` 결과를 확인한다.

<details>
<summary>심화: C의 바이트와 `sizeof`</summary>

`sizeof(char)`는 1이다. 그러나 이것을 모든 C 환경에서 8비트라고 바꾸어 읽으면 안 된다. C 바이트의 비트 수는 `CHAR_BIT`로 확인하며 적어도 8이다.

`sizeof` 결과는 `size_t` 형이므로 출력할 때 `%zu`를 쓴다. 다음은 **`main` 몸체 안에 넣는 조각**이며 `<stdio.h>`와 `<limits.h>`가 필요하다.

```c
printf("bytes=%zu bits-per-byte=%d\n", sizeof(int), CHAR_BIT);
printf("int-range=%d..%d\n", INT_MIN, INT_MAX);
```

출력 숫자는 현재 구현의 관찰값이다. 다른 PC에서 값이 달라졌다고 무조건 오류는 아니다.

</details>

### 6. 정수 상수·부동소수 상수·`const`

정수 계산은 `7`, 소수 계산은 `7.0`처럼 적는다. 먼저 두 종류의 나눗셈 결과를 비교해 보자.

<details>
<summary>심화: 정수 상수·부동소수 상수·`const`</summary>

`7`과 `7.0`은 값의 표기뿐 아니라 형도 다르다. `7`은 이 경우 `int`, 접미사 없는 `7.0`은 `double`이다. `7.0f`는 `float` 상수다.

`const int limit = 10;`은 그 이름을 통해 값을 변경하지 못하도록 제약한다. 하지만 C의 `const` 객체를 모든 위치에서 사용할 수 있는 정수 상수 식과 똑같이 취급하면 안 된다. 배열 길이와 상수 식의 세부 규칙은 뒤에서 다룬다.

</details>

### 7. 부동소수의 범위와 정밀도

소수 계산에는 보통 `double`을 사용한다. 저장할 수 있는 정밀도가 유한하므로 계산 결과가 근사값일 수 있다.

<details>
<summary>심화: 부동소수의 범위와 정밀도</summary>

`float`·`double`은 유한한 표현을 사용하므로 실수 계산 결과가 근사될 수 있다. `<float.h>`의 최소 보장은 `FLT_DIG >= 6`, `DBL_DIG >= 10`이다. 이 값은 정해진 의미의 십진 정밀도 지표이지 모든 결과에 고정된 소수점 이하 자릿수를 보장한다는 뜻이 아니다.

일반적인 구현은 이진 부동소수를 사용해 0.1 같은 십진 소수를 정확히 저장하지 못할 수 있다. 다만 C11이 항상 IEEE 754 또는 이진 표현을 강제하는 것은 아니다. `FLT_RADIX`, `FLT_DIG`, `DBL_DIG` 등으로 환경을 확인한다.

큰 수까지 표현할 수 있는 **범위**와 가까운 값들을 구별할 수 있는 **정밀도**는 다르다. 출력의 `%.1f`도 저장값을 정확한 소수로 바꾸는 장치가 아니라 출력 자릿수를 지정한다.

</details>

### 8. 정수 나눗셈과 나머지

C11 정수 나눗셈은 몫이 표현 가능하면 소수부를 **0 방향**으로 버린다.

| 식 | 값 | 이유 |
| --- | ---: | --- |
| `7 / 2` | 3 | 정수 몫 |
| `-7 / 2` | -3 | 음수도 0 방향 |
| `-7 % 2` | -1 | `(-3) * 2 + (-1) == -7` |

음수에서 0 방향 버림은 내림과 다르다. 분모가 0이거나 정수 몫을 표현할 수 없는 경우는 정의되지 않은 동작이므로 정상 예제로 실행하지 않는다. `%`의 피연산자는 정수 형이어야 한다.

### 9. 연산 뒤 대입과 연산 전 변환

```c
double late = 7 / 2;
double early = (double)7 / 2;
double also_late = (double)(7 / 2);
```

- `late`: `int` 나눗셈 → 3 → `double` 대입 → 3.0
- `early`: 한 피연산자를 먼저 `double`로 변환 → 부동소수 나눗셈 → 3.5
- `also_late`: 괄호 안의 `int` 나눗셈 → 3 → 캐스트 → 3.0

캐스트의 존재보다 **언제 변환되는가**를 읽는다. 괄호는 형을 바꾸지 않고 묶는 순서를 표시한다.

### 10. 변환은 안전성을 자동으로 추가하지 않는다

형 변환은 나누기 전에 할지 뒤에 할지 구분한다. 바꾼 형에 담을 수 있는 작은 값으로 연습한다.

<details>
<summary>심화: 변환은 안전성을 자동으로 추가하지 않는다</summary>

유한한 부동소수 값을 정수로 바꾸면 소수부를 0 방향으로 버린다. `(int)-3.75`는 -3이다. 하지만 정수부를 목적 정수 형으로 표현할 수 없는 변환은 정의되지 않은 동작이다.

정수에서 다른 정수 형으로 바꿀 때도 범위를 확인한다. 표현 가능한 값은 유지되지만, 범위 밖 값을 signed 정수 형으로 바꾸는 결과는 C11에서 구현 정의 결과나 구현 정의 신호일 수 있다. 이 규칙과 **signed 산술 연산의 넘침**을 같은 것으로 혼동하지 않는다.

</details>

### 11. signed 넘침과 unsigned 모듈러 연산

계산 결과가 자료형의 범위를 넘지 않도록 입력 약속을 먼저 정한다. 합은 -20000~20000 안에서 계산한다.

<details>
<summary>심화: signed 넘침과 unsigned 모듈러 연산</summary>

`int` 덧셈의 결과가 그 형에 표현되지 않으면 정의되지 않은 동작이다. 계산한 뒤 음수가 되었는지 확인하는 방법으로 미리 막을 수 없다.

unsigned 연산은 해당 형의 최댓값 다음에서 모듈러 규칙으로 순환하지만, 이것이 곧 프로그램의 계산 의도가 안전하다는 뜻은 아니다. 음수와 unsigned를 섞은 비교에서는 변환으로 의미가 달라질 수 있다. 이 단원의 예제는 작고 범위가 정해진 같은 형의 값을 쓴다.

```c
long product = (long)20000 * 20000;
```

위 조각의 400000000은 C11의 최소 `long` 범위 안이다. `long product = 20000 * 20000;`로 바꾸면 곱셈 자체가 `int`로 먼저 수행되므로 좁은 구현에서 넘칠 수 있다. 목적 변수만 넓힌 것은 충분하지 않다.

</details>

### 12. 입출력 형식의 대응

| 객체/값 | `printf` | `scanf` |
| --- | --- | --- |
| `int` | `%d`, 값 전달 | `%d`, `int *` 전달 |
| `float` | `%f`, 호출 시 `double` 승격 | `%f`, `float *` 전달 |
| `double` | `%f`, 값 전달 | `%lf`, `double *` 전달 |

`printf`와 `scanf`는 같은 형식 문자열처럼 보여도 인수 계약이 다르다. 특히 `scanf`의 `%f`와 `%lf`를 바꾸어 쓰거나 `&`를 빼면 기록 대상의 형이 맞지 않아 정의되지 않은 동작이 될 수 있다.

### 13. `scanf` 반환값의 범위

`scanf("%d%d", &a, &b)`의 반환값 2는 두 변환 결과를 두 객체에 기록했다는 뜻이다. 1·0·EOF는 두 값을 모두 얻은 성공이 아니다.

<details>
<summary>심화: scanf와 임의 텍스트의 범위 검증</summary>

그러나 이 검사는 입력 범위를 증명하지 않는다. `%d`의 변환 결과를 `int` 객체로 표현할 수 없는 매우 큰 숫자 문자열은 단순히 0이나 EOF로 안전하게 거부된다고 기대하면 안 된다. C11에서는 이 경우 정의되지 않은 동작일 수 있다.

신뢰하지 않는 임의 텍스트의 강건한 검증은 후속 `fgets`·`strtol` 단원에서 처리한다. 이번 프로그램의 목적과 입력 전제를 먼저 밝힌다.

</details>

### 14. 기존 채점 계약

- 입력은 정확히 두 정수다.
- 각 피연산자는 `[-10000, 10000]`이다.
- 합은 `[-20000, 20000]`이므로 최소 보장 `int` 범위 안이다.
- 범위 밖 값·변환 실패·조기 EOF·추가 토큰은 이 기초 문제의 채점 계약 밖이다.

완성 프로그램은 변환 개수를 검사하지만 범위 밖 임의 텍스트를 모두 안전하게 검증하는 파서가 아니다. 아래 프로그램을 공개된 무제한 입력 서비스의 파서로 재사용하지 않는다.

## 정적 도식 읽기

화면 SVG는 두 경로를 대비한다. 위쪽은 `7 / 2` → `int 3` → `double 3.0`이고 아래쪽은 `(double)7 / 2` → `double 3.5`다. 화살표는 계산과 변환의 순서다. “대입은 소수부를 복구하지 않음”이라는 문장을 코드와 연결해 읽는다.

도식은 독자 제작 정적 SVG이며 실제 메모리나 실행의 애니메이션이 아니다.

## 단계별 예제

1. `count`를 3으로 초기화한다.
2. 현재 값을 읽어 1을 더하고 4를 저장한다.
3. 같은 숫자의 정수 나눗셈과 먼저 변환한 나눗셈을 비교한다.
4. 작은 음수를 사용해 0 방향 버림과 나머지를 확인한다.
5. 출력하기 전에 각 값과 식의 형을 말해 본다.

위의 짧은 코드들은 조각이다. 아래 두 코드는 헤더와 `main`을 포함하는 별도 완성 프로그램이다.

## 완성 프로그램 A: 값과 변환 관찰

```c
#include <stdio.h>

int main(void) {
    int count = 3;
    count = count + 1;
    double late = 7 / 2;
    double early = (double)7 / 2;
    int truncated = (int)-3.75;

    printf("count=%d\n", count);
    printf("integer=%d negative=%d remainder=%d\n", 7 / 2, -7 / 2, -7 % 2);
    printf("late=%.1f early=%.1f\n", late, early);
    printf("cast=%d\n", truncated);
    return 0;
}
```

## 실행 결과

프로그램 A의 입력 없는 출력:

```text
count=4
integer=3 negative=-3 remainder=-1
late=3.0 early=3.5
cast=-3
```

## 왜 이런 결과가 나오는가

`count`는 대입 뒤 4다. 정수 나눗셈은 몫을 0 방향으로 버리고 `-7`은 몫 -3·나머지 -1로 나뉜다. `late`는 정수 결과를 대입 때 변환하고 `early`는 계산 전에 변환한다. `(int)-3.75`의 정수부 -3은 `int`로 표현 가능하다.

## 완성 프로그램 B: 기존 두 정수 합

```c
#include <stdio.h>

int main(void) {
    int a, b;
    if (scanf("%d%d", &a, &b) != 2) {
        return 1;
    }
    printf("%d\n", a + b);
    return 0;
}
```

입력 `4 7`의 출력은 `11`과 개행이다. 계약 안의 양쪽 경계 입력 `10000 10000`과 `-10000 -10000`의 출력은 각각 `20000`과 `-20000`이다. 간단한 변환 실패/한 정수만 있는 EOF에서는 상태 1로 종료하고 합을 출력하지 않는다. 이 추가 관찰은 기존 채점 범위를 늘렸다는 뜻이 아니다.

## 흔한 오류

- 초기화하지 않은 자동 지역 변수는 “우연한 숫자가 보이면 괜찮다”가 아니다.
- `double q = 7 / 2;`는 3.5가 아니다. 피연산자를 먼저 바꾼다.
- `%f`/`%lf`는 출력과 입력에서 서로 다른 주소 계약을 가진다.
- `scanf` 인수에서 주소를 빼거나 변환 개수를 무시하지 않는다.
- signed 넘침은 계산 후 검사로 되돌릴 수 없다.
- `i++ + i++`처럼 같은 객체를 순서 없이 여러 번 변경하는 식을 예제처럼 실행하지 않는다. 별도 명령문으로 나눈다.
- 경고 없는 번역이 모든 범위·입력·동작을 증명하는 것은 아니다.

## 중간 점검

1. `int a = 3; int b = a; a = 9;` 뒤 `b`는 무엇인가?
2. `-7 / 2`의 결과는 내림인가 0 방향 버림인가?
3. `(double)(7 / 2)`는 왜 `(double)7 / 2`와 다른가?
4. `scanf` 반환값 2만으로 입력이 `[-10000, 10000]` 안임을 알 수 있는가?

확인: 3, 0 방향 버림, 캐스트 시점 차이, 아니오. 맞힌 개수뿐 아니라 각 이유를 자기 말로 적는다.

## 개념 확인 퀴즈

`int a = 7, b = 2;`에서 `a / b`는 무엇인가?

- 정답: 3
- 3.5를 골랐다면 정수끼리 계산된 식의 형을 다시 읽는다.
- 4를 골랐다면 정수 나눗셈이 반올림이 아님을 확인한다.

기존 화면 퀴즈와 정답 인덱스는 그대로 유지한다.

## 핵심 요약

이름·자료형·현재 값을 나누어 읽는다. 초기화는 첫 값을, 대입은 기존 객체의 새 값을 정한다. 식은 저장 변수에 대입되기 전에 피연산자의 형을 기준으로 계산된다. 최소 보장·실제 크기·표현 범위·정밀도는 따로 확인하며 입력 변환 개수와 입력 범위도 구분한다.

## 기초 코딩 연습

기존 `c-types` 문제를 풀어 두 정수 합을 출력한다. `4 7`, `-5 2`, `0 0`, 양쪽 경계의 예상값을 먼저 적는다. 설명 문구나 입력 프롬프트를 추가하면 자동 채점 출력과 달라질 수 있다.

## 응용 연습

`7 / 2`, `(double)7 / 2`, `(double)(7 / 2)`를 각각 한 줄로 출력한다. 먼저 형과 계산 순서를 표에 쓰고 실행 결과와 대조한다. 이어 -7과 2로 바꾸어 0 방향 버림을 확인한다.

## 도전 문제

`sizeof(int)`, `CHAR_BIT`, `INT_MIN`, `INT_MAX`, `FLT_DIG`, `DBL_DIG`를 출력하는 환경 관찰 카드를 만든다. 관찰값 옆에 “현재 구현”을, 문서의 최소 범위 옆에 “C11 최소 보장”을 붙인다. 한 번의 실행 결과를 모든 C 환경의 규칙으로 일반화하지 않는다.

## Mini Project

작은 점수 두 개를 입력받아 합과 평균을 출력하는 학습용 계산기를 만든다. 입력 계약을 각 0~100으로 정하고 평균의 나눗셈 전에 변환한다. 출력 자릿수는 한 자리로 정한다. 입력 `0 1`의 평균 0.5, `100 100`의 평균 100.0을 반드시 확인한다.

이 프로젝트의 강건한 텍스트 파서는 후속 `fgets`·`strtol` 학습 뒤 확장한다. 초기 버전에서는 신뢰하는 계약 입력을 사용한다.

## 테스트와 풀이 개선

`gcc -std=c11 -Wall -Wextra -Werror -Wpedantic`으로 두 완성 프로그램을 별도 파일로 번역한다. 경고 없는 빌드, 기대 표준 출력, 종료 상태를 각각 검사한다. B는 기존 5개 실제 채점 사례를 모두 통과해야 한다.

오답을 고친 뒤에는 “실수형으로 바꿈”이 아니라 **어떤 식의 어느 피연산자를 언제 변환했는지** 적는다. 미초기화 읽기·범위 밖 변환·넘침 예제는 의도적으로 실행해 정상 출력을 기대하지 않는다.

## 복습 연결

조건·반복 단원에서는 범위 판정과 반복마다 바뀌는 상태를 다룬다. 넘어가기 전에 초기값·불변 범위·입력 성공 조건·연산 형을 선언할 수 있는지 확인한다. 배열과 포인터에서는 여기서 배운 객체와 주소 구분을 확장하고, 텍스트 입력의 범위 검증은 `fgets`·`strtol` 단원으로 연결한다.
