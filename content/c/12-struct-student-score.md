# 구조체와 포인터로 학생 점수 갱신하기

> 이 원고와 예제·문제는 CodeWeave용으로 새로 작성했습니다. 상용 교재의 본문·그림·문제를 복제하지 않았습니다.

## 단원 개요

학생 한 명을 프로그램에서 표현하려면 학번과 점수처럼 서로 관련된 여러 값을 함께 다뤄야 합니다. 각각을 별도 변수와 배열로 흩어 놓으면 어떤 학번이 어떤 점수와 짝인지 계속 맞춰야 합니다. C의 구조체는 관련된 데이터를 하나의 객체로 묶고, 각 구성 요소에 이름을 붙입니다.

이 단원에서는 다음 자료형을 사용합니다.

```c
struct Student {
    int id;
    int score;
};
```

그리고 학생 객체의 주소를 함수에 전달하여 점수를 갱신합니다.

```c
int update_score(struct Student *student, int delta);
```

함수는 무조건 값을 바꾸지 않습니다. 포인터, 기존 점수, 변경량을 먼저 검사하고 결과가 0 이상 100 이하일 때만 `score`를 수정합니다. 실패하면 구조체 원본 전체를 보존합니다.

## 선수 지식

이 단원을 시작하기 전에 다음 내용을 알고 있어야 합니다.

- 함수의 선언·정의·호출과 반환값
- 변수의 주소를 구하는 `&` 연산자
- 포인터를 통한 간접 접근과 `NULL`
- `int` 표현 범위를 벗어난 산술을 피해야 하는 이유
- 성공과 실패를 정수 상태값으로 표현하는 함수 계약

## 학습 목표

학습을 마치면 다음을 할 수 있어야 합니다.

1. 구조체가 여러 멤버를 하나의 객체로 묶는 이유를 설명한다.
2. 구조체 객체에는 `.`을, 구조체 포인터에는 `->`를 사용하는 이유를 설명한다.
3. 구조체를 값으로 전달할 때와 주소로 전달할 때의 차이를 설명한다.
4. 포인터를 역참조하기 전에 `NULL`을 검사한다.
5. 유효성 검사를 모두 끝낸 뒤 필요한 멤버만 변경한다.
6. 실패하면 호출자가 가진 객체의 원래 상태를 보존하는 함수를 작성한다.
7. 덧셈 자체가 범위를 벗어나기 전에 안전한 비교로 결과 범위를 판정한다.

## 핵심 이론

### 1. 구조체는 관련된 값을 하나의 객체로 묶는다

구조체 정의는 새로운 객체 형태를 기술합니다.

```c
struct Student {
    int id;
    int score;
};
```

`id`와 `score`는 `struct Student`의 멤버입니다. 이 정의만으로 학생 객체가 자동 생성되지는 않습니다. 다음 선언이 실제 객체 하나를 만듭니다.

```c
struct Student minsu = { 101, 70 };
```

초기화 목록은 선언된 멤버 순서대로 대응합니다. 더 명시적으로 쓰고 싶다면 지정 초기화를 사용할 수 있습니다.

```c
struct Student minsu = {
    .id = 101,
    .score = 70
};
```

지정 초기화는 멤버 이름이 드러나므로 구조체가 커질 때 실수를 줄이는 데 도움이 됩니다.

### 2. 객체의 멤버는 점 연산자로 접근한다

구조체 객체 자체가 있을 때는 `.` 연산자를 사용합니다.

```c
printf("%d\n", minsu.id);
printf("%d\n", minsu.score);
```

대입의 왼쪽에도 멤버 접근식을 쓸 수 있습니다.

```c
minsu.score = 85;
```

이 대입은 `minsu` 객체의 `score`만 바꾸고 `id`는 그대로 둡니다.

### 3. 구조체를 값으로 전달하면 복사본을 받는다

다음 함수의 매개변수는 구조체 값입니다.

```c
void try_change(struct Student student) {
    student.score = 100;
}
```

호출할 때 구조체 값이 매개변수 객체로 복사됩니다. 함수 안에서 `student.score`를 바꿔도 호출자가 가진 원본은 바뀌지 않습니다.

```c
struct Student minsu = { 101, 70 };
try_change(minsu);
printf("%d\n", minsu.score);  // 70
```

값 전달이 잘못된 것은 아닙니다. 함수가 원본을 바꾸지 않아야 한다면 복사본은 분명한 선택입니다. 그러나 이 단원의 목적은 호출자의 학생 객체를 갱신하는 것이므로 주소를 전달합니다.

### 4. 주소를 전달하면 원본 객체에 접근할 수 있다

함수의 매개변수를 구조체 포인터로 선언합니다.

```c
int update_score(struct Student *student, int delta);
```

호출자는 `&`로 객체의 주소를 넘깁니다.

```c
update_score(&minsu, 15);
```

`student`는 구조체 객체가 아니라 그 객체를 가리키는 포인터입니다. 포인터를 통해 멤버에 접근할 때 `->` 연산자를 사용합니다.

```c
student->score
```

이 표현은 다음 표현과 같은 뜻입니다.

```c
(*student).score
```

괄호가 필요한 이유는 `.` 연산자가 단항 `*`보다 먼저 결합하기 때문입니다. `*student.score`라고 쓰면 의도한 “구조체를 역참조한 뒤 멤버 접근”이 되지 않습니다. `->`는 이 패턴을 간결하고 명확하게 표현합니다.

### 5. 역참조 전에 NULL을 검사한다

`student->score`는 내부적으로 포인터가 가리키는 객체에 접근합니다. `student == NULL`이면 가리키는 객체가 없으므로 멤버 접근을 해서는 안 됩니다.

```c
if (student == NULL) {
    return 0;
}
```

조건의 순서도 중요합니다. 다음 코드는 이미 잘못된 접근을 한 뒤 검사하므로 안전하지 않습니다.

```c
if (student->score < 0 || student == NULL) {  // 잘못된 순서
    return 0;
}
```

`&&`와 `||`의 단락 평가를 이용할 때도 왼쪽에서 먼저 실행되는 식이 안전해야 합니다.

### 6. 기존 객체 상태도 함수 계약의 일부다

이 문제는 기존 점수가 0 이상 100 이하인 학생만 갱신합니다. 이미 잘못된 점수 `-1`이나 `101`을 가진 객체를 조용히 고쳐 주지 않습니다.

```c
if (student->score < 0 || student->score > 100) {
    return 0;
}
```

왜 이런 정책이 필요할까요? 기존 상태 오류와 이번 변경 요청 오류를 섞으면 원인을 알기 어려워집니다. “현재 객체가 유효해야 갱신을 수행한다”는 전제는 호출자와 함수가 공유하는 계약입니다.

다른 프로그램에서는 잘못된 상태를 복구하는 별도 함수를 만들 수 있습니다. 하지만 검증 함수와 복구 함수를 같은 동작으로 숨기지 않는 편이 책임을 이해하기 쉽습니다.

### 7. 덧셈한 뒤 검사하면 이미 늦을 수 있다

다음 접근은 단순해 보입니다.

```c
int next = student->score + delta;
if (next < 0 || next > 100) {
    return 0;
}
```

그러나 `delta`가 매우 큰 양수나 음수라면 `int` 덧셈이 표현 범위를 벗어날 수 있습니다. 부호 있는 정수 오버플로는 C에서 정의되지 않은 동작입니다. 나중에 `next`를 검사한다고 이미 발생한 잘못된 연산이 되돌아가지는 않습니다.

이 단원에서는 기존 점수가 0 이상 100 이하임을 먼저 확인합니다. 그러면 안전한 변경량 범위는 다음과 같이 계산할 수 있습니다.

```c
if (delta < -student->score ||
    delta > 100 - student->score) {
    return 0;
}
```

`student->score`가 0~100이라는 전제를 먼저 확인했으므로 `-student->score`와 `100 - student->score`는 `int` 범위 안에 있습니다. `delta`가 이 범위 안에 있을 때만 실제 덧셈을 수행합니다.

```c
student->score += delta;
```

즉, 덧셈하기 전에 결과 범위를 판정하여 정의되지 않은 오버플로와 잘못된 점수를 함께 피합니다.

### 8. 검증과 변경을 분리하면 실패 시 원본을 보존할 수 있다

좋은 갱신 함수는 모든 실패 조건을 먼저 검사하고 마지막에 한 번만 상태를 바꿉니다.

```c
if (student == NULL) return 0;
if (student->score < 0 || student->score > 100) return 0;
if (delta < -student->score || delta > 100 - student->score) return 0;

student->score += delta;
return 1;
```

이 구조에서는 어느 검사에서 실패하더라도 아직 멤버를 바꾸지 않았습니다. 따라서 실패 시 원본 구조체가 자연스럽게 보존됩니다. `id`는 성공할 때도 수정 대상이 아니므로 항상 그대로 유지됩니다.

반대로 먼저 `score`를 바꾼 뒤 잘못된 결과면 0을 반환하는 구현은 상태값만 실패일 뿐 객체는 이미 손상시킵니다. 반환값과 실제 부작용이 서로 모순됩니다.

### 9. 구조체 대입은 멤버 값을 복사한다

같은 구조체 형식의 객체끼리는 대입할 수 있습니다.

```c
struct Student backup = *student;
```

이 코드는 현재 학생 객체의 멤버 값을 `backup`으로 복사합니다. 단순한 `int` 멤버만 있는 이 구조체에서는 독립적인 값 복사가 됩니다.

그러나 구조체에 포인터 멤버가 있다면 포인터가 가리키는 대상까지 새로 복제되는 것은 아닙니다. 포인터 값만 복사됩니다. 이를 얕은 복사라고 부르며, 동적 메모리 단원에서 소유권과 수명 정책을 별도로 다뤄야 합니다.

이 실습은 백업 후 되돌리는 방식보다 “검증이 끝날 때까지 변경하지 않기”를 사용합니다. 변경할 멤버가 하나이므로 더 단순하고 오류 가능성도 작습니다.

### 10. 구조체의 크기를 멤버 크기의 단순 합으로 단정하지 않는다

구현은 멤버가 적절히 정렬되도록 멤버 사이 또는 끝에 사용하지 않는 바이트를 둘 수 있습니다. 이를 구조체의 패딩(padding)이라고 합니다.

따라서 다음 관계를 모든 구현의 보장처럼 가정하면 안 됩니다.

```c
sizeof(struct Student) == sizeof(int) + sizeof(int)
```

현재 구조체에서는 우연히 같을 수 있지만 C 언어가 일반적으로 보장하는 식은 아닙니다. 객체를 파일이나 네트워크에 그대로 덤프하여 이식 가능한 형식이라고 생각해서도 안 됩니다. 직렬화 형식은 멤버의 의미, 크기, 바이트 순서를 별도로 정의해야 합니다.

`sizeof(struct Student)` 자체는 현재 구현에서 그 구조체 객체 하나를 저장하는 데 필요한 크기를 정확히 제공합니다. 구조체 배열이나 동적 할당에는 이 값을 사용합니다.

## 단계별 예제

### 1단계: 자료형과 객체 선언

```c
struct Student {
    int id;
    int score;
};

struct Student student = { 101, 70 };
```

`student.id`는 101, `student.score`는 70입니다.

### 2단계: 포인터와 현재 상태 검사

아래는 함수 정의의 앞부분입니다. 독립적인 완성 프로그램은 아닙니다.

```c
int update_score(struct Student *student, int delta) {
    if (student == NULL) {
        return 0;
    }
    if (student->score < 0 || student->score > 100) {
        return 0;
    }
```

`NULL` 검사 뒤에만 `student->score`를 읽습니다.

### 3단계: 변경량을 안전하게 검사

```c
    if (delta < -student->score ||
        delta > 100 - student->score) {
        return 0;
    }
```

현재 점수가 70이면 허용되는 `delta`는 -70부터 30까지입니다.

### 4단계: 검증 뒤 필요한 멤버만 변경

```c
    student->score += delta;
    return 1;
}
```

`student->id`에는 대입하지 않습니다.

### 5단계: 완성 프로그램

다음 코드는 그대로 컴파일할 수 있는 완성 프로그램입니다.

```c
#include <stdio.h>

struct Student {
    int id;
    int score;
};

int update_score(struct Student *student, int delta) {
    if (student == NULL) {
        return 0;
    }
    if (student->score < 0 || student->score > 100) {
        return 0;
    }
    if (delta < -student->score ||
        delta > 100 - student->score) {
        return 0;
    }

    student->score += delta;
    return 1;
}

int main(void) {
    struct Student student = { 101, 70 };

    int status = update_score(&student, 15);
    printf("status=%d id=%d score=%d\n",
           status, student.id, student.score);

    status = update_score(&student, 20);
    printf("status=%d id=%d score=%d\n",
           status, student.id, student.score);
    return 0;
}
```

## 실행 결과

```text
status=1 id=101 score=85
status=0 id=101 score=85
```

첫 요청은 70에서 85로 바뀌므로 성공합니다. 두 번째 요청은 85에서 105가 되므로 실패합니다. 두 번째 호출이 실패한 뒤에도 `id`와 `score`가 각각 101과 85로 유지됩니다.

## 흔한 오류

1. **값으로 받은 구조체를 수정한다**: 복사본만 바뀌어 호출자의 원본에는 반영되지 않습니다.
2. **NULL 검사 전에 `student->score`를 읽는다**: 유효한 객체가 없는 포인터를 역참조할 수 있습니다.
3. **먼저 점수를 더한 뒤 범위를 검사한다**: 실패해도 원본이 바뀌며, 큰 `delta`에서는 부호 있는 정수 오버플로가 먼저 발생할 수 있습니다.
4. **실패하면서 점수를 0이나 100으로 보정한다**: 이 함수의 “실패 시 원본 보존” 계약을 어깁니다.
5. **기존 점수가 잘못됐는데 변경으로 정상 범위에 넣는다**: 기존 상태 오류를 조용히 숨깁니다.
6. **`id`까지 함께 변경한다**: 성공 시 수정 대상은 `score` 하나뿐입니다.
7. **`student.score`를 쓴다**: `student`는 객체가 아니라 포인터이므로 `student->score`가 필요합니다.
8. **구조체 크기를 멤버 크기의 합으로 고정한다**: 정렬과 패딩을 무시한 이식성 없는 가정입니다.
9. **함수 안에서 디버그 문구를 출력한다**: 함수 계약에 없는 출력은 호출자의 출력 형식을 깨뜨립니다.

## 중간 점검

1. `struct Student student`와 `struct Student *student`는 무엇이 다른가요?
2. `student->score`를 `(*student).score`로 쓸 때 괄호가 필요한 이유는 무엇인가요?
3. 구조체를 값으로 전달한 함수에서 멤버를 바꾸면 호출자의 객체도 바뀌나요?
4. 기존 점수가 70일 때 허용되는 `delta`의 범위는 얼마인가요?
5. 왜 `student->score + delta`를 먼저 계산하지 않나요?
6. 실패 시 원본 보존을 코드 구조만으로 보장하려면 언제 대입해야 하나요?
7. 구조체에 포인터 멤버가 있다면 구조체 대입만으로 가리키는 데이터까지 복제되나요?

## 핵심 요약

- 구조체는 관련된 여러 값을 이름 있는 멤버로 묶습니다.
- 객체에는 `.`, 구조체 포인터에는 `->`를 사용합니다.
- 구조체 값 전달은 복사본을 만들고, 주소 전달은 원본에 접근하게 합니다.
- 포인터는 멤버 접근 전에 `NULL`인지 검사합니다.
- 기존 상태와 요청을 모두 검증한 뒤 필요한 멤버만 변경합니다.
- 변경 가능 범위를 덧셈 전에 비교하면 오버플로를 피할 수 있습니다.
- 실패 시 원본 구조체 전체를 보존하고 성공 시에도 계약에 없는 멤버는 바꾸지 않습니다.
- 구조체에는 구현이 선택한 패딩이 있을 수 있습니다.

## 기초 코딩 연습

`struct Point { int x; int y; };`를 정의하고 객체 하나를 초기화한 뒤 `.` 연산자로 두 좌표를 출력하세요. 다음으로 `struct Point *pointer = &point;`를 만들고 `->` 연산자로 `x`만 1 증가시키세요. 객체와 포인터가 같은 원본을 가리키는지 출력으로 확인합니다.

## 응용 연습

학생의 점수를 새 값으로 교체하는 다음 함수를 작성하세요.

```c

```

새 점수가 0~100일 때만 성공하고, 실패하면 객체 전체를 보존해야 합니다. `update_score`와 달리 덧셈은 없지만 `NULL`, 기존 객체 정책, 수정 대상 멤버를 어떻게 정의할지 문서화하세요.

## 도전 문제

학생 배열에서 특정 학번을 찾아 점수를 갱신하는 함수를 설계하세요.

                       size_t count,

배열·길이 계약, 중복 학번 정책, 찾지 못한 경우, 변경 실패 시 배열 보존을 명확히 하세요. `count == 0`, `students == NULL`, 매우 큰 `delta`도 고려합니다.

## 테스트와 풀이 개선

최소한 다음 사례를 차례대로 검증합니다.

- 일반 증가: 70에 15를 더해 85
- 일반 감소와 0 경계
- 정확히 100이 되는 상한 경계
- `delta == 0`
- 100을 초과하는 요청과 실패 후 원본 보존
- 0보다 작아지는 요청과 실패 후 원본 보존
- 기존 점수가 101 또는 -1인 객체
- `student == NULL`
- `INT_MAX`, `INT_MIN` 변경량
- 성공할 때 `id`가 유지되는지
- 표준 출력 부작용이 없는지
- 종료하지 않는 구현이 시간 제한으로 중단되는지

한 사례만 통과했다고 계약 전체가 맞는 것은 아닙니다. 특히 정상 결과만 확인하면 실패 전에 객체를 바꾸는 구현을 놓치기 쉽습니다. 반환 상태와 호출 뒤의 모든 멤버 값을 함께 검사해야 합니다.

## 복습 연결

이 단원은 함수·포인터의 원본 수정 개념을 이름 있는 복합 객체로 확장합니다. 다음에는 구조체 배열, 중첩 구조체, 구조체 포인터를 연결 리스트 노드로 사용하는 방법으로 이어집니다. 파일 입출력에서는 구조체 객체를 메모리 그대로 저장하지 않고 이식 가능한 텍스트 또는 명시적 이진 형식으로 직렬화해야 합니다.

Rust에서는 구조체 메서드의 `&mut self`, 소유권과 빌림 규칙이 같은 “원본 갱신 권한”을 형식으로 표현합니다. C와 Rust를 비교할 때 어느 쪽이 무조건 우수하다고 단정하기보다, C의 포인터 계약을 프로그래머가 어떻게 지키고 Rust의 빌림 검사가 어떤 오류를 컴파일 단계에서 제한하는지 구체적으로 비교할 수 있습니다.
