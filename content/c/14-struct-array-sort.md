# 구조체 배열을 학번순으로 안정 정렬하기

## 단원 개요

학생 한 명은 `struct Student` 한 객체로 나타낼 수 있습니다. 학생 여러 명을 배열에 저장했다면 화면에 학번순으로 출력하거나 정렬된 데이터에서 탐색하기 전에 레코드의 순서를 정리해야 합니다. 이 단원에서는 `id`를 키로 삼아 학생 배열을 오름차순으로 정렬합니다.

단순히 학번 숫자만 옮기는 것이 아닙니다. `id`와 `score`는 한 학생을 이루는 레코드이므로 **구조체 전체**를 함께 이동해야 합니다. 또한 같은 학번이 여러 번 나타날 때 입력에서 먼저 있던 레코드가 정렬 뒤에도 먼저 남는 **안정 정렬**을 구현합니다.

## 선수 지식

- `struct Student`의 정의와 객체 초기화
- 구조체 배열의 `students[i].id` 멤버 접근
- 배열의 유효 범위 `[0, count)`
- `size_t` 반복 변수와 함수 반환값
- 선형 탐색의 첫 일치 정책

이 단원은 `c-struct-array-search`의 구조체 배열 계약을 수정 가능한 배열과 정렬 불변식으로 확장합니다.

## 학습 목표

학습을 마치면 다음을 설명하고 구현할 수 있어야 합니다.

1. 정렬 키인 `id`와 나머지 레코드 데이터를 분리하지 않는다.
2. 같은 학번의 상대 순서를 유지하는 안정 정렬을 판별한다.
3. 삽입 정렬에서 `[0, i)`가 정렬되어 있다는 불변식을 사용한다.
4. `>`와 `>=`가 안정성에 미치는 차이를 설명한다.
5. 비교 결과를 뺄셈으로 만들 때 생길 수 있는 signed 오버플로를 피한다.
6. 빈 범위와 잘못된 포인터를 서로 다른 계약으로 처리한다.

## 핵심 이론

### 키만 바꾸면 레코드가 깨진다

다음 두 멤버는 서로 독립된 배열이 아니라 한 학생 객체의 상태입니다.

```c
struct Student {
    int id;
    int score;
};
```

`id`만 교환하고 `score`를 그대로 두면 학번과 점수가 서로 다른 학생의 값으로 섞입니다. C는 같은 구조체 형식의 객체 사이에 대입을 허용합니다. 따라서 임시 변수를 `int`가 아니라 `struct Student`로 선언해 구조체 전체를 복사합니다.

```c
struct Student key = students[i];
students[j] = students[j - 1];
students[j] = key;
```

구조체에 정렬을 위한 패딩이 있을 수 있어도 멤버 값은 구조체 대입으로 올바르게 전달됩니다. 이것이 구조체의 원시 바이트 표현을 이식 가능한 파일 형식으로 저장해도 된다는 뜻은 아닙니다.

### 안정 정렬이란 무엇인가

학번이 같은 학생을 점수로 구별해 다음 입력을 생각해 봅시다.

```text
205:11, 101:22, 205:33, 101:44
```

학번만 오름차순으로 정렬한 안정적인 결과는 다음과 같습니다.

```text
101:22, 101:44, 205:11, 205:33
```

같은 학번 101 안에서 22가 44보다 먼저이고, 학번 205 안에서 11이 33보다 먼저라는 입력 순서가 보존되었습니다. 점수는 정렬 기준이 아니라 같은 키의 상대 순서를 관찰하기 위한 꼬리표 역할을 합니다.

### 삽입 정렬의 불변식

바깥 반복의 인덱스가 `i`일 때 `[0, i)`는 이미 학번순으로 정렬되어 있다고 봅니다. `students[i]`를 `key`에 복사한 뒤, 앞쪽에서 `key.id`보다 큰 레코드를 오른쪽으로 한 칸씩 옮깁니다. 마지막 빈 자리에 `key`를 넣으면 `[0, i + 1)`도 정렬됩니다.

`i`는 1부터 시작합니다. `[0, 1)`의 한 원소는 이미 정렬되어 있고, 한 원소 배열이나 빈 배열에 불필요한 이동을 만들지 않습니다.

### 엄격한 `>`가 안정성을 보존한다

이동 조건은 다음과 같아야 합니다.

```c
students[j - 1].id > key.id
```

앞 레코드의 학번이 더 클 때만 이동합니다. 같은 학번에서는 반복을 멈추고 새 레코드를 기존 동등 키 뒤에 둡니다. `>=`를 쓰면 같은 학번도 오른쪽으로 밀려 새 레코드가 앞에 들어가므로 원래 순서가 뒤집힐 수 있습니다.

### 비교를 빼기 연산으로 표현하지 않는다

`a.id - b.id > 0`처럼 빼기 결과의 부호로 순서를 판정하는 코드는 피합니다. `a.id`가 `INT_MAX`, `b.id`가 `INT_MIN`이면 수학적인 차이는 `int`가 표현할 수 있는 범위를 벗어날 수 있습니다. signed int 오버플로는 C에서 정의되지 않은 동작입니다.

`a.id > b.id`처럼 관계 연산자로 직접 비교하면 `INT_MIN`과 `INT_MAX`도 언어가 정한 비교 규칙 안에서 처리됩니다. 특정 컴퓨터에서 `int`가 32비트라고 고정해 가정할 필요도 없습니다.

### 빈 범위는 읽을 객체가 없다

이 함수의 계약은 다음과 같습니다.

- `count == 0`: 정렬할 원소가 없으므로 성공 `1`. `students == NULL`도 허용합니다.
- `count > 0 && students == NULL`: 실제 배열이 없으므로 실패 `0`.
- 그 밖: `[0, count)` 안의 구조체를 안정적으로 정렬하고 성공 `1`.

빈 범위에서는 포인터를 역참조하지 않습니다. 따라서 `count == 0` 검사를 `students == NULL` 검사보다 먼저 해야 `stable_sort_students_by_id(NULL, 0)`을 계약대로 성공시킬 수 있습니다. 반대로 양수 `count`가 실제로 그만큼의 유효 객체를 가리키는지는 함수가 일반적으로 증명할 수 없으므로 호출자의 책임입니다.

## 단계별 예제

다음 배열을 정렬해 봅시다.

```c
struct Student students[] = {
    {.id = 309, .score = 95},
    {.id = 101, .score = 70},
    {.id = 205, .score = 88}
};
```

1. `i == 1`: `key`는 `101:70`입니다. `309 > 101`이므로 `309:95` 전체를 오른쪽으로 옮기고 key를 인덱스 0에 넣습니다.
2. 현재 배열은 `101:70, 309:95, 205:88`입니다.
3. `i == 2`: `key`는 `205:88`입니다. `309 > 205`라서 한 칸 옮기지만 `101 > 205`는 거짓이므로 멈춥니다.
4. 빈 인덱스 1에 `205:88`을 넣습니다.

핵심 반복은 다음과 같습니다.

```c
for (size_t i = 1; i < count; ++i) {
    struct Student key = students[i];
    size_t j = i;

    while (j > 0 && students[j - 1].id > key.id) {
        students[j] = students[j - 1];
        --j;
    }
    students[j] = key;
}
```

`&&`의 왼쪽 피연산자가 먼저 평가되고 `j > 0`이 거짓이면 오른쪽은 평가하지 않습니다. 그래서 `j == 0`일 때 `j - 1` 원소를 읽지 않습니다.

### 완성 프로그램

다음은 함수를 호출하고 결과를 출력하는 별도 완성 프로그램입니다. 자동 채점에 제출할 때는 `stable_sort_students_by_id` 함수와 필요한 구조체 정의만 제출하고 `main`이나 출력 코드를 넣지 않습니다.

```c
#include <stddef.h>
#include <stdio.h>

struct Student {
    int id;
    int score;
};

int stable_sort_students_by_id(struct Student students[], size_t count) {
    if (count == 0) return 1;
    if (students == NULL) return 0;

    for (size_t i = 1; i < count; ++i) {
        struct Student key = students[i];
        size_t j = i;

        while (j > 0 && students[j - 1].id > key.id) {
            students[j] = students[j - 1];
            --j;
        }
        students[j] = key;
    }
    return 1;
}

int main(void) {
    struct Student students[] = {
        {309, 95}, {101, 70}, {205, 88}
    };
    size_t count = sizeof students / sizeof students[0];

    int status = stable_sort_students_by_id(students, count);
    printf("%d", status);
    for (size_t i = 0; i < count; ++i) {
        printf(" %d:%d", students[i].id, students[i].score);
    }
    putchar('\n');
    return 0;
}
```

## 실행 결과

```text
1 101:70 205:88 309:95
```

상태 `1`은 계약에 따라 정렬을 마쳤다는 뜻입니다. 학번은 오름차순이고 각 점수는 원래 학생 레코드에 붙어 있습니다.

중복 사례를 실행하면 다음처럼 같은 학번 내부의 원래 순서도 관찰할 수 있습니다.

```text
입력:  205:11 101:22 205:33 101:44
결과:  101:22 101:44 205:11 205:33
```

## 흔한 오류

1. **id만 교환한다.** 학번과 점수의 짝이 깨집니다.
2. **동등한 키에도 이동한다.** `>=` 조건은 안정성을 깨뜨릴 수 있습니다.
3. **`j > 0`보다 먼저 `students[j - 1]`을 읽는다.** `size_t`에서 0 - 1은 매우 큰 값으로 돌아 범위 밖 접근이 됩니다.
4. **학번을 빼서 비교한다.** 표현 범위를 넘는 signed 오버플로가 생길 수 있습니다.
5. **NULL을 무조건 실패시킨다.** 이 단원의 빈 범위 계약에서는 `NULL, 0`이 성공입니다.
6. **양수 길이의 NULL을 성공시킨다.** 실제 배열을 읽을 수 없으므로 실패해야 합니다.
7. **정렬 함수에서 디버그 출력을 남긴다.** 채점 하네스가 기대하는 출력과 섞이며 함수의 불필요한 부작용이 됩니다.

## 중간 점검

- 점수까지 함께 이동해야 하는 이유를 한 문장으로 설명해 보세요.
- `205:A, 101:C, 205:B`의 안정 정렬 결과에서 A와 B의 순서는 어떻게 됩니까?
- 이동 조건을 `>=`로 바꾸면 왜 그 순서가 보장되지 않습니까?
- `count == 0`일 때 `students[0]`을 읽으면 안 되는 이유는 무엇입니까?
- `INT_MIN`과 `INT_MAX`의 순서를 뺄셈 없이 어떻게 비교합니까?

## 핵심 요약

- 정렬 키가 한 멤버여도 구조체 전체가 하나의 레코드입니다.
- 삽입 정렬은 정렬된 앞 구간을 한 원소씩 확장합니다.
- 이전 id가 더 큰 경우에만 옮기는 엄격한 `>`가 동등 키의 상대 순서를 보존합니다.
- 관계 연산자를 사용해 비교 뺄셈의 signed 오버플로를 피합니다.
- 빈 범위는 성공이며 아무 객체도 읽지 않습니다. 양수 길이의 NULL은 실패입니다.
- 삽입 정렬은 최악·평균 `O(n²)`, 이미 정렬된 입력에서는 `O(n)`, 추가 공간은 `O(1)`입니다.

## 응용 연습

`struct Book { int year; int sequence; };` 배열을 `year` 오름차순으로 안정 정렬하세요. 같은 연도에서는 `sequence`의 입력 순서가 유지되는 사례를 최소 두 개 작성합니다. `sequence`를 두 번째 정렬 키로 사용하지 않는다는 점에 주의합니다.

## 도전 문제

비교 기준을 매개변수로 받는 범용 설계가 필요한 이유를 조사하고, 이 단원의 고정된 `id` 비교 함수와 표준 라이브러리 `qsort`의 계약을 비교해 보세요. `qsort` 자체는 동등 키의 상대 순서 보존을 보장하는 안정 정렬 인터페이스가 아니라는 점을 고려합니다. 이 도전 문제는 현재 자동 채점 범위 밖입니다.

## 테스트와 풀이 개선

정상 사례 하나만으로는 안정성이나 레코드 보존을 확인할 수 없습니다. 다음 분류를 각각 테스트합니다.

- 이미 정렬된 배열과 역순 배열
- 한 원소와 빈 범위
- 두 개 이상의 중복 학번과 모든 학번이 같은 배열
- 음수 학번, 0, `INT_MIN`, `INT_MAX`
- 점수가 서로 다른 중복 레코드로 상대 순서 관찰
- `NULL, 0` 성공과 `NULL, 양수` 실패
- 함수가 표준 출력을 남기지 않는지 확인

실패한 코드는 어떤 계약을 어겼는지 먼저 분류합니다. id만 이동했다면 구조체 임시 객체로 바꾸고, 중복 순서가 뒤집혔다면 비교가 `>=`인지 확인합니다. 극값에서만 실패한다면 뺄셈 비교를 관계 비교로 바꿉니다. 무한 반복이 생기면 이동할 때 `j`가 반드시 감소하는지 확인합니다.

## 복습 연결

이 단원은 구조체 배열 검색에서 배운 범위 계약을 수정 연산으로 확장했습니다. 다음에는 정렬된 배열이라는 전제 조건을 명시하고 이진 탐색을 적용할 수 있습니다. 또한 선택 정렬과 삽입 정렬의 이동 횟수·안정성을 같은 입력으로 비교하고, 더 큰 자료에서는 병합 정렬처럼 안정성과 `O(n log n)` 시간을 함께 제공하는 알고리즘으로 이어갈 수 있습니다.
