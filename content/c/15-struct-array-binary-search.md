# 정렬된 구조체 배열에서 첫 학번 이진 탐색

## 단원 개요

앞 단원에서는 `struct Student` 배열을 학번 오름차순으로 안정 정렬했습니다. 정렬된 배열에서는 목표 학번이 있을 수 있는 구간을 절반씩 버리는 이진 탐색을 사용할 수 있습니다. 이 단원은 단순히 “값 하나를 찾는 코드”가 아니라 다음 계약을 함께 다룹니다.

- 입력 배열은 `id` 오름차순으로 정렬되어 있다.
- 중복 학번이 있으면 가장 작은 인덱스, 즉 첫 위치를 찾는다.
- 빈 배열·잘못된 포인터·미발견에서는 출력 객체를 보존한다.
- 후보 구간은 `[left, right)`로 표현한다.
- 중간점 계산과 구간 갱신은 `size_t` 경계를 지킨다.

## 선수 지식

- `struct Student` 배열과 `students[i].id`
- 배열의 유효 범위 `[0, count)`
- 선형 탐색의 첫 일치 정책
- 학번 기준 안정 정렬
- 함수 상태 반환값과 출력 포인터

정렬을 수행하는 함수와 탐색하는 함수의 책임은 다릅니다. 이 함수는 배열을 수정하지 않으므로 `const struct Student students[]`로 받습니다.

## 학습 목표

학습을 마치면 다음을 설명하고 구현할 수 있어야 합니다.

1. 정렬 전제가 이진 탐색의 정확성에 필요한 이유를 설명한다.
2. 반열린 후보 구간 `[left, right)`의 불변식을 유지한다.
3. `left + (right - left) / 2`로 중간점을 계산한다.
4. 같은 학번 중 첫 위치를 찾는 하한 탐색을 구현한다.
5. 수렴 후 실제 일치 여부를 검증한다.
6. 실패 시 출력값을 보존한다.
7. `O(n)` 선형 탐색과 `O(log n)` 이진 탐색의 전제와 비용을 구분한다.

## 핵심 이론

### 정렬 전제 없이는 절반을 버릴 수 없다

이진 탐색의 핵심은 중간 원소와 목표를 비교한 뒤 한쪽 절반에는 답이 없다고 결론 내리는 것입니다. 이 결론은 배열이 학번 오름차순으로 정렬되어 있을 때만 성립합니다.

예를 들어 중간 학번이 목표보다 작다면 정렬된 배열의 중간 왼쪽 원소도 모두 목표보다 작거나 같습니다. 그래서 그 구간을 버릴 수 있습니다. 정렬되지 않은 배열에서는 왼쪽 어디에 더 큰 학번이 숨어 있을 수 있으므로 같은 판단의 결과를 보장할 수 없습니다.

함수가 매번 배열 전체를 순회해 정렬 여부를 확인하면 검증 자체가 `O(n)`입니다. 이 단원의 함수는 정렬된 입력을 호출자 전제로 명시하고, 앞 단원의 안정 정렬 결과와 연결합니다.

### 반열린 구간 `[left, right)`

후보 인덱스를 다음처럼 표현합니다.

```text
left <= 후보 인덱스 < right
```

초기값은 `left = 0`, `right = count`입니다. `right`는 실제 원소 인덱스가 아니라 후보 구간 바로 다음 경계일 수 있습니다.

이 표현에는 다음 장점이 있습니다.

- 후보 개수는 언제나 `right - left`이다.
- 빈 구간은 `left == right`이다.
- 빈 배열도 `[0, 0)`으로 자연스럽게 표현된다.
- `count - 1`을 만들 필요가 없어 `count == 0`일 때 unsigned 언더플로를 피한다.

### 안전한 중간점 계산

중간점은 다음과 같이 계산합니다.

```c
size_t mid = left + (right - left) / 2;
```

불변식 `left <= right` 때문에 `right - left`는 음수가 되지 않습니다. `left + right`를 먼저 계산하는 표현은 두 값의 합이 자료형 범위를 넘을 위험이 있지만, 차이를 절반으로 나눈 뒤 `left`에 더하면 후보 구간 안의 인덱스를 얻습니다.

### 첫 위치를 찾는 하한 탐색

일반적인 “값을 발견하면 즉시 반환” 방식은 중복 중 어느 위치를 반환할지 정하지 않습니다. 이 단원은 목표 이상인 첫 위치, 흔히 하한(lower bound)이라고 부르는 경계를 찾습니다.

- `students[mid].id < target_id`: `mid`까지는 첫 위치가 될 수 없으므로 `left = mid + 1`
- 그 밖, 즉 같거나 큼: `mid` 또는 더 왼쪽이 첫 위치일 수 있으므로 `right = mid`

같은 값을 만났을 때도 `right = mid`로 이동하는 것이 핵심입니다. 즉시 반환하지 않기 때문에 더 왼쪽의 중복을 계속 찾습니다.

각 반복에서 `left`가 증가하거나 `right`가 감소하므로 후보 구간이 반드시 줄어듭니다. 경계를 `left = mid`처럼 잘못 갱신하면 한 원소 구간에서 값이 바뀌지 않아 무한 반복할 수 있습니다.

### 수렴은 성공과 같지 않다

반복이 끝나면 `left == right`입니다. 이 위치는 목표 이상인 첫 후보지만 목표가 실제로 존재한다는 뜻은 아닙니다.

- 목표가 모든 원소보다 크면 `left == count`
- 목표가 두 값 사이에 없으면 `students[left].id`는 목표보다 큰 다음 값
- 목표가 있으면 `students[left].id == target_id`

따라서 다음 두 조건을 함께 검사합니다.

```c
left < count && students[left].id == target_id
```

`&&`의 단락 평가 덕분에 `left == count`일 때 배열을 읽지 않습니다.

### 실패 시 출력값 보존

함수는 성공 여부를 `int`로 반환하고 위치를 `size_t *out_index`에 기록합니다. 다음은 모두 실패 `0`입니다.

- `count == 0`
- 양수 길이인데 `students == NULL`
- `out_index == NULL`
- 목표 학번 미발견

유효한 `out_index`가 있더라도 성공이 확정되기 전에는 쓰지 않습니다. 호출자가 미리 넣어 둔 감시값 77은 실패 뒤에도 77이어야 합니다. 빈 범위에서는 읽을 원소가 없으므로 `students == NULL`도 역참조하지 않고 실패할 수 있습니다.

## 단계별 예제

다음처럼 학번이 정렬된 배열에서 7의 첫 위치를 찾습니다.

```text
인덱스: 0   1   2   3   4
학번:   1   7   7   7   9
```

1. `[left, right) = [0, 5)`, `mid = 2`, 학번은 7입니다. 첫 7일 수도 더 왼쪽일 수도 있으므로 `right = 2`입니다.
2. 후보는 `[0, 2)`, `mid = 1`, 학번은 7입니다. 다시 `right = 1`입니다.
3. 후보는 `[0, 1)`, `mid = 0`, 학번 1은 목표보다 작으므로 `left = 1`입니다.
4. `left == right == 1`로 수렴합니다.
5. 인덱스 1의 학번이 실제로 7이므로 `*out_index = 1`을 기록하고 1을 반환합니다.

### 완성 프로그램

다음 코드는 함수와 호출 예시를 함께 포함한 별도 완성 프로그램입니다. 자동 채점에는 구조체 정의와 함수만 제출하며 `main`과 출력 코드는 넣지 않습니다.

```c
#include <stddef.h>
#include <stdio.h>

struct Student {
    int id;
    int score;
};

int find_first_student_by_id(const struct Student students[], size_t count,
                             int target_id, size_t *out_index) {
    if (count == 0 || students == NULL || out_index == NULL) return 0;

    size_t left = 0;
    size_t right = count;

    while (left < right) {
        size_t mid = left + (right - left) / 2;
        if (students[mid].id < target_id) {
            left = mid + 1;
        } else {
            right = mid;
        }
    }

    if (left < count && students[left].id == target_id) {
        *out_index = left;
        return 1;
    }
    return 0;
}

int main(void) {
    const struct Student students[] = {
        {101, 70}, {205, 88}, {205, 91}, {309, 95}
    };
    size_t index = 77;
    int status = find_first_student_by_id(students, 4, 205, &index);
    printf("%d %zu\n", status, index);
    return 0;
}
```

## 실행 결과

```text
1 1
```

두 번째 205가 인덱스 2에 있어도 첫 위치 1을 반환합니다. 같은 배열에서 250을 찾고 `index`를 77로 초기화했다면 결과는 `0 77`입니다.

## 흔한 오류

1. **같은 값을 발견하자마자 반환한다.** 중복의 중간 위치를 반환할 수 있습니다.
2. **빈 배열에서 `right = count - 1`을 계산한다.** `size_t`가 매우 큰 값으로 돌아갑니다.
3. **`left = mid`로 갱신한다.** 후보가 줄지 않아 무한 반복할 수 있습니다.
4. **수렴 뒤 동등성을 검사하지 않는다.** 목표가 없는 삽입 위치를 성공으로 잘못 처리합니다.
5. **`left + right`로 중간점을 계산한다.** 합의 표현 범위를 불필요하게 위험하게 만듭니다.
6. **실패 전에 `*out_index = 0`을 쓴다.** 출력 보존 계약을 어깁니다.
7. **정렬되지 않은 배열에 호출한다.** 결과는 계약상 보장되지 않습니다.
8. **함수에서 디버그 출력을 남긴다.** 직접 호출 하네스의 기대 출력과 섞입니다.

## 중간 점검

- 왜 `right`의 초기값이 마지막 인덱스가 아니라 `count`입니까?
- 학번이 목표와 같을 때 즉시 반환하지 않는 이유는 무엇입니까?
- 반복 종료 후 `left < count`를 먼저 검사해야 하는 이유는 무엇입니까?
- 정렬 여부를 함수 안에서 매번 검사하면 전체 시간 복잡도는 어떻게 됩니까?
- 미발견 때 출력값을 보존하면 호출자가 무엇을 구분하기 쉬워집니까?

## 핵심 요약

- 이진 탐색의 정확성에는 정렬 전제가 필요합니다.
- 후보 구간 `[left, right)`는 빈 배열과 경계를 자연스럽게 표현합니다.
- 중간점은 `left + (right - left) / 2`로 계산합니다.
- 같은 값에서도 `right = mid`로 줄이면 첫 위치에 수렴합니다.
- 수렴 후 범위와 실제 동등성을 모두 확인합니다.
- 성공이 확정된 경우에만 출력 객체를 기록합니다.
- 시간 복잡도는 `O(log n)`, 추가 공간은 `O(1)`입니다.

## 도전 문제

첫 위치뿐 아니라 목표보다 큰 첫 위치인 상한(upper bound)도 구현해 `[lower, upper)`를 같은 학번의 전체 범위로 반환해 보세요. 두 출력 포인터 중 하나만 유효한 경우와 미발견 시 두 출력값 보존 정책을 먼저 문서화합니다. 현재 자동 채점 범위 밖입니다.

## 테스트와 풀이 개선

다음 분류를 각각 검사합니다.

- 첫 원소·중간 원소·마지막 원소
- 한 원소의 성공과 실패
- 중복 학번 세 개의 첫 위치
- 두 값 사이의 미발견과 범위 밖 목표
