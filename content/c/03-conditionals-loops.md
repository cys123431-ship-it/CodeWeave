# 조건문과 반복문: 상태·경계·종료를 설명하기

## 단원 개요

조건문은 실행할 경로를 고르고 반복문은 상태를 조금씩 바꾸며 본문을 다시 실행한다. 이 단원은 `if/else`, 논리 조건, `for`, `while`, `do`, `break`, `continue`를 상태와 검사 시점으로 연결한다. 기존 `c-loops` 문제인 1부터 n까지 합을 풀면서 불변식·종료 이유·최대 합의 표현 범위까지 확인한다.

## 필요한 이유

컴파일되는 반복문도 틀릴 수 있다. 마지막 값을 빼먹거나 누산값을 매번 지우면 출력이 잘못된다. 갱신을 건너뛰면 끝나지 않을 수 있고, 반복 횟수가 작아 보여도 합은 자료형의 범위를 넘을 수 있다.

반복문을 읽을 때의 네 질문을 익힌다. **시작 상태는 무엇인가? 지금까지 무엇을 처리했는가? 다음 상태로 어떻게 이동하는가? 왜 끝나는가?**

## 선수 지식

- 첫 C 프로그램의 명령문·블록·실행 결과·종료 상태
- 변수의 초기화·대입·수치 범위와 연산 시점
- `scanf` 변환 개수와 `printf` 형식

배열·포인터 연산은 아직 필요하지 않다.

## 학습 목표

1. 0과 비0 조건, 비교와 대입을 구분한다.
2. 분기와 논리 조건을 의도에 맞게 작성한다.
3. 반복의 초기화·조건·본문·갱신·종료를 추적한다.
4. `for`·`while`·`do`의 검사 시점과 `continue` 경로를 설명한다.
5. 합의 불변식과 종료 이유를 말한다.
6. 0회·1회·마지막 항·최대 합을 서로 다른 경계로 검사한다.
7. `long` 누산형으로 이식 가능한 합 예제를 작성한다.

## 핵심 이론

### 1. C 조건의 0과 비0

조건은 0이면 거짓, 0이 아닌 값이면 참이다. 음수도 0이 아니면 참이므로 `if (value)`를 `value == 1`과 같은 것으로 해석하지 않는다.

관계·동등 비교 연산은 결과 0 또는 1을 만든다. 하지만 비교 결과가 아닌 다른 정수도 조건에 사용할 수 있다. 처음에는 `score >= 60`처럼 의도가 드러나는 조건을 선호한다.

### 2. 분기와 중괄호

다음은 `score`가 초기화된 `main` 몸체 안의 **코드 조각**이다.

```c
if (score >= 60) {
    printf("pass\n");
} else {
    printf("retry\n");
}
```

참이면 첫 블록, 거짓이면 `else` 블록을 실행한다. 중괄호는 여러 명령문을 묶으며 들여쓰기 자체가 실행 범위를 정하지는 않는다. 중첩에서 `else`는 결합 가능한 가장 가까운 앞선 `if`와 연결되므로 중괄호로 의도를 드러낸다.

### 3. 대입과 비교

`=`는 새 값을 저장하고 `==`는 같은지 비교한다. 의도치 않은 `if (score = 60)`은 값을 바꾸며 대입 결과 60이 비0라 참으로 판단될 수 있다.

조건 안에서 상태를 바꾸는 코드가 항상 문법 오류인 것은 아니다. 그래서 경고를 켜고, 초기 단계에서는 값을 바꾸는 명령문과 검사하는 명령문을 분리한다.

### 4. 범위는 두 비교를 연결한다

수학의 `0 <= n <= 1000`을 그대로 C에 쓰면 왼쪽 비교 결과 0 또는 1을 다시 1000과 비교한다. 원하는 범위 검사가 아니다.

```c
if (n >= 0 && n <= 1000) {
    /* 범위 안 */
}
```

`&&`는 둘 다 참, `||`는 하나 이상 참, `!`는 논리 부정을 나타낸다. `&&`와 `||`는 왼쪽 평가 후 결과가 정해지면 오른쪽을 평가하지 않는 단락 평가를 한다. 비트 연산 `&`·`|`와 혼동하지 않는다.

### 5. `for`의 순서

```c
for (int i = 1; i <= n; ++i) {
    sum += i;
}
```

1. 초기화 `i = 1`: 한 번
2. 조건 `i <= n`: 본문에 들어가기 전마다
3. 본문 `sum += i`: 조건이 참일 때
4. 갱신 `++i`: 정상 본문 종료 뒤
5. 조건이 거짓이면 반복을 벗어남

`sum += i`는 단순 변수에서 현재 합에 i를 더해 저장한다. `for` 초기화에서 정의한 i의 범위는 그 반복문 안이므로 반복 밖에서 접근하는 코드와 구분한다.

### 6. 추적은 시점을 명시한다

n=3, 초기 sum=0인 경우다.

| 조건 검사 직전 i | 검사 직전 sum | 조건 | 본문 뒤 sum | 갱신 뒤 i |
| ---: | ---: | --- | ---: | ---: |
| 1 | 0 | 참 | 1 | 2 |
| 2 | 1 | 참 | 3 | 3 |
| 3 | 3 | 참 | 6 | 4 |
| 4 | 6 | 거짓 | 본문 없음 | 갱신 없음 |

“두 번째 반복에서 sum이 얼마인가?”라는 질문은 모호할 수 있다. 검사 직전인지 본문 뒤인지 먼저 정한다.

### 7. 불변식으로 이미 처리한 범위를 말한다

각 조건 검사 직전에는 **sum이 1부터 i-1까지의 합**이라는 설명이 성립한다.

- 초기화: i=1이므로 아직 처리한 항이 없다. 빈 합은 0이다.
- 유지: 본문에서 i를 더한 뒤 i를 1 늘리면 새 i 바로 전까지의 합이 된다.
- 종료: i=n+1에서 멈추므로 sum은 1부터 n까지의 합이다.

불변식은 코드를 암기하는 별칭이 아니라 정확한 시점의 상태 설명이다. 본문 중간의 모든 줄에서 같은 형태가 유지되어야 한다는 뜻은 아니다.

### 8. 종료와 감소하는 남은 일

허용 범위에서 i는 1부터 최대 1001까지 움직인다. 이 값들은 최소 `int` 범위 안이다. 본문마다 아직 더하지 않은 항의 수가 하나씩 줄어 끝에 도달한다.

일반 프로그램에서는 “i가 증가한다”만으로 충분하지 않다. 표현 범위 초과나 다른 상태 변경으로 경계에 도달하지 못할 수 있다. 이번 증명은 n이 0~1000이라는 계약과 충분한 형을 함께 전제로 한다.

### 9. 0회·1회·마지막 항

- n=0: 첫 조건 1 <= 0이 거짓 → 빈 합 0
- n=1: i=1의 본문을 한 번 → 합 1
- n=5: 1·2·3·4·5 포함 → 합 15

`i <= n`을 `i < n`으로 바꾸면 마지막 항을 놓친다. n=1이 최소 양수 사례라 이 차이를 가장 작게 드러낸다.

### 10. 누산값의 범위는 입력 범위와 다르다

n은 최대 1000이라 `int`로 충분하다. 하지만 최종 합은 500500이고, C11의 최소 `int` 최댓값 32767을 넘는다. `int` 누산형이 현재 PC에서 통과해도 모든 C11 구현에 이식 가능한 예제는 아니다.

`long`은 적어도 2147483647까지 표현하므로 이 합을 담을 수 있다. 따라서 `long sum = 0;`과 `printf("%ld\n", sum);`을 함께 사용한다. `long`이 항상 64비트라고 가정하는 것은 아니다.

합이 커진 뒤 검사하는 방법으로 signed 넘침을 되돌릴 수 없다. signed 넘침은 정의되지 않은 동작이므로 **계산 전에** 범위와 형을 정한다. 이번 실행은 현재 GCC에서 검사했으며 실제 16비트 컴파일러에서 실행했다고 주장하지 않는다.

### 11. 수학 공식도 연산 형을 먼저 본다

학습용 반복을 수학 공식과 대조할 수 있다.

```c
long expected = (long)n * (n + 1) / 2;
```

n+1은 최대 1001이라 `int`로 안전하고, 첫 피연산자를 먼저 `long`으로 바꾸므로 곱셈도 `long`으로 계산된다. 곱은 최대 1001000이라 최소 `long` 범위 안이다.

`long expected = n * (n + 1) / 2;`는 곱셈이 `int`로 먼저 일어날 수 있으므로 목적 변수만 바꾼 것으로 안전성을 주장하지 않는다.

### 12. `while`과 `do`

`while`는 조건을 본문 전에 검사해 0회일 수 있다. `do`는 본문 뒤에 검사하므로 정상적으로 제어가 도달하면 최소 한 번 실행한다.

`i=1`에서 시작하는 합을 `do`로 기계적으로 바꾸면 n=0에서도 1을 더할 수 있다. 같은 계약을 유지하려면 빈 입력 경로를 먼저 분리하거나 알고리즘을 다시 설계한다. 문법만 바꾸어 동등하다고 말하지 않는다.

### 13. `break`와 `continue`

`break`는 가장 안쪽 반복문 또는 `switch`를 벗어난다. `continue`는 현재 반복의 남은 본문을 건너뛴다.

| 반복 종류 | `continue` 뒤 경로 |
| --- | --- |
| `for` | 갱신식 → 조건 검사 |
| `while` | 조건 검사 |
| `do` | 뒤의 조건 검사 |

`while` 본문의 끝에 i 갱신을 두었는데 앞에서 `continue`하면 갱신을 건너뛸 수 있다. 중첩에서 `break` 한 번으로 모든 반복이 종료되는 것도 아니다.

### 14. 입력 계약과 간단한 오류 정책

기존 채점 계약은 정확히 한 정수 n, 범위 0~1000이다. 범위 밖 값·변환 실패·조기 EOF·추가 토큰은 기존 채점 대상 밖이다. 완성 예제는 변환 개수와 **이미 int로 표현 가능한 n**의 범위를 검사한다.

`scanf`의 `%d`가 임의로 큰 숫자 텍스트를 안전하게 거부한다고 가정하지 않는다. 변환 결과를 `int`로 표현할 수 없으면 정의되지 않은 동작일 수 있다. 신뢰하지 않는 텍스트 파서는 후속 `fgets`·`strtol` 경로로 확장한다.

## 정적 도식 읽기

독자 SVG의 초기화→조건→참 본문→갱신→다음 조건 경로를 따라간다. 거짓 경로만 종료와 sum 출력으로 간다. 조건 검사 직전의 불변식 문장을 함께 읽는다.

도식은 실행 애니메이션이 아니라 상태 변화를 설명하는 정적 지도다.

## 단계별 예제

먼저 sum=0으로 빈 합을 만든다. i=1부터 시작해 현재 i를 더하고 한 칸 전진한다. 본문 안에서 sum을 다시 0으로 만들지 않는다. 결과를 예측한 뒤 다음 관찰용 프로그램으로 비교한다.

## 완성 프로그램 A: 상태 추적

```c
#include <stdio.h>

int main(void) {
    long sum = 0;
    for (int i = 1; i <= 3; ++i) {
        long before = sum;
        sum += i;
        printf("i=%d before=%ld after=%ld\n", i, before, sum);
    }
    printf("sum=%ld\n", sum);
    return 0;
}
```

## 실행 결과

프로그램 A는 입력 없이 다음을 출력한다.

```text
i=1 before=0 after=1
i=2 before=1 after=3
i=3 before=3 after=6
sum=6
```

## 왜 이런 결과가 나오는가

각 줄의 before는 현재 i를 더하기 전의 합이고 after는 더한 뒤의 합이다. i=3 본문 뒤 합은 6이고 갱신된 i=4에서 조건이 거짓이므로 네 번째 본문 줄은 없다.

## 완성 프로그램 B: 채점용 합

```c
#include <stdio.h>

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) {
        return 1;
    }
    if (n < 0 || n > 1000) {
        return 1;
    }

    long sum = 0;
    for (int i = 1; i <= n; ++i) {
        sum += i;
    }
    printf("%ld\n", sum);
    return 0;
}
```

입력 5는 15, 0은 0, 1은 1, 1000은 500500과 개행을 출력한다. 프로그램 A의 관찰 문구를 B의 표준 출력에 섞으면 기존 채점 형식과 달라진다. 간단한 입력 실패와 표현 가능한 범위 밖 n에서는 출력 없이 상태 1로 종료한다.

## 흔한 오류

- `for (...);`처럼 뒤에 세미콜론을 붙이면 빈 명령문을 반복할 수 있다.
- `i < n`은 마지막 항을 놓친다.
- sum을 본문 안에서 초기화하면 누적이 아니라 마지막 값만 남을 수 있다.
- `while`에서 갱신을 빠뜨리거나 `continue`로 건너뛰면 종료하지 않을 수 있다.
- `=`와 `==`, 논리 `&&`와 비트 `&`를 혼동하지 않는다.
- `i++ + i++`처럼 같은 객체를 순서 없이 여러 번 변경하는 식을 정상 예제로 실행하지 않는다.
- 반복 범위가 안전하다고 누산 범위도 안전한 것은 아니다.

## 중간 점검

1. n=0에서 본문과 갱신은 몇 번 실행되는가?
2. n=3의 두 번째 조건 검사 직전 i·sum은 무엇인가?
3. n=1000의 마지막 본문 뒤 갱신한 i는 무엇인가?
4. `continue`는 `for`의 갱신식을 건너뛰는가?

확인: 0회, i=2·sum=1, 1001, 아니오. 답뿐 아니라 검사 시점을 함께 말한다.

## 개념 확인 퀴즈

`for (int i=0; i<4; i++)`의 본문은 몇 번 실행되는가?

- 정답: 4번. i가 0·1·2·3일 때 실행된다.
- 5번을 골랐다면 조건 `<4`와 마지막 거짓 검사를 본문 실행으로 세지 않았는지 확인한다.

기존 화면 퀴즈와 정답 인덱스는 그대로 유지한다.

## 핵심 요약

조건은 0/비0로 판단한다. 반복을 초기화·조건·본문·갱신·종료로 나누고 불변식으로 처리한 범위를 설명한다. 빈 합, 첫 항, 마지막 항과 최대 누산값은 별개의 경계다. 계산 전에 충분한 형을 정하고 출력 형식을 맞춘다.

## 기초 코딩 연습

기존 `c-loops` 문제를 `long` 누산형으로 풀고 0·1·5·10·1000의 출력을 검사한다. 예시 하나의 성공을 전체 동작으로 일반화하지 않는다.

## 응용 연습

같은 합을 `while`로 바꾼다. 조건 검사 직전 불변식과 출력이 유지되는지 먼저 설명한다. 갱신 위치를 표시한 뒤 0과 1을 다시 검사한다.

## 도전 문제

1부터 n까지 홀수의 합과 개수를 별도 변수로 센다. 짝수를 건너뛰는 `continue`를 쓴다면 선택한 반복 종류에서 갱신이 어떻게 일어나는지 확인한다. n=0·1·2·3의 상태 표를 먼저 작성한다.

## Mini Project

한 주의 작은 점수를 7회 입력받아 합·개수·평균을 출력한다. 각 점수 범위를 0~100으로 정하면 합은 최대 700이다. 평균 계산 전에 자료형을 변환하고, 중간에 간단한 입력 실패가 발생했을 때 중단할 정책을 정한다.

이 버전은 신뢰하는 계약 입력용이다. 임의 텍스트 입력 검증은 `fgets`·`strtol` 학습 뒤 확장한다.

## 테스트와 풀이 개선

두 완성 프로그램을 별도 파일로 저장해 `gcc -std=c11 -Wall -Wextra -Werror -Wpedantic`으로 빌드한다. A는 상태 추적 출력, B는 합과 종료 상태를 검사한다.

기존 공개 예시는 유지하고 비공개 GCC 사례에는 n=1을 추가해 0회·1회·상한을 분리한다. 회귀 검사는 마지막 항을 제외하는 풀이와 본문에서 누산값을 지우는 풀이를 거부한다.

유한한 테스트는 현재 컴파일러의 관찰이다. 모든 허용 n을 비교하더라도 모든 C 환경·입력 문자열·메모리·보안 격리를 증명하는 것은 아니다. 이식성은 최소 보장 범위와 연산 형의 별도 논증을 함께 사용한다.

## 복습 연결

다음 배열 단원에서는 1..n의 닫힌 범위 대신 `[0, count)` 인덱스를 사용한다. 오늘의 초기값·끝 조건·처리한 범위 설명을 배열의 유효 접근 범위와 연결한다. 함수로 분리할 때는 반복의 입력 전제와 결과 범위를 계약으로 전달한다.

## 의미 검토 출처

원고·예제·문제·도식은 독자 작성했다. C11 위원회 초안 [N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)의 5.2.4.2.1(정수 최소 범위), 6.5.13~14(논리 연산), 6.8.4~6(분기·반복·점프), 7.21.6(형식 입출력)으로 의미를 검토했다. 최종 표준과 위원회 초안을 구분하며 원문을 복제하지 않았다. 제공 교재 PDF의 본문 전체를 대조했다고 주장하지 않는다.
