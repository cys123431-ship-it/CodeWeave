# `fgets`와 `strtol`로 정수 입력 검증하기

> 이 원고와 예제·문제는 CodeWeave용으로 새로 작성했습니다. 상용 교재의 본문·그림·문제를 복제하지 않았습니다.

## 단원 개요

키보드나 파일에서 들어오는 데이터는 처음에는 숫자가 아니라 문자 바이트의 연속입니다. `"-42"`를 `long` 값 `-42`로 쓰려면 문자열을 해석해야 합니다. 이때 다음 입력은 서로 다른 결과여야 합니다.

- `-42`: 정상 음수
- `0`: 정상적인 값 0
- 빈 줄이나 `abc`: 변환할 숫자 없음
- `12xyz`: 숫자 뒤 허용하지 않은 문자
- `long`으로 표현할 수 없을 만큼 큰 수: 범위 초과
- 아무 바이트도 없는 입력: 입력 없음

`atoi`처럼 값 하나만 돌려주는 인터페이스로는 이 상태들을 충분히 구분하기 어렵습니다. 이 단원에서는 `fgets`로 한 줄의 경계를 먼저 확보하고, `strtol`의 반환값·끝 포인터·`errno`를 함께 검사합니다.

## 선수 지식

- 문자 배열과 널 종료 문자 `\0`
- `fgets`가 저장하는 최대 바이트 수와 개행 처리
- EOF와 입력 오류의 차이
- 포인터가 배열의 특정 원소 주소를 가리킬 수 있다는 사실
- 함수의 반환값과 별도 출력 정보를 함께 해석하는 방법

앞 단원의 `char chunk[8]` 반복 읽기는 길이를 모르는 줄을 여러 조각으로 소비했습니다. 이번 실습은 입력 정책을 단순하게 유지하기 위해 `char line[64]` 하나를 사용하며, 첫 줄 내용이 63바이트를 넘으면 `TOO LONG`으로 거부합니다.

## 학습 목표

학습을 마치면 다음을 할 수 있어야 합니다.

1. 문자열을 정수로 바꾸는 일과 입력 전체가 유효한지 검사하는 일을 구분한다.
2. `strtol`의 반환값, `endptr`, `errno`가 각각 어떤 정보를 제공하는지 설명한다.
3. 정상 값 0과 숫자가 하나도 없는 입력을 구분한다.
4. 앞뒤 공백은 허용하되 숫자 뒤의 비공백 문자는 거부한다.
5. `ERANGE`를 사용해 현재 구현의 `long` 표현 범위를 벗어난 입력을 찾는다.
6. 정확히 63바이트인 줄과 64바이트 이상인 줄을 구분한다.
7. `isspace`를 정의된 인수 범위 안에서 호출한다.

## 핵심 이론

### 1. 입력은 먼저 문자열이다

표준 입력에서 읽은 `'-'`, `'4'`, `'2'`는 각각 문자입니다. 프로그램은 이 문자들의 문법을 확인한 뒤 정수 값을 계산해야 합니다. 입력 함수가 어떤 범위까지 읽었는지 모른 채 변환부터 시도하면 다음 입력의 일부를 남기거나, 긴 줄의 첫 조각만 정상 값으로 승인할 수 있습니다.

이 단원은 다음 순서를 사용합니다.

1. 첫 논리 줄을 `fgets`로 읽는다.
2. 줄이 고정 버퍼 정책 안에 완전히 들어왔는지 확인한다.
3. `strtol`로 10진수 변환을 시도한다.
4. 숫자 소비 여부, 범위 상태, 남은 문자를 차례로 검사한다.

### 2. `atoi`의 0은 두 의미를 가질 수 있다

`atoi("0")`은 0을 반환합니다. 숫자로 변환할 수 없는 문자열도 반환값만 보면 0과 구분되지 않을 수 있습니다. 더구나 변환 결과가 `int`로 표현할 수 없는 경우를 검증하는 계약으로 쓰기 어렵습니다.

학습용 입력 검증에서는 “어떤 값이 나왔는가”뿐 아니라 “숫자를 실제로 소비했는가”, “어디에서 멈췄는가”, “표현 범위를 벗어났는가”가 필요합니다. `strtol`은 이 정보를 나누어 제공합니다.

### 3. `strtol`의 인수와 결과

```c
char *endptr;
long value = strtol(line, &endptr, 10);
```

첫 번째 인수는 해석할 널 종료 문자열입니다. 두 번째 인수는 변환에 사용하지 않은 첫 문자의 주소를 받을 포인터입니다. 세 번째 인수 `10`은 10진수로 해석하라는 뜻입니다.

`strtol`은 앞쪽 공백 문자를 건너뛰고 선택적인 `+` 또는 `-` 부호를 처리합니다. 이어지는 10진 숫자를 가능한 만큼 소비한 뒤 멈춥니다. 따라서 변환 함수가 일부 숫자를 찾았다는 사실만으로 전체 줄이 유효하다고 결론 내리면 안 됩니다.

### 4. `endptr == line`은 숫자가 없다는 뜻이다

다음 입력에는 변환 가능한 숫자가 없습니다.

```text

   
abc
+
```

이 경우 `endptr`는 시작 주소인 `line`과 같습니다. 반환값이 0인지 검사해서는 정상 입력 `0`과 구분할 수 없습니다.

```c
if (endptr == line) {
    puts("INVALID");
    return 0;
}
```

### 5. 변환 뒤 남은 문자를 검사한다

`12xyz`에서 `strtol`은 `12`를 계산하고 `endptr`를 `'x'`에 둡니다. 이 동작은 부분 변환으로는 성공이지만, “한 줄 전체가 정수 하나와 공백뿐이어야 한다”는 이 실습 계약에는 실패입니다.

숫자 뒤의 공백, 탭, 개행은 허용하고 나머지는 거부합니다.

```c
while (*endptr != '\0' && isspace((unsigned char)*endptr)) {
    ++endptr;
}

if (*endptr != '\0') {
    puts("INVALID");
    return 0;
}
```

`<ctype.h>`의 `isspace`에는 `EOF` 또는 `unsigned char`로 표현 가능한 값을 `int`로 승격해 전달해야 합니다. 일반 `char`가 signed인 구현에서 음수 바이트를 그대로 넘기지 않도록 `(unsigned char)` 변환을 사용합니다.

### 6. `errno`는 호출 전에 초기화한다

`strtol`은 결과가 `long` 범위를 벗어나면 `errno`를 `ERANGE`로 설정합니다. `errno`는 성공할 때 자동으로 0이 된다고 가정할 수 없습니다. 앞선 라이브러리 호출이 남긴 값을 현재 변환 오류로 오인하지 않으려면 직전에 직접 초기화합니다.

```c
errno = 0;
char *endptr;
long value = strtol(line, &endptr, 10);

if (errno == ERANGE) {
    puts("RANGE");
    return 0;
}
```

범위 초과 방향에 따라 반환값은 `LONG_MIN` 또는 `LONG_MAX` 쪽으로 제한될 수 있습니다. 그 값을 정상 경계값으로 오인하지 말고 `ERANGE`를 함께 확인합니다.

### 7. `LONG_MIN`과 `LONG_MAX`는 구현의 범위다

`<limits.h>`의 `LONG_MIN`과 `LONG_MAX`는 현재 C 구현에서 `long`이 표현할 수 있는 최소·최대값입니다. C 언어는 모든 환경에서 `long`이 반드시 64비트라고 보장하지 않습니다.

따라서 long의 비트 수나 최댓값을 고정해 가정하지 않습니다. 교육 예제에서 특정 운영체제의 숫자를 모든 C 환경의 약속처럼 암기시키지 않고, 실제 변환에서는 `ERANGE`를 판정 근거로 사용합니다.

### 8. 63바이트 경계를 정확하게 판정한다

`char line[64]`에서 `fgets`는 최대 63바이트와 널 문자를 저장합니다. 버퍼 안에서 개행을 찾았다면 첫 줄이 끝났습니다. 개행이 없다면 다음 문자 하나를 확인합니다.

- 다음 문자가 개행: 내용이 정확히 63바이트이므로 허용
- 다음 문자가 EOF이고 입력 오류가 아님: 개행 없이 끝난 63바이트 이하의 마지막 줄이므로 허용
- 다음 문자가 다른 바이트: 첫 줄 내용이 64바이트 이상이므로 나머지 줄을 소비하고 `TOO LONG`
- 읽는 동안 `ferror(stdin)` 발생: 정상 판정으로 처리하지 않음

이 정책은 너무 긴 줄의 앞부분만 숫자로 승인하지 않도록 합니다. 남은 첫 줄을 소비하는 이유는 이후 입력을 처리하는 프로그램으로 확장할 때 스트림 경계를 회복하기 위해서입니다.

### 9. 검사 순서를 정한다

이 실습은 다음 우선순위를 사용합니다.

| 단계 | 조건 | 결과 |
|---|---|---|
| 입력 | 첫 `fgets`가 깨끗한 EOF | `NO INPUT` |
| 줄 경계 | 첫 줄 내용 64바이트 이상 | `TOO LONG` |
| 변환 | 숫자를 하나도 소비하지 않음 | `INVALID` |
| 범위 | `errno == ERANGE` | `RANGE` |
| 잔여 문자 | 공백 아닌 문자가 남음 | `INVALID` |
| 성공 | 위 조건을 모두 통과 | 변환된 `long` 출력 |

범위보다 줄 길이를 먼저 판정하므로, 64자리 숫자는 `RANGE`가 아니라 `TOO LONG`입니다. 이는 C 표준이 정한 보편적 우선순위가 아니라 이 문제에서 명시한 입력 계약입니다.

## 단계별 예제

### 1단계: 읽기 결과와 입력 없음을 구분하기

```c
char line[64];

if (fgets(line, sizeof line, stdin) == NULL) {
    if (ferror(stdin)) {
        return 1;
    }
    puts("NO INPUT");
    return 0;
}
```

빈 줄은 `"\n"`을 성공적으로 읽으므로 `NO INPUT`이 아니라 이후 변환 단계의 `INVALID`가 됩니다.

### 2단계: 너무 긴 줄을 소비하기

```c
size_t i = 0;
while (line[i] != '\0' && line[i] != '\n') {
    ++i;
}

if (line[i] == '\0') {
    int ch = getchar();
    if (ch != EOF && ch != '\n') {
        do {
            ch = getchar();
        } while (ch != EOF && ch != '\n');

        if (ch == EOF && ferror(stdin)) {
            return 1;
        }
        puts("TOO LONG");
        return 0;
    }
    if (ch == EOF && ferror(stdin)) {
        return 1;
    }
}
```

첫 `getchar`가 개행이면 정확한 63바이트 경계입니다. 다른 내용 바이트라면 초과한 줄이므로 개행 또는 EOF까지 소비합니다.

### 3단계: 변환의 세 신호 확인하기

```c
errno = 0;
char *endptr;
long value = strtol(line, &endptr, 10);

if (endptr == line) {
    puts("INVALID");
    return 0;
}
if (errno == ERANGE) {
    puts("RANGE");
    return 0;
}
while (*endptr != '\0' && isspace((unsigned char)*endptr)) {
    ++endptr;
}
if (*endptr != '\0') {
    puts("INVALID");
    return 0;
}
```

### 4단계: 완성 프로그램

다음 코드는 그대로 컴파일할 수 있는 완성 프로그램입니다.

```c
#include <ctype.h>
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    char line[64];

    if (fgets(line, sizeof line, stdin) == NULL) {
        if (ferror(stdin)) {
            return 1;
        }
        puts("NO INPUT");
        return 0;
    }

    size_t i = 0;
    while (line[i] != '\0' && line[i] != '\n') {
        ++i;
    }

    if (line[i] == '\0') {
        int ch = getchar();
        if (ch != EOF && ch != '\n') {
            do {
                ch = getchar();
            } while (ch != EOF && ch != '\n');

            if (ch == EOF && ferror(stdin)) {
                return 1;
            }
            puts("TOO LONG");
            return 0;
        }
        if (ch == EOF && ferror(stdin)) {
            return 1;
        }
    }

    errno = 0;
    char *endptr;
    long value = strtol(line, &endptr, 10);

    if (endptr == line) {
        puts("INVALID");
        return 0;
    }
    if (errno == ERANGE) {
        puts("RANGE");
        return 0;
    }

    while (*endptr != '\0' && isspace((unsigned char)*endptr)) {
        ++endptr;
    }
    if (*endptr != '\0') {
        puts("INVALID");
        return 0;
    }

    printf("%ld\n", value);
    return 0;
}
```

## 실행 결과

앞뒤 공백과 부호는 허용합니다.

```text
입력:   -42  
출력: -42
```

숫자 뒤에 비공백 문자가 있으면 전체 줄 계약에 실패합니다.

```text
입력: 12xyz
출력: INVALID
```

현재 구현의 `long` 범위를 벗어나면 숫자 일부를 정상 값으로 사용하지 않습니다.

```text
입력: 9999999999999999999999999999999999999999
출력: RANGE
```

빈 입력 스트림과 빈 줄도 구분합니다.

```text
입력: 즉시 EOF
출력: NO INPUT

입력: 빈 줄
출력: INVALID
```

## 흔한 오류

1. **`atoi`만 호출한다**: 정상 0과 숫자 없음, 범위 오류를 계약대로 구분하지 못합니다.
2. **`value == 0`을 실패로 본다**: 유효한 입력 `0`, `+0`, `-0`을 잘못 거부합니다.
3. **`endptr`를 검사하지 않는다**: `12xyz`를 정상 12로 승인합니다.
4. **개행만 특별 취급하고 다른 공백을 잊는다**: 뒤따르는 탭 같은 허용 공백을 잘못 거부할 수 있습니다.
5. **`isspace(*endptr)`를 그대로 호출한다**: 음수 `char`가 가능한 환경에서 함수 인수 계약을 어길 수 있습니다.
6. **`errno`를 초기화하지 않는다**: 이전 호출의 오류 상태를 현재 `strtol`의 오류로 오인합니다.
7. **`LONG_MAX` 반환만으로 범위 초과를 판단한다**: 정상 입력이 실제 `LONG_MAX`인 경우와 혼동합니다.
8. **첫 버퍼 조각만 변환한다**: 64바이트 이상인 줄의 앞부분을 값으로 승인하고 나머지를 스트림에 남깁니다.
9. **모든 `long`을 64비트라 가정한다**: 구현 의존 범위를 언어 전체의 고정 보장처럼 설명하게 됩니다.
10. **입력 오류를 `NO INPUT`으로 바꾼다**: 장치·스트림 오류와 정상 EOF를 같은 결과로 숨깁니다.

## 중간 점검

1. `strtol("0", &endptr, 10)`과 `strtol("abc", &endptr, 10)`은 반환값만 보면 왜 구분하기 어렵나요?
2. `12xyz`에서 `endptr`는 어느 문자를 가리키나요?
3. `errno = 0`을 호출 전에 실행해야 하는 이유는 무엇인가요?
4. 반환값이 `LONG_MAX`일 때 그것만으로 범위 초과라고 결론 내릴 수 없는 이유는 무엇인가요?
5. `isspace`에 문자열의 `char`를 전달할 때 왜 `(unsigned char)` 변환을 하나요?
6. 내용 63바이트 뒤 개행과 내용 64바이트 뒤 개행을 어떻게 구분하나요?

## 핵심 요약

- `fgets`로 입력 경계부터 확정한 뒤 숫자를 변환합니다.
- `strtol`의 값, `endptr`, `errno`는 서로 다른 검증 정보를 제공합니다.
- `endptr == line`이면 숫자를 하나도 소비하지 않았습니다.
- `errno == ERANGE`이면 현재 구현의 `long` 범위를 벗어났습니다.
- 변환 뒤 공백만 허용하고 비공백 문자가 남으면 `INVALID`입니다.
- `isspace((unsigned char)*endptr)`처럼 문자 분류 함수의 인수 범위를 지킵니다.
- `LONG_MIN`과 `LONG_MAX`는 구현에서 확인하며 고정 비트 폭을 가정하지 않습니다.
- 고정 버퍼를 쓸 때는 너무 긴 한 줄을 일부만 승인하지 않는 정책이 필요합니다.

- `+`
- `12xyz`

디버그 출력을 최종 제출에 남기면 자동 채점 출력 계약을 깨뜨리므로 실험 뒤 제거합니다.

## 응용 연습

변환된 값이 `-100` 이상 `100` 이하일 때만 승인하도록 응용 정책을 추가하세요. 이 검사는 `strtol`의 표현 범위 검사가 끝난 뒤 실행해야 합니다. `long`으로도 표현할 수 없는 입력과 프로그램이 정한 업무 범위를 벗어난 입력은 서로 다른 종류의 실패입니다.

## 도전 문제

한 줄에 쉼표로 구분한 정수 세 개가 들어오는 형식을 파싱하세요. 첫 번째 `strtol`의 `endptr`에서 쉼표를 확인한 뒤 다음 숫자의 시작점으로 이동합니다. 각 필드에서 숫자 없음, 범위 초과, 잘못된 구분자, 마지막 쓰레기 문자를 구분하세요. 포인터가 원래 배열의 범위 안에서만 이동하도록 설계합니다.

## Mini Project

명령행 도구의 설정 파일에서 `port=4173`, `timeout=1500` 같은 한 줄을 읽어 검증하는 작은 파서를 만드세요. 키 이름, 등호, 정수 값, 뒤따르는 공백의 계약을 문서화하고 다음 사례를 시험합니다.

- 정상 양수와 0
- 음수를 허용하지 않는 키
- 키 누락
- 숫자 없음
- 범위 초과
- 중복 키
- 너무 긴 줄
- 마지막 줄에 개행이 없는 파일

## 테스트와 풀이 개선

이 단원 자동 채점은 다음 범주를 분리합니다.

- 정상 양수·0·음수
- 앞뒤 공백과 선택적 부호
- 빈 줄·공백뿐인 줄·문자열·부호만 있는 줄
- 숫자 뒤 즉시 문자와 공백 뒤 문자
- 양수·음수 방향 범위 초과
- 첫 줄 뒤의 두 번째 줄 무시
- 즉시 EOF
- 정확히 63바이트인 줄
- 64바이트 이상인 줄

먼저 `atoi` 풀이를 제출해 0과 잘못된 입력이 섞이는 실패를 확인하고, `strtol`로 바꾸어 `endptr` 검사를 추가하세요. 그다음 큰 수에서 `ERANGE` 검사가 필요한 이유와 긴 줄에서 버퍼 경계 검사가 필요한 이유를 각각 확인합니다. 한 번에 모든 조건을 고치기보다 실패 범주를 하나씩 줄이면 계약과 코드가 연결됩니다.

표준 입력 파이프만으로 실제 읽기 오류를 안정적으로 주입하기는 어렵습니다. 현재 로컬 채점은 정상 EOF와 위 문자열·범위·길이 경계를 실행 검증하지만, `ferror(stdin)` 분기의 실제 발생까지 통과했다고 주장하지 않습니다.

## 복습 연결

이 단원은 `fgets`의 줄 경계를 문자열 변환 계약으로 연결합니다. 다음에는 `strtoul`, `strtod`, 여러 필드 토큰화, 파일 설정 파서, 명령행 인수 검증으로 확장할 수 있습니다. 자료구조 단원에서는 사용자 입력으로 배열 크기나 명령을 받을 때 같은 검증 흐름을 재사용합니다. Rust에서는 문자열의 `parse::<i64>()`가 오류를 `Result`로 표현하는 방식과 비교하여, C가 값·포인터·전역 오류 상태로 나눈 정보를 어떻게 조합하는지 살펴볼 수 있습니다.
