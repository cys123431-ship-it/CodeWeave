# C언어 심화 06 — 함수 설계: 선언·호출·값 전달

> CodeWeave 독자 원고다. 이미 연결된 함수 화면과 clamp 실습을 확장하며 교재 원문·그림·상용 문제를 복제하지 않는다.

## 단원 개요

입력·계산·출력을 나누는 함수는 자료형 계약과 호출 상태를 함께 가진다. 같은 이름의 지역 변수가 있어도 같은 객체라는 뜻은 아니다.

기존 clamp의 선언·정의·호출·값 전달·배열 길이 설명을 유지하고, 범위·가림·저장기간·연결·자동/정적 객체로 확장한다. 세 완성 프로그램과 함수 부분 코드 조각은 따로 표시한다.

## 필요한 이유

같은 계산을 여러 곳에서 재사용하고 오류를 검사할 범위를 좁히기 위해 함수에 동작의 이름을 붙인다. 호출하는 쪽은 무엇을 요청할지, 함수는 어떻게 수행할지에 집중한다.

함수 원형은 자료형 정보를 제공한다. 외부 입력의 범위, 포인터의 수명, 배열의 실제 길이나 업무 규칙까지 자동 검사하는 장치가 아니다.

## 선수 지식

- int 객체·초기화·대입·비교와 if/return
- scanf 변환 개수와 printf
- 배열의 유효 인덱스·사용 길이
- 주소·역참조·포인터 값 전달

문제 메타데이터의 선수 c-loops/c-pointer는 유지한다. 재귀 구현·동시 실행·함수 포인터는 이번 완성 예제의 범위 밖이다.

## 학습 목표

1. 선언·정의·호출과 원형의 역할을 구분한다.
2. 인수·매개변수·반환값·호출자 객체를 구분한다.
3. 이름의 범위·객체의 저장기간·연결을 다른 질문으로 설명한다.
4. 내부 이름의 가림과 바깥 객체의 수명을 분리한다.
5. 자동/정적 지역 상태를 실제 출력으로 비교한다.
6. 값 반환과 수명이 끝나는 자동 객체의 주소 반환을 구분한다.
7. 배열과 별도 길이·읽기/수치 계약을 함께 전달한다.
8. 컴파일 오류·링크 오류·컴파일되는 오답을 단계별로 점검한다.

## 핵심 이론

### 1. 선언과 원형

다음은 함수 부분 코드 조각이다. main이 없으므로 그 자체로 완성 실행 프로그램은 아니다.

```c
// 함수 부분 코드 조각: 완성 실행 프로그램은 A
int clamp(int value, int low, int high);

int clamp(int value, int low, int high) {
    if (value < low) return low;
    if (value > high) return high;
    return value;
}
```

선언은 반환형과 인수의 형 계약을 알린다. 원형의 매개변수 이름은 설명을 돕지만, 대응 형이 호환된다면 정의의 이름과 반드시 같을 필요는 없다.

정의는 몸체를 제공한다. 선언을 썼다고 몸체가 생성되지는 않는다. 선언/정의의 반환형·매개변수형은 호환되어야 한다.

### 2. 호출과 반환값

main 몸체의 int limited=clamp(15,0,10)은 호출 결과 10을 limited에 저장한다. clamp(value,low,high)만 호출하고 반환값을 버리면 호출자의 value가 자동으로 갱신되는 것은 아니다.

C의 인수는 포인터를 포함해 값으로 전달된다. 호출 시 인수 값은 매개변수의 대응 형으로 변환된다.

### 3. C11의 빈 괄호와 void

C11의 선언 int f(void)는 인수가 없다는 원형이다. 정의가 아닌 선언 int f()는 인수 수/형 정보를 제공하지 않는다. 빈 괄호인 정의는 매개변수가 없는 정의이므로 선언/정의 문맥을 구분한다.

이번 예제와 검사는 -std=c11을 기준으로 한다. 이 설명을 모든 C 버전의 규칙으로 일반화하지 않는다. 새 코드는 명시적 원형을 사용한다.

### 4. 호출 프레임은 학습 모델이다

함수를 호출할 때마다 매개변수와 자동 지역 객체를 별도 상태 묶음으로 추적한다. 같은 함수의 같은 변수 이름이라도 호출마다 객체를 구분한다.

실제 구현이 OS 스택, 레지스터, 인라인 중 무엇을 사용하는지는 별도 문제다. C가 특정 스택 배치나 주소 증가 방향을 보장한다고 설명하지 않는다.

### 5. 이름의 범위

범위는 소스 코드에서 이름을 사용할 수 있는 영역이다. 함수 정의의 매개변수와 블록 안의 ordinary 지역 이름은 해당 블록 범위를 갖는다.

일상적인 “함수 안”과 C 표준의 function scope 용어는 같지 않다. 표준의 함수 범위는 goto 레이블 이름에 해당하며 이번 ordinary 변수의 블록 범위와 구분한다.

이름의 범위는 대체로 선언자의 완성 직후부터 시작한다. 선언 전의 이름 사용과 초기화 여부도 따로 점검한다.

### 6. 내부 이름의 가림

main의 int age=15 뒤 내부 블록에 int age=30을 선언하면 두 객체가 있다. 내부에서 단순 이름 age는 새 객체를 뜻한다.

내부 선언이 바깥 객체를 30으로 수정하거나 삭제하지 않는다. 내부 블록 뒤 바깥 age를 사용하면 15다. 완성 B와 세로 도식에서 직접 관찰한다.

가림은 가능한 문법이지만 불필요하게 남용하면 오해하기 쉽다. 평소 코드에서는 역할별 이름을 사용한다.

### 7. 범위·저장기간·연결

| 질문 | 개념 | 관찰 예 |
| --- | --- | --- |
| 이름을 어디서 쓸 수 있는가? | 범위 | 내부 age는 내부 블록에서 사용 |
| 객체가 언제까지 존재하는가? | 저장기간/수명 | static 지역 객체는 호출 뒤 유지 |
| 여러 선언이 같은 대상을 뜻하는가? | 연결 | 파일 범위 static 함수는 내부 연결 |

이 세 가지를 단순히 “지역/전역” 한 축으로 합치지 않는다. 이름이 좁아도 객체 수명이 길 수 있다.

### 8. 자동 지역 객체

보통의 비VLA 자동 객체 수명은 관련 블록 진입부터 블록 실행이 끝날 때까지다. 내부 블록 진입이나 다른 함수 호출은 바깥 블록의 실행을 잠시 멈출 뿐 객체 수명을 끝내지 않는다.

observe_visit의 int fresh=0은 호출마다 새 객체를 초기화한다. 각 호출에서 fresh를 한 번 증가시키므로 출력은 매번 1이다.

미초기화 자동 int의 값을 읽어 이전 호출의 값으로 해석하지 않는다. 같은 메모리 모양을 우연히 본 것처럼 보이는 실행은 언어 보장이 아니다.

### 9. static 지역 객체

static int persistent=0의 이름은 블록 범위지만 객체는 정적 저장기간을 가진다. 프로그램 시작 전에 한 번 초기화되고 호출 사이에 저장 값을 유지한다.

매번 함수에 들어올 때 0으로 다시 초기화하지 않는다. B의 두 호출에서는 1, 2로 관찰한다. 정적 지역 이름을 다른 함수에서 직접 사용할 수 있는 것은 아니다.

### 10. 정적 초기화의 제약

C11 정적 저장기간 객체의 초기화에는 상수 식/문자열 리터럴 제약이 있다. 이 단원의 int 예제에는 0 같은 정수 상수를 초기값으로 제공한다.

static int total=make()와 같이 함수 호출 결과로 초기화하는 것을 C++의 지연 초기화 규칙처럼 설명하지 않는다. 실제 실행 전에 컴파일 제약으로 검사한다.

초기값을 생략한 정적 int는 0이다. 자동 int도 자동으로 0이라는 뜻은 아니다.

### 11. static 함수와 내부 연결

파일 범위의 static 함수는 번역 단위 내부 연결을 가진다. B의 observe_visit 이름은 파일 범위이고 persistent 이름은 함수 몸체의 블록 범위다.

함수는 객체가 아니므로 객체의 저장기간 분류를 함수에 그대로 붙이지 않는다. static 함수라고 매 호출의 자동 지역 객체가 모두 유지되는 것도 아니다.

### 12. 저장기간은 두 가지만 있는 것이 아니다

C11에는 자동·정적·스레드·할당 저장기간이 있다. 이번 단원은 자동/정적 상태만 직접 관찰한다.

malloc/free의 할당 수명과 _Thread_local의 스레드별 객체는 후속 단원이다. static이 동시 호출·스레드 안전성까지 보장하지 않는다.

### 13. 값 반환과 주소 반환

살아 있는 자동 지역 객체의 값을 return으로 복사하면, 그 객체의 수명이 끝난 뒤에도 복사된 반환값을 사용할 수 있다.

반면 자동 지역 객체 주소를 반환해 수명 종료 뒤 접근하면 정의되지 않은 동작이다. 수명이 끝난 포인터를 읽기·출력·NULL 비교로 검사하지 않는다. 잘못된 주소를 일부러 실행해 “이번에는 됐다”는 예를 만들지 않는다.

### 14. 포인터도 값 전달

set_local(age)는 정수 값을 복사한다. 복사본에 30을 대입해도 main의 객체는 그대로다.

set_target(&age)는 포인터 값을 복사한다. 복사한 값이 같은 main 객체를 가리키므로 역참조를 통해 대상을 바꾼다. C의 별도 참조 전달 방식이 생긴 것은 아니다.

set_target은 살아 있는 수정 가능한 int를 전제로 한다. NULL이나 임의 잘못된 포인터를 검사하는 일반 함수가 아니다.

### 15. 배열과 별도 길이

다음은 함수 부분 코드 조각이다. 함수의 배열 표기는 포인터로 조정되며 원래 배열 크기가 매개변수에 보존되지 않는다.

```c
// 함수 부분 코드 조각: 길이/읽기 범위/합의 표현 가능성은 전제
long long sum_array(const int values[], int count) {
    long long sum = 0;
    for (int i = 0; i < count; ++i) {
        sum += values[i];
    }
    return sum;
}
```

count>=0, 적어도 count개의 읽기 가능한 원소, long long에 표현 가능한 모든 중간 합이 호출자 전제다. const는 이 포인터 경로로 원소를 수정하지 않는 형 계약이다.

반환형을 크게 바꿨다고 임의 큰 합의 signed overflow가 사라지지는 않는다. 빈 배열 정책과 출력 포인터 실패 보존은 기존 배열 함수 실습으로 연결한다.

### 16. 평가 순서와 return 경로

한 printf의 여러 인수에서 같은 객체를 변경하고 읽는 특정 좌우 순서를 기대하지 않는다. C는 인수 평가의 특정 좌우 순서를 보장하지 않는다.

수정 함수 호출과 관찰을 별도 문장으로 나눈다. C의 main은 set_local을 먼저 호출해 returned에 저장한 뒤 값을 출력한다.

void가 아닌 함수에서 필요한 return 경로를 빠뜨리고 호출 결과를 사용하면 정의되지 않은 동작이 될 수 있다. main의 특수 종료 규칙은 별도로 구분한다. void 함수는 값을 돌려주지 않아도 약속한 부작용을 만들 수 있다.

### 17. 상태를 일부러 넣는가?

clamp는 입력 값과 범위만으로 결과를 계산한다. 과거 호출 횟수가 결과에 개입할 필요가 없다.

persistent는 상태 관찰을 위한 교육 예제다. 이를 clamp의 정답에 몰래 추가하는 것은 다른 계약이다. 공유 상태가 필요한지부터 설계하고 의도하지 않은 static 상태는 피한다.

### 18. 기존 입력 계약

c-functions는 표현 가능한 int 세 개와 low<=high를 전제로 한다. low==high도 유효하므로 항상 그 경계값을 돌려준다. 비교만 사용하므로 큰 두 값을 빼는 방식의 signed overflow를 만들지 않는다.

A는 scanf 반환값으로 변환 개수를 확인한다. 임의 큰 숫자 텍스트·추가 토큰·뒤집힌 범위의 일반 검증까지 완료한 것이 아니다. 강건한 입력은 후속 fgets·strtol에서 다룬다.

### 19. 원형·목적 파일·링크

원형이 보이지만 정의가 없을 때 -c로 목적 파일을 생성하는 단계는 성공할 수 있다. 실행 파일을 링크하는 단계에서는 실제 정의가 필요하다.

선언/정의 형 충돌과 블록 밖 이름 사용은 컴파일 단계의 진단이다. 정의 누락은 링크 단계다. 출력값이 잘못된 정상 프로그램은 오답이다.

### 20. 세 실습 경로

현재 전체 프로그램 c-functions, 함수만 작성하는 c-clamp-function, main.c/functions.c/functions.h를 나누는 c-multi-file은 이미 구현되어 있다.

함수 직접 호출형에는 main이나 printf를 추가하지 않는다. 다중 파일 연습의 고정 파일 계약을 임의 통계 프로젝트 이름으로 바꾸어 제출하지 않는다.

## 정적 도식 읽기

도식은 코드를 직접 표시한 세로 스냅샷이다.

1. 바깥 블록: int age=15, 출력 15.
2. 내부 블록: 별도 int age=30, 내부 이름으로 출력 30. 바깥 이름만 가려진다.
3. 내부 블록 뒤: 바깥 age를 사용해 출력 15.

객체를 물리 주소 상자로 배치하거나 실행 애니메이션을 만들지 않는다. 실제 코드와 출력으로 도식을 확인한다.

## 단계별 예제

A: 원형을 읽는다 → 세 입력을 검사한다 → clamp를 호출한다 → 분기별 반환값을 출력한다.

B: 바깥 객체를 초기화한다 → 내부 객체가 이름을 가린다 → 내부 블록 뒤 바깥 이름을 다시 사용한다 → 두 함수 호출에서 자동/정적 상태를 관찰한다.

C: 정수 복사본을 바꿔 반환한다 → 호출자 값과 반환값을 비교한다 → 복사된 포인터의 대상을 바꾼다.

## 완성 프로그램 A: 선언과 기존 clamp

```c
#include <stdio.h>

int clamp(int value, int low, int high);

int main(void) {
    int value, low, high;
    if (scanf("%d%d%d", &value, &low, &high) != 3) return 1;
    printf("%d\n", clamp(value, low, high));
    return 0;
}

int clamp(int value, int low, int high) {
    if (value < low) return low;
    if (value > high) return high;
    return value;
}
```

## 실행 결과 A

입력 15 0 10의 출력은 다음 한 줄이다.

```text
10
```

## 왜 이런 결과가 나오는가

value가 high보다 크므로 high인 10을 반환한다. main의 value 자체를 변경하는 함수가 아니라 결과를 반환하는 함수다.

예제를 바꾸며 실력 다지기: 5 0 10, -3 0 10, 5 5 5의 출력을 먼저 예상한다. printf의 인수를 원래 value로 바꾸면 왜 일부 경계에서 실패하는지 확인한다.

## 완성 프로그램 B: 이름 가림과 자동/정적 지역 상태

```c
#include <stdio.h>

static void observe_visit(void) {
    int fresh = 0;
    static int persistent = 0;
    ++fresh;
    ++persistent;
    printf("fresh=%d persistent=%d\n", fresh, persistent);
}

int main(void) {
    int age = 15;
    printf("outer=%d\n", age);
    {
        int age = 30;
        printf("inner=%d\n", age);
    }
    printf("after=%d\n", age);
    observe_visit();
    observe_visit();
    return 0;
}
```

## 실행 결과 B

```text
outer=15
inner=30
after=15
fresh=1 persistent=1
fresh=1 persistent=2
```

내부 age와 바깥 age는 별도 객체다. 내부 이름의 가림이 끝나면 바깥 이름이 다시 사용된다. fresh는 각 호출에서 0으로 초기화되고 persistent는 같은 객체의 상태를 유지한다.

예제를 바꾸며 실력 다지기: 내부 초기값만 40으로 바꾸면 어느 줄이 달라지는가? observe_visit를 세 번 호출하면 마지막 두 값은 무엇인가? 정적 초기화를 매번 수행한다고 오해하지 않는다.

B는 정확히 두 번 호출해 int 증가의 안전 범위 안이다. 무제한 호출이나 동시 실행 안전성을 증명하지 않는다.

## 완성 프로그램 C: 반환값과 호출자 수정

```c
#include <stdio.h>

static int set_local(int age) {
    age = 30;
    return age;
}

static void set_target(int *age) {
    *age = 30;
}

int main(void) {
    int age = 15;
    int returned = set_local(age);
    printf("returned=%d caller=%d\n", returned, age);
    set_target(&age);
    printf("caller=%d\n", age);
    return 0;
}
```

## 실행 결과 C

```text
returned=30 caller=15
caller=30
```

첫 함수는 복사본의 값을 바꿔 반환한다. 다음 함수는 복사된 포인터가 가리키는 main 객체를 바꾼다. 반환과 관찰은 별도 문장으로 나눈다.

예제를 바꾸며 실력 다지기: 두 함수의 대입값을 40으로 바꾸고 returned/caller 값을 예상한다. set_target에 main의 살아 있는 객체 주소 대신 수명이 끝난 주소를 넘겨 실험하지 않는다.

## 흔한 오류

- 원형을 함수 몸체나 입력 검증기라고 생각한다.
- C11에서 빈 괄호 선언과 void 원형을 같다고 설명한다.
- 내부 같은 이름 선언이 바깥 객체를 수정한다고 생각한다.
- static 지역 이름은 어디에서나 보인다고 생각한다.
- 정적 초기화가 매 호출마다 또는 C++처럼 함수 실행 때 일어난다고 생각한다.
- 지역 값을 반환하는 것과 지역 객체 주소 반환을 혼동한다.
- 스택 그림을 C의 실제 메모리 배치 보장이라고 설명한다.
- 원형만 넣고 실제 정의를 링크하지 않는다.
- 반환값을 버린 뒤 호출자 변수를 출력한다.
- 같은 식의 여러 인수에서 동일 객체의 수정/관찰 순서에 기대한다.

## 중간 점검

1. 내부 age=30 뒤 바깥 age는? 15.
2. 두 호출의 fresh/persistent는? 1/1, 1/2.
3. static 지역 이름은 다른 함수에서 직접 보이는가? 아니다.
4. 원형만으로 정의가 생기는가? 아니다.
5. 포인터 매개변수도 복사되는가? 그렇다.
6. 같은 입력의 clamp가 과거 호출 횟수로 달라져도 되는가? 아니다.

결과 숫자만 말하지 말고 어떤 객체와 어떤 호출을 관찰했는지 설명한다.

## 핵심 요약

선언은 형 계약, 정의는 몸체, 호출은 실행 요청이다. 범위·저장기간·연결을 분리한다. 자동 지역 상태와 정적 지역 상태를 의도적으로 선택한다.

값 전달·수명·배열 길이·수치 범위는 안전한 함수 인터페이스의 전제다. 컴파일 성공은 모든 전제의 충족을 증명하지 않는다.

## 개념 확인

기존 퀴즈: 함수 원형의 가장 중요한 역할은 무엇인가?

정답은 함수 이름·매개변수 자료형·반환형을 컴파일러에 알리는 선택지 0이다. 함수 실행·출력·입력 검증·지역 객체 수명 연장이 아니다. 기존 선택지와 정답을 유지한다.

## 응용 연습

swap_int에 유효한 수정 가능한 int 주소 두 개를 전달한다. 임시 int로 교환하고 같은 주소 두 번을 전달했을 때 값이 보존되는지도 확인한다. 산술 교환으로 불필요한 넘침을 만들지 않는다.

## 도전 문제

기존 clamp의 반환값을 버린 뒤 main의 value를 출력하는 오답을 수정한다. 반환값을 받아 출력하고 기존 여섯 사례, low==high를 확인한다. 함수 본문 전용 문제는 불필요한 출력을 제거한다.

## Mini Project

main.c/statistics.c/statistics.h로 배열 합·최소·최대를 설계한다. 헤더의 원형/중복 포함 방지, 빈 배열 정책, 읽기 가능한 길이, 합의 표현 가능성, 정의 포함을 먼저 정한다.

이 독립 설계 연습은 아직 새 자동 채점 문제로 등록하지 않았다. 이미 구현된 c-multi-file에는 그 문제의 main.c/functions.c/functions.h 계약을 그대로 사용한다.

## 테스트 및 풀이 개선

A/B/C와 두 함수 부분 조각을 gcc -std=c11 -Wall -Wextra -Werror -Wpedantic으로 실제 컴파일한다. 화면/원고 소스 일치, 실제 출력, A의 기존 사례와 작은 경계 조합을 검사한다.

자료형 충돌·블록 밖 이름·정적 int의 함수 호출 초기화는 컴파일 실패를 예상한다. 원형만 있는 소스는 -c 성공 뒤 링크 실패를 확인한다. 실패 소스는 실행하지 않는다.

유한 검사는 임의 포인터/메모리 안전·모든 입력·실제 스택 배치를 증명하지 않는다. 시간 제한도 보안 샌드박스가 아니다.
