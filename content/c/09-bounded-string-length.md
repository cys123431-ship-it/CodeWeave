# 경계 있는 문자열: 용량과 종료 문자

> 이 원고는 CodeWeave를 위해 독자 작성한 학습 자료다. 특정 교재의 본문·그림·문제를 복제하지 않았다.

## 단원 개요

C 문자열은 첫 널 문자 `\0`에서 끝난다. 그러나 함수가 받은 `char *`만으로는 실제 배열의 크기와 종료 문자의 존재를 알 수 없다. 이 단원에서는 포인터와 함께 **읽어도 되는 최대 문자 수**를 전달하고, 그 범위에서만 종료 문자를 찾는 `bounded_length`를 설계한다.

핵심 질문은 “종료 문자가 메모리 어딘가에 있는가?”가 아니다. “호출자가 허용한 `[0, capacity)` 범위 안에 종료 문자가 있는가?”이다.

## 선수 지식

- 문자 배열과 C 문자열의 차이
- 널 문자 `'\0'`
- 배열 인덱스와 반열린 구간
- `size_t`, 포인터, `NULL`
- 상태 반환값과 출력 포인터

## 학습 목표

학습 후에는 다음을 할 수 있어야 한다.

1. `capacity`가 배열의 길이와 언제 같고 언제 다를 수 있는지 설명한다.
2. `[0, capacity)`만 읽는 반복문을 작성한다.
3. 마지막 허용 칸의 종료 문자와 범위 바로 밖의 종료 문자를 구분한다.
4. 실패한 함수가 출력 객체를 변경하지 않도록 구현한다.
5. `fgets`의 크기 인수, 널 종료, 개행 보존, 실패 반환을 설명한다.

## 핵심 이론

### 포인터에는 저장 공간 크기가 없다

함수 매개변수 `const char *buffer`는 첫 문자 객체의 주소다. 그 주소만 보고 배열이 세 칸인지 삼백 칸인지 알아낼 방법은 없다. 그래서 길이 제한 함수는 별도의 `capacity`를 받는다.

```c
int bounded_length(const char *buffer,
                   size_t capacity,
                   size_t *out_length);
```

호출자는 `buffer`부터 `capacity`개의 `char` 객체가 읽기 가능함을 보장해야 한다. `capacity` 숫자를 함께 넘겼다는 이유만으로 잘못된 포인터나 너무 작은 배열이 안전해지는 것은 아니다.

### `[0, capacity)`는 capacity를 포함하지 않는다

`capacity`가 4라면 읽을 수 있는 인덱스는 0, 1, 2, 3이다. 반복 조건은 `i < capacity`여야 한다.

```c
for (size_t i = 0; i < capacity; ++i) {
    /* buffer[i]는 호출자 계약 안에서 읽는다. */
}
```

`i <= capacity`로 쓰면 `buffer[capacity]`까지 읽어 한 칸 벗어난다. 이는 정의되지 않은 동작을 일으킬 수 있다.

### 성공과 실패 계약

다음 세 조건은 호출 직후 검사한다.

- `buffer == NULL`
- `out_length == NULL`
- `capacity == 0`

어느 하나라도 참이면 0을 반환한다. 입력이 유효해도 종료 문자가 범위 안에 없으면 0이다. 성공한 경우에만 `*out_length`를 변경한다. 이 규칙 덕분에 호출자는 실패한 결과를 실수로 새 길이로 사용할 가능성을 줄일 수 있다.

## 단계별 예제

먼저 네 칸 배열을 살펴보자.

```c
const char word[] = {'C', 'A', 'T', '\0'};
```

`capacity`가 4이면 인덱스 3의 종료 문자를 검사할 수 있다. 그 인덱스가 종료 문자 앞의 문자 수이므로 길이는 3이다.

```c
#include <stddef.h>

int bounded_length(const char *buffer, size_t capacity,
                   size_t *out_length) {
    if (buffer == NULL || capacity == 0 || out_length == NULL) {
        return 0;
    }

    for (size_t i = 0; i < capacity; ++i) {
        if (buffer[i] == '\0') {
            *out_length = i;
            return 1;
        }
    }
    return 0;
}
```

같은 배열에 `capacity` 3을 전달하면 인덱스 3은 범위 밖이다. 함수는 배열 밖을 추측해 읽지 않고 실패한다. 종료 문자가 범위 안에 없으면 문자열의 길이를 확정할 수 없기 때문이다.

## 실행 결과

다음은 완성 프로그램의 호출 부분이다.

```c
#include <stdio.h>

int main(void) {
    const char word[] = {'C', 'A', 'T', '\0'};
    size_t length = 77;

    int status = bounded_length(word, 4, &length);
    printf("%d %zu\n", status, length);
    return 0;
}
```

실행 결과:

```text
1 3
```

`bounded_length(word, 3, &length)`로 바꾸면 결과는 `0 77`이다. 종료 문자는 존재하지만 허용 범위 밖이며, 실패했으므로 기존 출력값 77을 보존한다.

### `fgets`와 실제 입력 버퍼

`fgets(buffer, n, stream)`는 성공하면 최대 `n - 1`개의 문자를 저장하고 마지막에 널 문자를 기록한다. 줄의 개행 문자가 그 안에 들어오면 개행도 저장된다.

```c
#include <stdio.h>

int main(void) {
    char line[8];
    if (fgets(line, sizeof line, stdin) == NULL) {
        return 1;
    }

    size_t stored;
    if (!bounded_length(line, sizeof line, &stored)) {
        return 2;
    }
    printf("저장된 문자 수: %zu\n", stored);
    return 0;
}
```

사용자가 `CAT` 뒤 Enter를 누르고 전체 줄이 들어오면 배열에는 `C`, `A`, `T`, `\n`, `\0`가 저장될 수 있다. 따라서 출력 길이는 4다. 빈 줄도 첫 문자가 즉시 `\0`인 문자열이 아니라 보통 `"\n"` 문자열이다.

버퍼가 먼저 가득 차면 개행은 다음 입력에 남을 수 있다. 성공한 `fgets` 호출은 널 종료를 보장하지만, 개행이 없다는 사실만으로 입력 줄 전체를 읽었다고 단정할 수는 없다. 반환값이 `NULL`이면 EOF 또는 오류이므로 버퍼에 새 문자열이 있다고 가정해서는 안 된다.

## 흔한 오류

1. **`i <= capacity` 사용**: 마지막 반복에서 허용 범위를 한 칸 벗어난다.
2. **종료 누락을 성공으로 처리**: 종료 문자가 범위 안에 없으면 `capacity`를 문자열 길이로 발표해서는 안 된다.
3. **실패 전에 결과 초기화**: `*out_length = 0`을 먼저 수행하면 출력 보존 계약을 어긴다.
4. **`capacity`를 실제 배열보다 크게 전달**: 함수가 범위를 지켜도 호출자 계약이 틀리면 범위 밖 읽기가 생긴다.
5. **`strlen`로 대신 검사**: `strlen`은 먼저 종료 문자를 찾아야 하므로 비종료 버퍼의 경계 검증 수단이 아니다.
6. **`fgets` 개행 무시**: 저장 길이와 사용자가 입력한 본문 길이를 같은 것으로 오해한다.

## 중간 점검

1. `capacity == 3`일 때 `buffer[3]`을 읽을 수 있는가?
2. 종료 문자가 `buffer[capacity - 1]`에 있으면 성공인가?
3. 종료 문자가 범위 안에 없을 때 왜 길이를 `capacity`라고 기록하지 않는가?
4. `fgets`가 성공해도 개행 문자가 없을 수 있는 이유는 무엇인가?
5. `capacity`는 왜 잘못된 포인터를 안전하게 만들지 못하는가?

## 핵심 요약

- 검사 범위는 `[0, capacity)`다.
- 호출자가 그 범위의 객체가 실제로 읽기 가능함을 보장한다.
- 범위 안의 첫 종료 문자 인덱스가 길이다.
- 종료 문자가 범위 안에 없으면 실패하고 출력값을 보존한다.
- `fgets`는 성공 시 널 종료하지만 개행을 저장할 수 있으며, `NULL` 반환을 먼저 처리해야 한다.

## 기초 코딩 연습

빈 문자열 배열 `{ '\0' }`과 `capacity` 1을 전달해 성공 상태 1, 길이 0을 확인하라. 이어 `{ 'A', 'B', '\0' }`에 용량 2와 3을 각각 전달해 결과 차이를 적어 보라.

## 응용 연습

`fgets`로 읽은 문자열의 마지막 문자가 `\n`이면 그 문자를 제외한 본문 길이를 계산하는 함수를 작성하라. 개행이 없을 때는 버퍼가 잘린 것인지 EOF 직전 입력인지 호출 정책으로 구분해야 한다.

## 도전 문제

긴 한 줄을 작은 버퍼로 여러 번 읽고, 개행을 만날 때까지 총 문자 수를 누적하라. 각 조각이 널 종료되었는지 검사하고 오버플로 없이 누적하는 방법도 설명하라.

## 테스트와 풀이 개선

최소 다음 사례를 독립적으로 검사한다.

- 정상 문자열과 빈 문자열
- 첫 종료 문자 뒤에 쓰레기 값이 있는 배열
- 마지막 허용 칸의 종료 문자
- 종료 문자가 없는 정확한 크기 배열
- 종료 문자가 범위 바로 밖에 있는 배열
- `capacity == 0`
- `buffer == NULL`, `out_length == NULL`
- 모든 실패에서 기존 출력값 보존
- 함수가 표준 출력에 디버그 문자를 쓰지 않음
