# 포인터의 주소와 역참조: 대상·별칭·수명을 함께 보기

## 단원 개요

포인터는 단지 별표 문법이 아니다. **포인터 객체에 저장된 값, 그 값이 가리키는 대상 객체, 대상에 접근할 수 있는 조건**을 분리해 이해한다.

주소·역참조·초기화·NULL·수명·별칭·값 전달·배열/길이·읽기/쓰기를 연결한 뒤 기존 c-pointer 실습을 유지한다. 오류를 만들기 위해 잘못된 주소를 실행하지 않고, 정의된 동작의 관찰과 계약 설명으로 확인한다.

## 필요한 이유

함수에 정수를 전달하면 함수가 받은 복사본을 바꾸어도 호출자의 정수는 그대로다. 호출자의 객체를 수정하거나 배열 범위를 읽기 위해 주소를 전달한다.

주소는 사용 권한과 수명을 자동 보장하지 않는다. 어떤 객체인지, 살아 있는지, 몇 개를 읽거나 쓸 수 있는지와 값 범위를 함께 전달해야 한다.

## 선수 지식

- 변수·객체·초기화·대입과 정수 표현 범위
- 함수 호출과 매개변수의 최소 형식
- 조건식·단락 평가
- 배열의 사용 길이·용량·sizeof

동적 메모리와 해제는 후속 단원이다. 이번 실행 예제는 살아 있는 지역 int 객체만 사용한다.

## 학습 목표

1. 선언의 *와 식의 역참조 *를 구분한다.
2. &x·p·*p·&p가 서로 다른 역할임을 설명한다.
3. p 재대입과 *p 쓰기를 구분한다.
4. 포인터 값 복사·별칭·대상 값 복사를 구분한다.
5. 포인터도 값 전달이며 호출자 객체가 바뀌는 이유를 설명한다.
6. 초기화·NULL·수명·형·범위·쓰기 가능성을 점검한다.
7. 배열 객체·포인터 객체·별도 길이의 관계를 설명한다.
8. 증가하기 전에 수치 범위를 확인하고 실패 시 값을 보존한다.

## 핵심 이론

### 1. 포인터도 별도 객체다

`int x=7; int *p=&x;`에서 x는 int 객체이고 p는 int를 가리키는 값을 저장하는 별도 포인터 객체다.

| 표현 | 역할 |
| --- | --- |
| x | int 객체의 값 |
| &x | x를 가리키는 값 |
| p | 포인터 객체에 저장된 값 |
| *p | p가 가리키는 객체 |
| &p | 포인터 객체 p 자체를 가리키는 값 |

*p를 읽는 것과 p를 읽는 것은 다르다. &p의 형은 int **이지만 이중 포인터 구현은 후속 동적 메모리 실습에서 자세히 배운다.

### 2. 선언과 역참조의 별표

`int *p;`의 별표는 선언에서 p의 형을 정한다. 식 `*p`의 별표는 가리키는 객체를 지정한다.

`int *p, q;`에서 p는 포인터이고 q는 int다. 입문에서는 한 줄에 하나씩 선언한다. 별표를 단순히 int의 일부 모양으로 암기하면 q까지 포인터로 오해하기 쉽다.

### 3. 초기화가 먼저다

자동 저장 기간의 `int *p;`는 접근 대상이 정해지지 않은 미초기화 포인터다. 이를 읽어 비교하거나 역참조하는 코드를 정상 예제로 실행하지 않는다.

다음은 main 몸체에 넣는 **코드 조각**이다.

```c
int x = 7;
int *p = &x;
*p = 8;
```

초기화는 적절한 형의 살아 있는 객체를 가리키게 만드는 단계다. 임의 정수를 캐스트한다고 유효한 객체가 생기지는 않는다.

### 4. &와 *의 연결

&x는 x를 가리키고, 그 값을 p에 저장하면 *p가 x를 지정한다. *p=8은 x=8과 같은 대상 쓰기를 수행한다.

포인터를 읽었다고 반드시 대상을 읽는 것은 아니다. 대상 값을 사용하려면 역참조와 읽기 조건을 따로 만족해야 한다.

### 5. p와 *p의 변경 대상

`p=&other;`는 포인터 객체 p의 값을 바꾼다. `*p=8;`는 p가 가리키는 객체를 바꾼다.

주소를 재대입하는 동안 원래 객체가 자동으로 복사되거나 삭제되지 않는다. 어느 객체가 바뀌는지 문장으로 먼저 말한 뒤 코드를 읽는다.

### 6. 포인터 값 복사와 별칭

`int *alias=p;`는 포인터 값을 복사한다. 두 값이 같은 객체를 가리키면 한 경로로 바꾼 값을 다른 경로에서도 관찰할 수 있다.

p만 다른 객체로 재대입해도 alias는 따라가지 않는다. 대상 객체의 복사도, 별칭 포인터 전체의 일괄 갱신도 아니다. 별칭이 있다고 대상 수명이 늘어나지도 않는다.

### 7. NULL은 명시적 대상 없음

`int *p=NULL;`은 대상 없음의 상태다. 널 포인터를 역참조할 수는 없다. NULL은 관련 헤더에서 제공하는 널 포인터 상수 매크로를 사용한다.

널 포인터의 바이트 표현이 항상 전부 0이라고 단정하지 않는다. 정수 상수 0을 포인터 문맥에서 쓰는 언어 규칙과 물리 주소 숫자/비트 패턴은 다르다.

### 8. NULL 검사만으로 유효성은 증명되지 않는다

p!=NULL은 널이 아니라는 사실만 확인한다. 다음도 필요하다.

- 적절한 형과 정렬의 실제 객체
- 끝나지 않은 대상 수명
- 읽을 때 초기화된 값
- 쓰기 가능한 대상
- 배열이면 읽기/쓰기 가능한 범위

미초기화·수명 종료·범위 밖 포인터를 널 검사로 안전하게 바꾸지 못한다. 함수는 일반적인 임의 포인터 검사기가 아니다.

### 9. 수명과 범위

지역 객체의 수명은 그 선언이 속한 블록의 실행과 연결된다. 수명이 끝난 지역 객체를 더 이상 참조하면 정의되지 않은 동작이다.

수명이 끝난 객체를 가리키던 포인터 값도 미정이 될 수 있다. 이후 그 값을 읽거나 비교하거나 출력하는 것으로 유효성을 시험하지 않는다. 지역 객체의 주소를 반환해 나중에 사용하는 설계는 피한다.

이번 예제의 value·other는 관찰 시점 모두 main의 블록 안에서 살아 있다. 후속 malloc/free에서도 해제와 별칭 수명의 계약을 별도로 설명한다.

### 10. 포인터도 값 전달

add_one(&n)은 n을 가리키는 값을 매개변수 value에 복사한다. 함수 안 value는 호출자의 포인터 변수 자체가 아니다.

하지만 복사한 값도 같은 n을 가리키므로 `++(*value)`는 호출자의 n을 바꾼다. 함수 안에서 value를 다른 주소로 재대입하는 것만으로 호출자가 저장한 포인터 값이 바뀌지는 않는다.

이 구분이 이중 포인터를 요구하는 이유와 연결된다. 지금은 대상 int 하나를 바꾸는 계약만 구현한다.

### 11. p++와 (*p)++

| 표현 | 변경되는 것 |
| --- | --- |
| p++ | 포인터 객체의 값 |
| (*p)++ | 가리키는 원소의 값 |
| *p++ | *(p++)로 해석, 포인터 이동 포함 |

괄호로 의도를 드러낸다. p++가 허용되는 범위와 *p를 읽는 범위는 별도다. 단일 객체 다음 위치가 표현 가능하더라도 그곳을 다음 int 데이터처럼 역참조하지 않는다.

### 12. int 증가의 수치 계약

기존 실습은 증가 전 -10000~9999, 증가 후 -9999~10000으로 제한한다. 이 범위는 C의 최소 int 범위 안이다.

INT_MAX인 int에 1을 더하면 signed overflow로 정의되지 않은 동작이다. 결과가 작아졌는지 계산 뒤 살피는 방식은 예방이 아니다. 증가하기 전에 범위를 검사한다.

### 13. 배열 객체와 포인터 객체의 차이

배열 표현식은 많은 문맥에서 첫 원소를 가리키는 값으로 변환된다. 배열 객체 자체가 포인터 객체와 동일한 형이나 크기라는 뜻은 아니다.

실제 배열 a와 포인터 p의 sizeof를 구분한다. 함수의 배열 매개변수는 포인터 형으로 조정되며 길이는 별도 count로 전달한다. 포인터 하나만으로 원래 배열의 원소 수를 구하지 않는다.

### 14. 원소 단위 이동과 끝 바로 다음

같은 배열에서 p+i는 원소 단위 이동이다. 숫자 바이트 주소에 i를 그대로 더한다는 설명을 일반 규칙으로 쓰지 않는다.

초기화된 데이터의 유효 범위 [0,count)만 역참조한다. 끝 바로 다음 포인터는 표현할 수 있어도 읽을 원소는 아니다. 같은 배열 범위 밖으로 포인터 연산을 수행하지 않는다.

서로 다른 객체 주소를 일반적인 순서/거리처럼 관계 비교하거나 차감하지 않는다. 포인터 차이는 같은 배열/끝 다음 범위와 결과 표현 가능성을 전제로 한다.

### 15. sizeof와 실제 역참조

sizeof p는 포인터 객체의 바이트 수다. 이번 int *p의 sizeof *p는 int형 크기이며 고정된 int형에서는 대상 값을 읽는 역참조 실행이 아니다.

int는 항상 4바이트, 포인터는 항상 8바이트라는 가정을 하지 않는다. 이 sizeof 규칙을 일반적인 *p 읽기·쓰기 허용으로 확대하지 않는다. VLA처럼 sizeof가 평가되는 경우는 별도 심화 주제다.

### 16. const의 위치

const int *view는 이 포인터 경로로 대상을 수정하지 않는 선언이다. int *const fixed는 포인터 값의 재대입을 제한하는 선언이다.

읽기 전용 경로라고 대상 수명이나 유효 범위가 보장되는 것은 아니다. 캐스트로 const를 제거해도 원래 수정 불가능한 객체에 쓰기가 허용되지 않는다.

### 17. %p와 주소 출력

객체 주소를 출력할 때 %p의 인수는 void *로 변환한 값으로 전달한다. 프로그램 A에서 이 변환을 실제 컴파일하고 실행한다.

주소 문자열의 형태는 구현 정의이며 주소 값도 실행에 따라 달라질 수 있다. 고정 16진수 접두나 숫자를 정답으로 요구하지 않는다. 주소를 출력하는 것과 대상 값을 출력하는 것도 구분한다.

### 18. 실패 상태와 단락 평가

별도 try_add_one은 NULL을 먼저 확인한다. OR의 왼쪽이 참이면 오른쪽 *value 검사는 평가하지 않아 널을 역참조하지 않는다.

널이 아닌 경우에는 실제로 살아 있는 수정 가능한 int를 받는다는 호출자 전제가 필요하다. 값이 INT_MAX면 쓰기 전에 0을 반환하고 기존 값을 보존한다. 성공하면 1을 반환한다.

### 19. 쓰기와 관찰을 분리한다

호출자의 값을 바꾸는 함수 호출과 그 값 출력은 다른 명령문으로 분리한다. 같은 printf의 여러 인수에 수정 호출과 같은 객체의 읽기를 섞어 평가 순서를 기대하지 않는다.

프로그램 C는 먼저 status에 호출 결과를 저장한 뒤 status와 객체 값을 출력한다. 오류를 만들기 위해 순서가 불명확한 식을 실행하지 않는다.

### 20. 입력 계약과 오류 범위

채점기는 정확히 한 정수를 -10000~9999로 제공한다. 범위 밖 값·변환 실패·조기 EOF·추가 토큰은 기존 채점 대상이 아닙니다.

B는 변환 개수와 표현 가능한 입력값 범위를 검사해 간단한 오류에서 상태 1로 종료한다. scanf의 %d가 임의 큰 숫자 텍스트를 안전하게 거부하는 파서는 아니다. 일반 입력 검증은 후속 fgets·strtol과 연결한다.

## 정적 도식 읽기

시점 A: p와 alias는 같은 value를 가리키며 *p=8 뒤 두 경로에서 8을 관찰한다.

시점 B: p만 other로 재대입해 *p=21을 수행한다. other는 21이지만 alias는 value를 계속 가리켜 8을 관찰한다.

두 시점은 실행 애니메이션이 아니라 비교 지도다. 주소 숫자·바이트 폭은 생략하고 객체 관계만 보여 준다.

## 단계별 예제

살아 있는 int를 초기화한다 → 그 객체 주소로 포인터를 초기화한다 → 역참조해 값을 바꾼다 → 별칭으로 관찰한다 → 한 포인터만 다른 살아 있는 객체로 재대입한다.

다음 A는 값과 주소 관찰, B는 기존 실습, C는 상태 반환과 실패 보존이다. 서로 다른 계약을 한 채점 규칙으로 섞지 않는다.

## 완성 프로그램 A: 별칭과 재대입 관찰

```c
#include <stdio.h>

int main(void) {
    int value = 7;
    int *p = &value;
    int *alias = p;
    printf("address=%p\n", (void *)p);

    *p = 8;
    printf("value=%d p=%d alias=%d\n", value, *p, *alias);

    int other = 20;
    p = &other;
    *p = 21;
    printf("value=%d other=%d alias=%d\n", value, other, *alias);
    return 0;
}
```

## 실행 결과

A의 첫 줄은 address= 뒤 현재 실행의 주소 표현이다. 이 부분은 고정하지 않는다. 그 다음 두 줄은 다음과 같다.

```text
value=8 p=8 alias=8
value=8 other=21 alias=8
```

## 왜 이런 결과가 나오는가

첫 쓰기는 value를 바꾼다. p와 alias의 값이 같은 대상에 연결되므로 두 경로로 같은 8을 읽는다. 그 다음 p만 other로 바뀌고 21을 쓰므로 value·alias는 그대로다.

예제를 바꾸며 실력 다지기: 다른 객체의 초기값과 두 번째 쓰기를 각각 30과 31로 바꾼다. value와 alias 출력은 바뀌는지 먼저 예상한다. 주소를 정답 숫자로 비교하지 않는다.

## 완성 프로그램 B: 기존 주소 전달 실습

```c
#include <stdio.h>

void add_one(int *value) {
    ++(*value);
}

int main(void) {
    int n;
    if (scanf("%d", &n) != 1) {
        return 1;
    }
    if (n < -10000 || n > 9999) {
        return 1;
    }
    add_one(&n);
    printf("%d\n", n);
    return 0;
}
```

| 입력 | 출력 |
| ---: | ---: |
| 7 | 8 |
| -4 | -3 |
| 0 | 1 |
| -10000 | -9999 |
| 9999 | 10000 |

n은 main 블록에서 살아 있고 add_one에는 &n을 전달한다. 함수는 ++(*value)로 대상 n을 바꾸며 포인터 변수 자체를 움직이지 않는다.

예제를 바꾸며 실력 다지기: -1과 9998을 입력해 출력부터 예상한다. p++ 형태로 구현하면 대상 값이 바뀌지 않는 이유를 설명하고 기존 경계에서 실패하는지 확인한다. 잘못된 포인터 역참조를 일부러 실행하지 않는다.

## 완성 프로그램 C: NULL·상한 실패 보존

```c
#include <limits.h>
#include <stddef.h>
#include <stdio.h>

static int try_add_one(int *value) {
    if (value == NULL || *value == INT_MAX) {
        return 0;
    }
    ++(*value);
    return 1;
}

int main(void) {
    int value = 7;
    int status = try_add_one(&value);
    printf("normal=%d value=%d\n", status, value);

    int limit = INT_MAX;
    status = try_add_one(&limit);
    printf("limit=%d preserved=%d\n", status, limit == INT_MAX);

    printf("null=%d\n", try_add_one(NULL));
    return 0;
}
```

C는 다음을 출력한다.

```text
normal=1 value=8
limit=0 preserved=1
null=0
```

현재 환경의 INT_MAX 기호를 사용해 상한 숫자나 고정 비트 폭을 가정하지 않고, 실패 뒤 limit==INT_MAX의 참/거짓을 출력한다. NULL 경로에서는 *value를 읽지 않는다. limit의 주소는 유효하고 살아 있으므로 값 상한 검사와 임의 포인터 유효성 검사를 구분한다.

예제를 바꾸며 실력 다지기: 정상 value를 -1로 바꾸면 상태 1·값 0이다. INT_MAX 실패 경로에서는 쓰기가 발생하지 않았는지 확인한다. 기존 void add_one 문제를 이 상태 반환 함수로 바꾸어 제출하지 않는다.

## 흔한 오류

- 선언의 *와 식의 *를 같은 역할로 암기한다.
- 미초기화 포인터를 NULL과 비교해 검사하려 한다.
- p 자체만 이동하고 대상 int는 증가시키지 않는다.
- 널이 아니면 살아 있는 유효 객체라고 가정한다.
- 지역 객체 주소를 저장해 수명 종료 뒤 읽는다.
- 끝 바로 다음 포인터를 다음 데이터처럼 역참조한다.
- 포인터 크기로 배열 길이를 추측한다.
- signed 증가 후에야 넘침을 검사한다.
- 한 식의 여러 인수에서 같은 객체의 수정/관찰 순서를 기대한다.

## 중간 점검

1. *p=8과 p=&other는 각각 무엇을 바꾸는가?
2. alias=p 뒤 p를 재대입하면 alias도 바뀌는가?
3. NULL 검사만 통과하면 대상 수명이 보장되는가?
4. add_one은 포인터를 참조 전달하는가, 포인터 값 복사 뒤 대상을 바꾸는가?
5. 기존 실습의 입력 상한과 출력 상한은?

확인: 대상/포인터 객체, 아니오, 아니오, 포인터도 값 전달, 9999·10000이다. 객체 이름과 시점을 함께 설명한다.

## 개념 확인 퀴즈

`int x=7; int *p=&x; *p=8;` 뒤 x의 값은?

정답은 8이다. 포인터 p의 숫자 주소를 출력한 것이 아니라 p의 대상 x에 값을 대입했다. 기존 정답 인덱스 1과 선택지는 유지한다.

## 핵심 요약

포인터 값과 대상 값을 나눈다. 주소 복사·별칭·재대입은 대상 복사나 수명 연장이 아니다. 역참조 전에 초기화·수명·형·범위·읽기/쓰기·수치 계약을 확인하고 NULL 검사만으로 안전성을 주장하지 않는다.

## 기초 코딩 연습

기존 c-pointer에서 add_one을 구현한다. 0·양수·음수·양쪽 경계를 테스트하고 호출자 n이 바뀌는 이유를 설명한다.

## 응용 연습

두 유효한 int 객체의 값을 임시 int로 교환한다. 같은 객체 주소를 두 번 전달할 때는 값이 그대로 남는 정책을 정하고 확인한다. 산술 교환으로 불필요한 signed 넘침을 만들지 않는다.

## 도전 문제

try_add_one의 정상·NULL·INT_MAX 실패 상태와 값 보존을 구현한다. 입력 포인터가 NULL이 아니라면 살아 있는 수정 가능한 int라는 전제를 명시한다.

## Mini Project

0~100 점수를 가리키는 포인터와 변화량을 받아 갱신한다. NULL·잘못된 현재 점수·범위 밖 결과를 쓰기 전에 거부하고, 성공 시에만 점수를 바꾼다.

예상: 70에 15를 요청하면 성공·85, 95에 10을 요청하면 실패·95 유지. 덧셈 전에 변화량을 -score~100-score와 비교한다. 이는 기존 구조체 학생 점수 실습으로 이어지는 독립 연습이며 새 채점 문제를 등록하지 않는다.

## 테스트와 풀이 개선

A/B/C를 각각 gcc -std=c11 -Wall -Wextra -Werror -Wpedantic으로 컴파일한다. 주소 문자열은 고정하지 않고 대상 값·상태·보존을 검사한다.

B는 기존 다섯 GCC 사례와 작은 추가 유효 입력, 표현 가능한 범위 밖·abc·즉시 EOF의 간단한 실패를 확인한다. 포인터만 이동과 두 번 증가 오답을 실제 API에서 거부한다. 기존 채점 사례·입력 계약은 바꾸지 않는다.

C의 테스트는 NULL과 유효한 INT_MAX 객체에 한정한다. 임의 잘못된 포인터·수명 종료 객체를 실행해 안전성을 증명하려 하지 않는다. 유한 테스트나 시간 제한은 메모리 안전 증명/공개 실행 격리가 아니다.

## 복습 연결

함수 설계 단원에서 선언·정의·값 전달·지역 범위를 정리한다. 기존 배열 최대 함수의 출력 포인터와 실패 보존, 문자열의 종료/용량, 구조체 포인터의 레코드 보존으로 이어 간다.

동적 메모리는 소유권·해제·별칭 무효화와 이중 포인터를 추가한다. 초기 포인터 실습과 다른 계약을 단계적으로 배운다.
