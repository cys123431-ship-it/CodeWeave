# 배열 함수 설계: 최댓값과 출력 포인터

> 이 원고와 예제, 문제는 CodeWeave를 위해 새로 작성했다. 상용 교재의 본문·그림·연습문제를 복제하지 않는다.

## 단원 개요

배열에서 최댓값을 찾는 계산은 단순해 보이지만 함수 인터페이스를 설계하려면 네 가지 질문에 답해야 한다. 배열은 어디서 끝나는가? 빈 배열은 어떻게 표현하는가? 모든 `int` 값이 정상 결과가 될 수 있는데 실패를 어떤 값으로 알리는가? 실패했을 때 출력 객체를 바꾸어도 되는가?

이 단원에서는 다음 계약을 구현한다.

```c
int find_max(const int values[], size_t length, int *out_max);
```

성공하면 `1`을 반환하고 `*out_max`에 최댓값을 기록한다. `values == NULL`, `length == 0`, `out_max == NULL` 중 하나라도 참이면 실패 `0`을 반환하며, 실패할 때 유효한 `out_max`의 기존 값은 변경하지 않는다.

## 선수 지식

- 배열의 유효 인덱스가 `0`부터 `length - 1`까지라는 사실
- 함수 선언·정의·호출과 반환값
- `&` 주소 연산자와 `*` 역참조
- `NULL` 포인터를 역참조하면 안 된다는 규칙
- `size_t`가 객체 크기와 원소 수를 표현하는 부호 없는 정수형이라는 사실

## 학습 목표

학습을 마치면 다음을 할 수 있어야 한다.

1. 배열 매개변수가 원소 개수를 보존하지 않는 이유를 설명한다.
2. 상태 반환값과 출력 포인터의 역할을 나누어 설계한다.
3. 입력 검증을 역참조보다 먼저 수행한다.
4. 모든 원소가 음수인 배열에서도 올바른 최댓값을 찾는다.
5. 실패 시 출력 객체를 보존하는 계약을 테스트한다.

## 핵심 이론 1 — 배열 매개변수에는 길이가 없다

함수 매개변수 위치의 `const int values[]`는 `const int *values`로 조정된다. 함수가 받는 것은 첫 원소를 가리키는 포인터 값이며 배열 전체의 크기 정보가 아니다. 따라서 호출자는 유효한 원소 수를 `length`로 함께 전달해야 한다.

`const`는 `values[i]`를 읽기만 한다는 인터페이스 약속이다. 포인터 자체가 항상 유효하다는 뜻도, 배열 경계를 자동 검사한다는 뜻도 아니다.

## 핵심 이론 2 — 결과와 성공 여부를 분리한다

최댓값은 `INT_MIN`부터 `INT_MAX`까지 어느 값이든 될 수 있다. `-1`, `0`, `INT_MIN` 같은 숫자를 실패 표식으로 예약하면 그 값이 실제 최댓값인 배열과 구분할 수 없다.

그래서 반환값은 성공 여부, `*out_max`는 계산 결과로 역할을 나눈다.

| 상황 | 반환값 | `*out_max` |
| --- | ---: | --- |
| 유효한 비어 있지 않은 배열 | `1` | 최댓값으로 변경 |
| `values == NULL` | `0` | 변경하지 않음 |
| `length == 0` | `0` | 변경하지 않음 |
| `out_max == NULL` | `0` | 접근하지 않음 |

## 핵심 이론 3 — 검증한 뒤에만 역참조한다

아래 순서가 중요하다.

1. `values`, `length`, `out_max`를 검사한다.
2. 유효하면 `values[0]`으로 현재 최댓값을 초기화한다.
3. 두 번째 원소부터 마지막 원소까지 비교한다.
4. 반복이 끝난 뒤에만 `*out_max`에 기록한다.
5. 성공 `1`을 반환한다.

실패 전에 `*out_max = 0;`을 실행하면 포인터가 `NULL`일 때는 잘못된 역참조가 되고, 유효하더라도 “실패 시 기존 값을 보존한다”는 계약을 위반한다.

## 단계별 예제

```c
#include <stddef.h>

int find_max(const int values[], size_t length, int *out_max) {
    if (values == NULL || length == 0 || out_max == NULL) {
        return 0;
    }

    int maximum = values[0];
    for (size_t i = 1; i < length; ++i) {
        if (values[i] > maximum) {
            maximum = values[i];
        }
    }

    *out_max = maximum;
    return 1;
}
```

`maximum`을 `0`으로 시작하지 않는 이유가 중요하다. `{-7, -3, -12}`에서 0은 배열에 없으므로 답이 될 수 없다. 첫 원소 `-7`로 시작하면 `-3`에서 갱신되고 결과는 올바른 `-3`이 된다.

## 완성 예제와 실행 결과

다음 프로그램은 함수의 사용 방법을 보여 주는 완성 프로그램이다. 실제 CodeWeave 실습에는 `main`을 제출하지 않는다. 서버의 별도 하네스가 같은 방식으로 함수를 호출한다.

```c
#include <stddef.h>
#include <stdio.h>

int find_max(const int values[], size_t length, int *out_max);

int find_max(const int values[], size_t length, int *out_max) {
    if (values == NULL || length == 0 || out_max == NULL) {
        return 0;
    }
    int maximum = values[0];
    for (size_t i = 1; i < length; ++i) {
        if (values[i] > maximum) maximum = values[i];
    }
    *out_max = maximum;
    return 1;
}

int main(void) {
    const int values[] = {4, -2, 9, 1};
    int result = 0;
    int status = find_max(values, 4, &result);
    printf("%d %d\n", status, result);
    return 0;
}
```

실행 결과:

```text
1 9
```

상태 `1`은 계산 성공, `9`는 출력 포인터를 통해 받은 최댓값이다.

## 경계값과 `INT_MIN`

`{INT_MIN, 0, INT_MAX}`처럼 표현 범위의 끝값을 포함해도 비교만 사용하므로 덧셈 오버플로를 만들지 않는다. `{-42}`처럼 원소가 하나뿐인 배열에서는 반복 본문이 한 번도 실행되지 않고 첫 원소가 그대로 결과가 된다.

반대로 `length == 0`에서 `values[0]`을 읽는 것은 허용되지 않는다. `size_t`는 부호 없는 형식이므로 검증 전에 `length - 1`을 계산하면 0에서 매우 큰 값으로 감길 수 있다. 반복 조건은 검증 후 `i < length`로 작성한다.

## 흔한 오류

- `maximum = 0`으로 시작해 모든 원소가 음수인 배열을 틀린다.
- `values[0]`을 읽은 뒤 `length == 0`을 검사한다.
- `*out_max = 0`을 먼저 실행해 실패 시 값을 바꾼다.
- `out_max == NULL` 검사를 빠뜨리고 역참조한다.
- `i <= length`로 반복해 배열 경계를 한 칸 넘는다.
- 함수 안에 디버그 `printf`를 남겨 하네스 출력 비교를 실패시킨다.
- 제출 코드에 `main`을 넣어 하네스의 `main`과 링크 충돌을 만든다.

## 중간 점검

1. 배열 매개변수만 보고 원소 수를 알 수 없는 이유는 무엇인가?
2. 최댓값 함수에서 `INT_MIN`을 실패 표식으로 사용하면 왜 모호한가?
3. `out_max == NULL`일 때 가장 먼저 해야 하는 일은 무엇인가?
4. 길이 0 실패 후 호출자가 미리 저장한 `out` 값은 어떻게 되어야 하는가?
5. `{-7, -3, -12}`에서 첫 원소 초기화가 만드는 반복 불변식은 무엇인가?

## 핵심 요약

- 배열 포인터와 길이는 함께 전달한다.
- 반환값은 성공 여부, 출력 포인터는 계산 결과를 담당한다.
- 모든 검증을 마친 뒤에만 포인터를 역참조한다.
- 최댓값 초기값은 0이 아니라 첫 원소로 잡는다.
- 실패한 함수는 계약에 없는 출력 부작용을 남기지 않는다.

## 기초 코딩 연습

`find_max`를 구현하고 `{4, -2, 9, 1}`, `{-7, -3, -12}`, `{-42}`를 검사한다. 제출에는 `main`과 출력 코드를 넣지 않는다.

## 응용 연습

같은 계약 형태로 `find_min`을 설계한다. 함수 이름만 바꾸지 말고 성공/실패 조건, 출력 객체 보존, 한 원소 배열과 `INT_MIN`·`INT_MAX` 사례를 표로 먼저 작성한다.

## 도전 문제

최솟값과 최댓값을 동시에 구하는 다음 계약을 설계한다.

```c
int find_range(const int values[], size_t length, int *out_min, int *out_max);
```

두 출력 포인터가 같은 객체를 가리키는 경우를 허용할지 금지할지 결정하고, 그 결정이 모호하지 않도록 전제조건과 테스트를 작성한다.

## 테스트와 풀이 개선

CodeWeave 하네스는 정상 배열, 모든 원소가 음수인 배열, 중복 최댓값, `INT_MIN`/`INT_MAX`, 한 원소 배열, `NULL`, 길이 0, `NULL` 출력 포인터를 검사한다. 반환값뿐 아니라 실패 후 sentinel 값이 보존되는지와 불필요한 표준 출력이 없는지도 확인한다. 실패한 사례의 계약을 읽고 함수 본문만 수정해 새 iteration으로 제출한다.

## 복습 연결

이 단원의 “포인터 + 길이 + 상태 + 출력 객체” 계약은 문자열 검색, 배열 변환, 연결 리스트 조회, 파일 처리 함수로 확장된다. Rust에서는 유효한 결과와 실패를 `Option`이나 `Result` 같은 타입으로 표현하는 방식을 비교할 수 있다. 다음 C 단원에서는 헤더와 여러 소스 파일로 같은 계약을 공유한다.
