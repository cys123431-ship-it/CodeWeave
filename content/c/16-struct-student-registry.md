# 학생 명부 Mini Project: 안정 정렬과 첫 학번 탐색

> 이 원고와 예제, 도식, 문제는 CodeWeave용으로 새로 작성했다. 특정 상용 교재의 본문·그림·문제를 옮기지 않았다.

## 단원 개요

함수 하나를 정확히 작성하는 일과 여러 함수를 하나의 프로그램으로 조립하는 일은 서로 다른 연습이다. 이 프로젝트에서는 학생 레코드를 입력받아 학번순으로 안정 정렬한 다음, 주어진 학번의 첫 레코드를 이진 탐색한다.

프로그램은 다음 세 파일로 나눈다.

- `student.h`: `struct Student`와 함수 원형이라는 공개 계약
- `student.c`: 안정 삽입 정렬과 첫 위치 이진 탐색의 정의
- `main.c`: 입력, 호출 순서, 출력

각 `.c` 파일은 별도의 번역 단위로 컴파일되고 링크 단계에서 하나의 실행 프로그램이 된다. 이 프로젝트의 핵심은 단순히 정답을 출력하는 것이 아니라, 알고리즘의 전제와 파일 사이 계약을 코드 구조로 드러내는 데 있다.

## 필요한 이유

현실의 프로그램은 대개 한 파일에 모든 코드를 넣지 않는다. 자료형과 연산을 하나의 모듈로 묶으면 호출자는 구현 세부 사항보다 계약에 집중할 수 있다. 또한 정렬과 탐색을 연결하면 “이진 탐색에는 정렬이 필요하다”는 문장을 실제 실행 순서로 검증할 수 있다.

출력에는 정렬된 모든 레코드와 탐색 결과를 함께 표시한다. 이 때문에 다음 두 속성을 눈으로 확인할 수 있다.

1. 같은 학번의 점수 순서가 유지되는가? — 안정 정렬
2. 중복 학번 그룹의 첫 인덱스를 선택하는가? — 하한 이진 탐색

## 선수 지식

- 구조체 정의와 구조체 배열
- 배열의 유효 범위 `[0, count)`
- `size_t`와 `<stddef.h>`
- 안정 삽입 정렬
- 정렬된 배열의 `[left, right)` 하한 이진 탐색
- 헤더, 함수 원형, 분할 컴파일과 링크

## 학습 목표

학습 후에는 다음을 할 수 있어야 한다.

1. 선언, 정의, 호출을 각각 알맞은 파일에 둔다.
2. 구조체 전체를 이동하여 `id`와 `score`의 결합을 보존한다.
3. 동등한 `id`의 상대 순서를 유지한다.
4. 정렬을 마친 뒤에만 이진 탐색을 호출한다.
5. 중복된 `id`의 첫 위치를 찾는다.
6. 빈 배열, 미발견, 잘못된 입력, 컴파일 오류와 링크 오류를 구별한다.

## 핵심 이론

### 1. 헤더는 스스로 완전해야 한다

`student.h`는 `size_t`를 함수 원형에 사용한다. 그러므로 다른 파일이 먼저 우연히 `<stddef.h>`를 포함해 주기를 기대하지 말고, 헤더가 직접 필요한 선언을 포함해야 한다.

```c
#ifndef STUDENT_H
#define STUDENT_H

#include <stddef.h>

struct Student {
    int id;
    int score;
};

int stable_sort_students_by_id(struct Student students[], size_t count);
int find_first_student_by_id(const struct Student students[], size_t count,
                             int target_id, size_t *out_index);

#endif
```

이 헤더를 `main.c`와 `student.c`가 함께 포함하면 호출부와 정의부가 같은 계약을 본다. `.c` 파일을 다른 `.c` 파일에서 직접 `#include`하지 않는다.

### 2. 안정 삽입 정렬은 레코드 전체를 이동한다

정렬 키는 `id`지만 `score`도 같은 학생에 속한다. 따라서 `id`만 교환하면 데이터의 의미가 깨진다. C의 구조체 대입을 사용해 레코드 전체를 이동한다.

```c
struct Student key = students[i];
students[j] = students[j - 1];
students[j] = key;
```

같은 id의 상대 순서를 보존하려면 이전 학번이 더 클 때만 이동한다.

```c
students[j - 1].id > key.id
```

`>=`를 사용하면 같은 `id`도 서로 넘어가므로 안정성이 사라진다. 또한 `students[j - 1].id - key.id`의 부호로 비교하면 `int` 범위를 넘는 뺄셈이 정의되지 않은 동작이 될 수 있다. 관계 연산자로 직접 비교한다.

### 3. 이진 탐색은 정렬 전제가 필요하다

이진 탐색은 가운데 값과 목표값의 관계로 후보 절반을 버린다. 배열이 정렬되지 않았다면 어느 절반을 버려도 되는지 근거가 없다. 이 프로그램은 다음 순서를 지켜 전제를 보장한다.

1. 모든 레코드를 읽는다.
2. `stable_sort_students_by_id`를 호출한다.
3. 정렬 결과를 출력한다.
4. `find_first_student_by_id`를 호출한다.

### 4. 첫 일치는 하한으로 찾는다

후보 구간을 `[left, right)`로 둔다. `students[mid].id`가 목표보다 작으면 `mid`까지 버리고, 같거나 크면 `mid`를 포함한 왼쪽을 계속 살핀다.

```c
while (left < right) {
    size_t mid = left + (right - left) / 2;
    if (students[mid].id < target_id) {
        left = mid + 1;
    } else {
        right = mid;
    }
}
```

반복이 끝난 뒤 `left < count`와 실제 동등성을 모두 확인한다. 목표가 없을 때 `left`는 더 큰 첫 값이나 `count`를 가리킬 수 있기 때문이다. `out_index`는 성공이 확정된 뒤에만 기록한다.

### 5. 비용을 합쳐서 읽는다

레코드 수를 `n`이라 하면 이 프로젝트의 작은 배열용 삽입 정렬은 최악 `O(n²)`, 첫 위치 이진 탐색은 `O(log n)`이다. 전체 실행 시간은 더 큰 항인 `O(n²)`가 지배한다. 이미 정렬된 입력에서는 삽입 정렬의 비교 수가 선형에 가깝지만, 이것이 모든 입력에서 선형이라는 뜻은 아니다.


## 단계별 예제

### 1단계: 입력 계약

첫 줄은 `count target_id`, 다음 `count`줄은 `id score`다. 이 프로젝트는 고정 배열을 사용하므로 `count`를 0 이상 16 이하로 제한한다.

```text
4 205
309 95
205 88
101 70
205 91
```

### 2단계: 안정 정렬

입력 레코드의 순서는 다음과 같다.

```text
309:95 205:88 101:70 205:91
```

정렬 결과는 다음과 같다.

```text
101:70 205:88 205:91 309:95
```

두 `205` 레코드에서 `88`점이 `91`점보다 먼저였고, 정렬 후에도 그 상대 순서가 유지된다.

### 3단계: 첫 위치 탐색

정렬된 배열에서 `205`의 하한은 인덱스 1이다. 해당 레코드의 점수는 88이다. 일치를 처음 만난 중간 인덱스에서 바로 반환하지 않고, 같은 값의 더 왼쪽 가능성을 계속 검사해야 한다.

### 4단계: 빈 배열

입력이 `0 42`이면 읽을 레코드가 없다. 정렬 함수는 빈 범위를 성공으로 처리할 수 있고, 검색 함수는 미발견을 반환한다. 어떤 배열 원소에도 접근하면 안 된다.

## 완성 프로그램

### student.c

```c
#include "student.h"

int stable_sort_students_by_id(struct Student students[], size_t count) {
    if (count == 0) return 1;
    if (students == NULL) return 0;

    for (size_t i = 1; i < count; ++i) {
        struct Student key = students[i];
        size_t j = i;
        while (j > 0 && students[j - 1].id > key.id) {
            students[j] = students[j - 1];
            --j;
        }
        students[j] = key;
    }
    return 1;
}

int find_first_student_by_id(const struct Student students[], size_t count,
                             int target_id, size_t *out_index) {
    if (count == 0 || students == NULL || out_index == NULL) return 0;

    size_t left = 0;
    size_t right = count;
    while (left < right) {
        size_t mid = left + (right - left) / 2;
        if (students[mid].id < target_id) left = mid + 1;
        else right = mid;
    }

    if (left < count && students[left].id == target_id) {
        *out_index = left;
        return 1;
    }
    return 0;
}
```

`student.h`와 `main.c`의 완성 형태는 화면의 스타터 코드에 제공된다. 학습자는 우선 `student.c`의 두 알고리즘을 완성하고, 이어 파일 경계와 입출력 검사를 검토한다.

## 실행 결과

앞의 예제 입력에 대한 실제 출력은 다음과 같다.

```text
101:70 205:88 205:91 309:95
FOUND 1 88
```

`target_id`가 250이고 정렬된 명부에 없다면 둘째 줄은 다음과 같다.

```text
NOT FOUND
```

빈 배열이면 다음과 같다.

```text
EMPTY
NOT FOUND
```

## 흔한 오류

### 오류 1: id만 이동한다

학번과 점수가 다른 학생끼리 섞인다. `struct Student` 전체를 임시 객체에 저장하고 이동한다.

### 오류 2: 같은 키에도 이동한다

조건을 `>=`로 쓰면 같은 학번의 원래 상대 순서가 뒤집힐 수 있다. 안정성 계약에는 엄격한 `>`가 필요하다.

### 오류 3: 정렬 전에 찾는다

정렬되지 않은 배열의 이진 탐색 결과는 보장되지 않는다. 호출 순서를 고친다.

### 오류 4: 일치하자마자 반환한다

중복 그룹의 가운데를 반환할 수 있다. 같은 경우 `right = mid`로 왼쪽 후보를 남긴다.

### 오류 5: 정의를 헤더에 중복해서 둔다

일반 외부 연결 함수를 헤더에 정의하고 여러 번역 단위에서 포함하면 다중 정의 링크 오류가 생길 수 있다. 이 프로젝트에서는 헤더에 원형, `student.c`에 정의를 둔다.

### 오류 6: 선언만 있고 정의가 없다

`main.c`는 원형을 보고 컴파일될 수 있지만 링크할 실제 함수가 없어 `undefined reference`가 발생한다. 컴파일 단계와 링크 단계를 구분해서 읽는다.

### 오류 7: 특정 int 폭을 C의 보장으로 말한다

C는 `int`가 정확히 32비트라고 보장하지 않는다. 자동 검사의 `-2147483648`과 `2147483647` 사례는 현재 GCC 실행 환경의 경계를 확인하는 사례이며, 이식 가능한 설명에서는 `<limits.h>`의 `INT_MIN`, `INT_MAX`를 기준으로 말해야 한다.

## 퀴즈

같은 `id`의 레코드가 여러 개일 때 `FOUND`가 가리켜야 하는 것은 무엇인가?

1. 안정 정렬 뒤 같은 `id` 중 첫 레코드
2. 점수가 가장 높은 레코드
3. 이진 탐색이 우연히 처음 만난 레코드
4. 입력의 마지막 레코드

정답은 1번이다. 안정 정렬은 동등 키 순서를 보존하고 하한 이진 탐색은 그룹 첫 위치를 찾는다.

## 도전 문제

학번 그룹의 범위 `[first, last)`를 찾는 두 하한 검색을 설계한다. 첫 번째 하한은 `id >= target`, 두 번째 하한은 `id > target`인 첫 위치다. 두 인덱스의 차이는 해당 학번의 레코드 수가 된다. 출력 포인터의 유효성과 실패 시 보존 정책도 먼저 정한다.

## Mini Project

이번 화면의 자동 채점 과제를 완성한다.

- 파일명: `main.c`, `student.c`, `student.h`
- 최대 학생 수: 16
- 정상 출력 1행: 정렬된 `id:score` 목록 또는 `EMPTY`
- 정상 출력 2행: `FOUND index score` 또는 `NOT FOUND`

자동 검사는 정렬 전/후, 중복, 모든 키 동일, 미발견, 한 원소, 빈 입력, 현재 GCC 환경의 정수 경계, 잘못된 개수, 불완전한 입력을 포함한다. 또한 세 필수 파일 누락과 링크 실패도 별도로 검사한다.

테스트 통과는 주어진 사례에서 관찰된 결과다. 임의의 모든 입력에 대한 정확성이나 공개 서버에서의 안전한 코드 실행을 뜻하지 않는다. 로컬 채점 서버는 신뢰하는 개인 코드용이며 샌드박스가 아니다.

- 구조체 배열 선형 탐색: 정렬 전에도 가능한 기준선
- 구조체 배열 안정 정렬: 동등 키 상대 순서와 레코드 이동
- 첫 위치 이진 탐색: 정렬 전제와 하한
- 분할 컴파일: 헤더, 번역 단위, 링크
- 다음 단계: 동적 메모리로 명부 크기 확장, 파일 저장 형식, 비교 함수, Make/CMake 같은 빌드 자동화
