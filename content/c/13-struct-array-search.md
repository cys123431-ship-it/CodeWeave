# 구조체 배열에서 학번 찾기

이 원고는 CodeWeave를 위해 독자적으로 작성한 학습 자료다. 상용 교재의 문장·그림·연습문제를 옮기지 않았다.

## 단원 개요

한 학생의 학번과 점수를 `struct Student`에 묶었다면 여러 학생은 그 구조체의 배열로 표현할 수 있다. 이번 단원에서는 배열에서 목표 학번을 찾고 그 위치를 호출자에게 돌려주는 함수를 만든다. 단순한 반복문처럼 보이지만 실제로는 배열 경계, 구조체 멤버 접근, `const`, 출력 포인터, 중복 데이터 정책과 실패 상태 보존이 함께 들어 있는 작은 API 설계 문제다.

## 선수 지식

- 배열의 인덱스와 `[0, count)` 범위
- `size_t`와 함수 매개변수
- 구조체 객체의 점(`.`) 멤버 접근
- 성공 여부를 반환값으로, 결과를 출력 포인터로 돌려주는 함수 계약
- `NULL` 포인터를 역참조하면 안 된다는 규칙

## 학습 목표

학습을 마치면 다음을 할 수 있어야 한다.

1. `struct Student` 배열의 각 원소와 멤버를 구분한다.
2. 배열 매개변수가 포인터로 조정되므로 원소 수를 별도로 받아야 하는 이유를 설명한다.
3. `students[i].id`를 사용해 범위 안에서 선형 탐색한다.
4. 중복 학번에서는 첫 번째 일치 위치를 선택한다.
5. 성공한 경우에만 출력 객체를 변경하고 모든 실패에서 원래 값을 보존한다.
6. 선형 탐색의 시간 복잡도 `O(n)`과 추가 공간 `O(1)`을 설명한다.

## 핵심 이론

### 구조체 배열은 구조체 객체의 연속된 배열이다

```c
struct Student {
    int id;
    int score;
};

struct Student students[] = {
    {.id = 101, .score = 70},
    {.id = 205, .score = 88},
    {.id = 309, .score = 95}
};
```

`students[0]`, `students[1]`, `students[2]`는 각각 완전한 `struct Student` 객체다. 배열 원소는 연속해서 놓이며 다음 원소의 시작 위치는 `sizeof(struct Student)`만큼 떨어져 있다. 구조체 내부에는 정렬을 위한 패딩이 있을 수 있으므로 이 크기를 단순히 두 `int` 크기의 합이라고 가정하지 않는다. C의 배열 인덱싱이 실제 객체 크기를 반영하므로 직접 바이트 수를 계산할 필요도 없다.

현재 원소가 구조체 객체이므로 점 연산자를 쓴다.

```c
if (students[i].id == target_id) {
    /* i번째 학생의 학번이 목표와 같다. */
}
```

`students->id`는 `(*students).id`와 같아 첫 원소의 학번만 가리킨다. 반복문의 모든 원소를 검색하려면 반드시 현재 인덱스를 반영한 `students[i].id`를 읽어야 한다.

### 배열 매개변수에는 전체 길이가 따라오지 않는다

다음 두 함수 매개변수 선언은 함수 형식에서 같은 의미다.

```c
const struct Student students[]
const struct Student *students
```

배열 매개변수는 포인터로 조정된다. 그러므로 함수 안의 `sizeof students`는 호출자가 선언한 배열 전체 크기가 아니라 포인터 자체의 크기다. `sizeof students / sizeof students[0]`로 원소 수를 계산하면 잘못된 결과를 낸다. 호출자가 실제 원소 수 `count`를 별도로 전달해야 한다.

`const`는 검색 함수가 배열 원소를 바꾸지 않는다는 의도를 자료형에 담는다. 그러나 포인터가 실제로 `count`개의 유효한 객체를 가리키는지는 함수가 알아낼 수 없다. 그 부분은 호출자가 지켜야 하는 계약이다.

### `[0, count)`로 경계를 표현한다

유효한 인덱스는 0부터 `count - 1`까지다. 반열린 구간으로는 `[0, count)`라고 쓴다.

```c
for (size_t i = 0; i < count; ++i) {
    /* students[i]는 계약이 지켜졌다면 유효하다. */
}
```

`i <= count`는 마지막에 `students[count]`를 읽어 배열 밖으로 나간다. `i < count - 1`은 마지막 원소를 빼먹을 뿐 아니라 `count == 0`일 때 unsigned 연산인 `count - 1`이 매우 큰 값으로 감길 수 있다. `i < count`가 빈 배열도 자연스럽게 0회 반복하는 표현이다.

### 첫 번째 일치를 함수 계약으로 정한다

학번이 고유해야 한다는 데이터 정책과 함수가 실제 중복 입력에서 무엇을 할지는 별개의 문제다. 이 실습에서는 중복 학번이 있으면 가장 작은 인덱스를 반환한다. 일치한 순간 출력하고 곧바로 성공을 반환하면 이 정책이 자연스럽게 지켜진다.

```c
if (students[i].id == target_id) {
    *out_index = i;
    return 1;
}
```

끝까지 계속 순회하면서 `*out_index = i`를 반복하면 마지막 일치 위치가 남는다. 그것도 가능한 정책이지만 이번 계약과는 다르다. 이름이나 문서 없이 두 정책을 섞으면 호출자가 결과를 예측할 수 없다.

### 실패에서는 출력 객체를 건드리지 않는다

함수는 성공 여부를 `int`로, 실제 인덱스를 `size_t *out_index`로 전달한다.

- 성공: 첫 일치 인덱스를 기록하고 `1` 반환
- 미발견: 출력 객체를 보존하고 `0` 반환
- `students == NULL`: 출력 객체를 보존하고 `0` 반환
- `count == 0`: 출력 객체를 보존하고 `0` 반환
- `out_index == NULL`: 기록할 곳이 없으므로 `0` 반환

함수 시작에서 `*out_index = 0`처럼 기본값을 쓰면 미발견과 잘못된 입력에서 호출자의 기존 값을 파괴한다. 출력은 성공이 확정된 분기에서만 한 번 기록한다.

## 단계별 예제

먼저 잘못된 포인터와 빈 범위를 거부한다. `out_index`를 역참조하기 전에 반드시 `NULL`인지 확인한다.

```c
if (students == NULL || count == 0 || out_index == NULL) {
    return 0;
}
```

다음으로 모든 유효 인덱스를 차례로 검사한다.

```c
for (size_t i = 0; i < count; ++i) {
    if (students[i].id == target_id) {
        *out_index = i;
        return 1;
    }
}
return 0;
```

완성 함수는 다음과 같다.

```c
int find_student_index(const struct Student students[], size_t count,
                       int target_id, size_t *out_index) {
    if (students == NULL || count == 0 || out_index == NULL) {
        return 0;
    }

    for (size_t i = 0; i < count; ++i) {
        if (students[i].id == target_id) {
            *out_index = i;
            return 1;
        }
    }
    return 0;
}
```

아래는 동작을 확인할 수 있는 완성 프로그램이다. 학습 과제에서는 서버가 `main`을 제공하므로 함수와 구조체 정의만 제출한다.

```c
#include <stddef.h>
#include <stdio.h>

struct Student {
    int id;
    int score;
};

int find_student_index(const struct Student students[], size_t count,
                       int target_id, size_t *out_index) {
    if (students == NULL || count == 0 || out_index == NULL) return 0;
    for (size_t i = 0; i < count; ++i) {
        if (students[i].id == target_id) {
            *out_index = i;
            return 1;
        }
    }
    return 0;
}

int main(void) {
    const struct Student students[] = {
        {101, 70}, {205, 88}, {309, 95}
    };
    size_t index = 77;

    int found = find_student_index(students, 3, 205, &index);
    printf("%d %zu\n", found, index);

    index = 77;
    found = find_student_index(students, 3, 999, &index);
    printf("%d %zu\n", found, index);
    return 0;
}
```

## 실행 결과

```text
1 1
0 77
```

첫 호출은 인덱스 1의 학번 205를 찾는다. 두 번째 호출은 999를 찾지 못하므로 상태 0을 반환하며 출력 객체의 기존 값 77을 보존한다. 77은 유효한 결과를 뜻하는 특별한 값이 아니라 실패 시 쓰기가 있었는지 드러내는 시험용 감시값이다.

## 흔한 오류

1. `sizeof students / sizeof students[0]`를 함수 안에서 사용한다. `students`는 이미 포인터이므로 배열 길이를 얻지 못한다.
2. 반복문에서 `students->id`만 비교한다. 항상 첫 원소만 읽는다.
3. 인덱스 1부터 시작한다. 목표가 첫 원소에 있을 때 실패한다.
4. `i <= count`를 쓴다. 마지막 반복에서 범위 밖 객체를 읽는다.
5. 실패 전에 `*out_index = 0`을 쓴다. 출력 보존 계약을 어긴다.
6. 중복을 끝까지 검색한다. 이번 문제의 첫 번째 일치 정책 대신 마지막 위치를 반환한다.
7. `score`의 범위를 검색 성공 조건에 섞는다. 이 함수의 키는 `id`이며 점수 유효성 검사는 별도의 책임이다.

구조체의 의미 있는 필드를 비교할 때 원시 바이트 전체에 `memcmp`를 쓰는 것도 피한다. 패딩 바이트의 값은 멤버의 논리적 동일성과 관계없을 수 있다. 이번 검색에서는 명시적으로 `id`만 비교한다.

## 중간 점검

1. 배열 매개변수 안에서 `sizeof students`가 전체 배열 크기가 아닌 이유는 무엇인가?
2. `count == 0`일 때 반복문 본문이 한 번도 실행되지 않아야 하는 이유는 무엇인가?
3. `students[i].id`와 `students->id`는 어떻게 다른가?
4. 중복 학번의 첫 번째 위치를 보장하는 문장은 무엇인가?
5. 미발견일 때 출력 객체를 유지하면 호출자에게 어떤 이점이 있는가?

## 핵심 요약

- 구조체 배열의 각 원소는 완전한 구조체 객체다.
- 배열 매개변수는 포인터로 조정되므로 원소 수를 별도로 전달한다.
- 유효한 검색 범위는 `[0, count)`다.
- 현재 원소의 학번은 `students[i].id`로 읽는다.
- 첫 일치에서 즉시 반환하면 중복에서도 가장 작은 인덱스를 얻는다.
- 성공할 때만 출력 포인터에 기록하면 모든 실패에서 기존 값을 보존할 수 있다.
- 선형 탐색은 최악 `O(n)` 시간과 `O(1)` 추가 공간을 사용한다.

## 기초 코딩 연습

학생 배열에서 점수가 정확히 `target_score`인 첫 학생의 인덱스를 찾는 함수를 작성한다. 빈 배열과 미발견에서 출력 값을 보존하고, 첫 원소와 마지막 원소가 일치하는 사례를 각각 시험한다.

## 응용 연습

`find_student_index`를 호출해 학번을 찾은 뒤, 성공한 경우에만 해당 학생의 점수를 출력하는 호출자 코드를 작성한다. 검색 함수는 출력하지 않고 호출자가 사용자 인터페이스를 담당하도록 책임을 나눈다.

## 도전 문제

학번이 오름차순으로 정렬되었다는 전제조건을 명시하고 이진 탐색 버전을 작성한다. 중복 학번이 있을 때도 첫 번째 위치를 반환하려면 일치를 찾은 뒤 왼쪽 구간을 계속 탐색해야 한다. 전제조건이 깨진 배열에서 올바른 결과를 보장한다고 주장해서는 안 된다.

## Mini Project

고정 크기 학생 명부를 만든다. 사용자가 학번을 입력하면 선형 탐색으로 위치를 찾고, 존재하면 학생 정보를 표시하며, 없으면 추가 가능한 빈 슬롯을 안내한다. 검색·표시·추가 함수를 분리하고 각 함수의 배열 길이와 실패 보존 계약을 문서화한다. 이후 파일 입출력을 배울 때 명부 저장과 불러오기를 연결할 수 있다.

## 테스트와 풀이 개선

정상 중간 위치만 시험하면 경계 오류를 놓친다. 최소한 첫 원소, 마지막 원소, 한 원소 배열, 미발견, 중복의 첫 일치, `students == NULL`, `count == 0`, `out_index == NULL`을 구분한다. `int` 학번에는 음수도 표현 가능하므로 함수가 임의로 양수 정책을 추가하지 않는지 `INT_MIN` 같은 값으로 확인할 수 있다. 출력 전용 디버그 문장은 하네스의 예상 출력과 섞이므로 제출 코드에서 제거한다. 무한 반복은 시간 제한으로 실패하지만 이 제한은 메모리·파일·네트워크 격리가 아니다.

## 복습 연결

이번 단원은 배열 함수의 길이 계약, 구조체 멤버 접근, 출력 포인터의 실패 보존을 결합했다. 다음에는 정렬 전제조건을 가진 이진 탐색, 키 비교 함수를 받는 일반 검색, 동적으로 커지는 구조체 배열로 확장할 수 있다. 연결 리스트에서는 인덱스 대신 노드 포인터를 결과로 돌려주며, 포인터의 수명과 소유권을 추가로 검토해야 한다.
