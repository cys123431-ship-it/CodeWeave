# C 문자열 함수: 널 종료와 문자 세기

> 이 원고와 예제·연습은 CodeWeave를 위해 독자 작성했다. 상용 교재 본문이나 그림·문제를 복제하지 않는다.

## 단원 개요

C에는 길이를 스스로 기억하는 내장 문자열 객체가 없다. C 문자열은 **읽을 수 있는 문자 배열 안에 값 0인 종료 문자 `\0`이 있는 표현 규약**이다. 이번 단원에서는 이 규약이 왜 필요한지 살펴보고, 첫 종료 문자 전까지 특정 문자의 개수를 세는 `count_char` 함수를 구현한다.

## 선수 지식

- 배열의 인덱스 범위와 범위를 벗어난 접근의 위험
- 포인터, `NULL`, 역참조
- 함수 선언·정의·호출
- 상태 반환값과 출력 포인터
- `size_t`가 객체 크기와 원소 개수를 표현하는 부호 없는 정수형이라는 점

## 학습 목표

학습을 마치면 다음을 할 수 있어야 한다.

1. 임의의 문자 배열과 널 종료 문자열을 구별한다.
2. `\0`과 문자 `'0'`의 차이를 설명한다.
3. `const char *`만으로 버퍼 크기를 알 수 없는 이유를 설명한다.
4. 포인터를 검증한 뒤 종료 문자 전까지만 읽는 반복문을 작성한다.
5. 실패할 때 출력 객체를 변경하지 않는 함수 계약을 구현한다.

## 핵심 이론

### 문자 배열이 문자열이 되는 조건

다음 두 선언은 겉보기에는 비슷하지만 의미가 다르다.

```c
char letters[3] = {'C', 'A', 'T'};
char word[] = "CAT";
```

`letters`에는 문자 세 개만 있다. 반면 문자열 리터럴로 초기화한 `word`에는 컴파일러가 마지막에 `\0`을 추가하므로 네 원소가 있다.

| 인덱스 | 0 | 1 | 2 | 3 |
|---|---:|---:|---:|---:|
| `word` | `'C'` | `'A'` | `'T'` | `'\0'` |

문자열 함수는 이 종료 문자를 만날 때까지 다음 원소를 읽는다. 종료 표시가 없는 `letters`를 문자열인 것처럼 넘기면 배열 바깥까지 읽을 수 있다.

### `\0`은 문자열 내용이 아니라 경계 표시다

`'\0'`은 값 0인 널 문자다. `'0'`은 화면에 보이는 숫자 문자다. 둘은 서로 다른 값이고 역할도 다르다. 저장 공간에는 종료 문자가 있지만, 문자열 길이와 이번 단원의 검색 범위는 첫 `\0` 직전까지만 포함한다. 따라서 `target == '\0'`이면 `count_char`의 결과는 0이다.

### 포인터에는 배열 길이가 들어 있지 않다

함수가 `const char *text`를 받으면 첫 문자의 주소는 알 수 있지만 몇 바이트를 읽을 수 있는지는 알 수 없다. 이 함수는 호출자가 `text`부터 첫 종료 문자까지 읽을 수 있는 올바른 C 문자열을 전달한다고 전제한다. `text == NULL`은 검사할 수 있지만, 포인터 하나만 보고 실제 버퍼 안에 종료 문자가 있는지 미리 확인할 수는 없다.

### `const`는 읽기 전용 인터페이스 약속이다

`const char *text`는 `count_char`가 `text`를 통해 원본 문자를 바꾸지 않겠다는 계약이다. 문자열 리터럴은 수정하려 해서는 안 된다. 수정 가능한 배열이 필요하면 `char word[] = "CAT";`처럼 별도 배열을 만든다. 이번 함수는 세기만 하므로 원본을 수정할 이유가 없다.

### 성공 상태와 실제 결과를 분리한다

계약은 다음과 같다.

```c
int count_char(const char *text, char target, size_t *out_count);
```

- `text`와 `out_count`가 유효하면 개수를 `*out_count`에 기록하고 1을 반환한다.
- 둘 중 하나가 `NULL`이면 0을 반환한다.
- 실패할 때 유효한 `out_count`가 있더라도 기존 값은 바꾸지 않는다.
- 첫 `\0`은 문자열 내용에 포함하지 않는다.

이 구조는 모든 `size_t` 값이 정상적인 개수가 될 수 있을 때 특정 숫자를 오류 표시로 빼앗지 않는다.

## 단계별 예제

### 1단계: 입력 계약을 먼저 검사한다

```c
if (text == NULL || out_count == NULL) {
    return 0;
}
```

검사 전에 `text[0]`이나 `*out_count`를 사용하면 널 포인터를 역참조할 수 있다.

### 2단계: 종료 문자 전까지만 센다

```c
size_t count = 0;
for (size_t i = 0; text[i] != '\0'; ++i) {
    if (text[i] == target) {
        ++count;
    }
}
```

반복 시작 시 `count`에는 이미 살펴본 `text[0]`부터 `text[i - 1]`까지의 일치 개수가 들어 있다는 불변식을 사용할 수 있다.

### 3단계: 성공한 뒤 결과를 기록한다

```c
*out_count = count;
return 1;
```

출력 객체 쓰기를 마지막에 두면 실패 경로에서 기존 값을 자연스럽게 보존한다.

### 완성 프로그램

아래는 함수 사용법까지 포함한 컴파일 가능한 전체 프로그램이다. CodeWeave 함수 실습에는 `count_char` 구현만 제출한다.

```c
#include <stddef.h>
#include <stdio.h>

int count_char(const char *text, char target, size_t *out_count) {
    if (text == NULL || out_count == NULL) return 0;

    size_t count = 0;
    for (size_t i = 0; text[i] != '\0'; ++i) {
        if (text[i] == target) ++count;
    }

    *out_count = count;
    return 1;
}

int main(void) {
    size_t count = 99;
    int status = count_char("banana", 'a', &count);
    printf("%d %zu\n", status, count);
    return 0;
}
```

## 실행 결과

```text
1 3
```

`banana`의 인덱스 1, 3, 5에서 `a`가 발견된다. 함수가 정상 입력을 받았으므로 상태 1을 반환하고 출력 객체에는 3을 기록한다.

## 흔한 오류

### 종료 문자까지 검색 대상으로 세기

`do-while`에서 현재 문자를 먼저 센 뒤 종료 여부를 확인하면 `target == '\0'`일 때 종료 표시를 한 번 센다. 이 단원의 문자열 내용은 종료 문자 전까지이므로 조건을 먼저 확인한다.

### 종료 표시가 없는 배열 전달

종료 문자를 찾기 전에 읽을 수 있는 객체가 끝나면 정의되지 않은 동작이다. 우연히 다음 메모리에서 0을 만났더라도 올바른 프로그램이 아니다.

### `sizeof(text)`로 길이 구하기

함수 매개변수의 `text`는 포인터다. `sizeof(text)`는 가리키는 문자열 길이가 아니라 포인터 객체의 크기다.

### 실패 전에 출력값 지우기

입력 검증보다 먼저 `*out_count = 0;`을 수행하면 `text == NULL`인 실패 호출에서도 호출자의 기존 값을 잃는다.

### 문자열 리터럴 수정

문자열 리터럴을 수정하려는 동작은 정의되지 않는다. 읽기만 하는 함수에는 `const char *`를 사용해 의도를 자료형에 드러낸다.

## 중간 점검

1. `char text[] = "";`의 배열 크기는 왜 1인가?
2. `'0'`과 `'\0'`은 각각 어떤 역할을 하는가?
3. `const char *`만 받은 함수가 버퍼 크기를 알 수 없는 이유는 무엇인가?
4. `count_char(NULL, 'a', &out)` 뒤 `out`은 왜 그대로여야 하는가?
5. 종료 문자가 없는 배열을 넘겼을 때 함수 내부에서 안전하게 알아낼 수 있는가?

## 핵심 요약

- C 문자열은 첫 `\0`으로 끝나는 문자 배열 표현이다.
- 종료 문자는 저장되지만 문자열 내용에는 포함하지 않는다.
- 포인터 값에는 버퍼 크기 정보가 없다.
- 입력 포인터를 검증한 뒤 읽고, 성공한 경우에만 출력 포인터에 쓴다.
- `const`는 함수를 통한 원본 변경을 금지하는 인터페이스 약속이다.

## 기초 코딩 연습

`count_char`를 구현하고 다음 사례를 직접 예측한다.

- `"banana", 'a'` → 3
- `"", 'a'` → 0
- `"AaA", 'a'` → 1
- `"abc", 'z'` → 0

## 응용 연습

`count_digits(const char *text, size_t *out_count)`를 작성해 `'0'`부터 `'9'`까지인 문자의 개수를 센다. 널 포인터와 출력 보존 계약은 동일하게 유지한다.

## 도전 문제

`count_char_n(const char *buffer, size_t capacity, char target, size_t *out_count)`를 설계한다. `capacity` 안에서 `\0`을 찾지 못하면 실패하고 출력값을 보존하도록 하라. 이 함수는 별도 길이를 받아 읽기 상한을 둘 수 있지만, `buffer`가 실제로 `capacity`바이트만큼 읽을 수 있다는 호출자 계약은 여전히 필요하다.
