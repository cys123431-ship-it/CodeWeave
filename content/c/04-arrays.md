# 배열과 함수: 원소·길이·경계를 함께 다루기

## 단원 개요

배열은 같은 형의 여러 객체를 순서대로 보관한다. 이 단원은 배열 객체·원소·0 기반 인덱스·초기화·용량·사용 길이를 구분하고, 반열린 순회 범위와 최댓값의 불변식을 함수로 연결한다.

기존 `c-array`의 전체 프로그램 실습을 유지한다. 후속 `c-array-max-function`은 함수 본문·출력 포인터·실패 보존을 다루므로 여기서 새 문제로 중복 생성하지 않는다.

## 필요한 이유

점수를 score1, score2처럼 따로 선언하면 개수가 바뀔 때 코드도 늘어난다. 배열은 인덱스로 같은 처리 규칙을 적용할 수 있게 한다.

편리함에는 책임이 따른다. C의 일반 배열 접근은 자동 경계 검사를 약속하지 않는다. **어떤 객체가 존재하는가, 어느 원소가 초기화됐는가, 이번 계산의 사용 범위는 어디인가**를 함께 설명한다.

## 선수 지식

- 변수의 선언·자료형·초기화·대입
- 조건식·for의 조건과 갱신·불변식
- scanf의 변환 개수와 printf 형식

함수의 작은 형식을 소개하지만 포인터 산술·동적 메모리·출력 포인터를 미리 구현할 필요는 없다. 주소와 역참조는 다음 단원에서 자세히 배운다.

## 학습 목표

1. 배열 객체와 각 원소를 구분한다.
2. 원소 수와 마지막 유효 인덱스를 구분한다.
3. 물리적 용량과 초기화된 사용 길이를 나눈다.
4. 초기화 규칙과 미초기화 읽기 위험을 설명한다.
5. 실제 배열 객체의 sizeof와 함수 매개변수의 sizeof를 구분한다.
6. 배열을 받는 함수에 길이를 별도로 전달한다.
7. 최댓값의 초기값·불변식·종료를 설명한다.
8. 단일·음수·첫/끝·중복·최대 길이를 검증한다.

## 핵심 이론

### 1. 배열 객체와 원소 객체

`int a[5];`는 int 원소 다섯 개를 갖는 배열 객체를 정의한다. 각각 a[0]부터 a[4]까지가 원소 객체이며 동일한 원소 형을 사용한다.

같은 배열의 원소는 연속 배치된다. int가 항상 4바이트이거나 모든 주소가 특정 숫자라고 가정하지 않는다. 도식의 칸은 원소 간 관계이며 실제 주소나 고정 바이트 폭이 아니다.

### 2. 개수와 인덱스

다섯 개의 원소에 접근하는 인덱스는 0·1·2·3·4다. 5는 마지막 인덱스가 아니라 원소 수다.

`[0, count)`는 0을 포함하고 count를 제외하는 반열린 구간이다. count개를 처리하는 반복은 보통 `i=0; i<count; ++i`로 쓴다.

`int a[5]`에서 a[5]를 읽거나 쓰면 배열 밖 접근으로 정의되지 않은 동작이다. 우연히 프로그램이 종료되지 않았다고 올바른 접근은 아니다. C 포인터에서 끝 바로 다음 위치를 표현하는 것과 그 위치의 원소를 읽는 것은 다르며 후속 포인터 단원에서 구분한다.

### 3. 물리적 용량과 사용 길이

`int values[20];`의 용량은 20이다. 입력 n=5일 때 사용 데이터는 앞 다섯 원소뿐이다.

| 구분 | 이 예제의 값 | 의미 |
| --- | ---: | --- |
| 선언 용량 | 20 | 실제 배열에 존재하는 칸 |
| 사용 길이 | 5 | 이번 계산의 입력 데이터 수 |
| 마지막 사용 인덱스 | 4 | n-1 |
| 마지막 물리 인덱스 | 19 | 용량-1 |

values[5]가 물리적 배열 안이어도 사용 데이터 밖이다. 값을 저장하지 않았다면 초기화된 원소라고 간주할 수 없다. 반대로 count=20일 때 values[20]은 물리적 배열 밖이다.

### 4. 고정 배열은 대입으로 늘어나지 않는다

이번 예제는 고정 용량 배열을 사용한다. 실행 도중 `values = larger;`로 교체하거나 선언 용량을 늘리지 않는다. VLA·동적 할당·동적 배열은 별도 주제다.

동적 배열에서도 사용 길이와 용량이 다르다는 개념은 유지된다. 기존 학생 배열 생성·예약·push 실습으로 나중에 연결한다.

### 5. 초기화와 미초기화

함수 안 자동 저장 기간의 `int a[5];`는 원소를 0으로 초기화하지 않는다. 값은 미정이며 정상 계산에 읽어서는 안 된다. 읽기 전에 각 원소에 값을 저장한다.

부분 초기화 `int a[5] = {4, -2};`는 뒤 세 int 원소를 0으로 만든다. `int a[5] = {0};`는 모든 원소가 0이다.

선언 때 초기화 목록이 있는 경우와, 입력을 성공적으로 받은 경우는 다른 경로다. scanf가 실패했는데 원소를 읽으면 초기화 전 읽기 위험이 남는다. 정적 저장 기간의 초기화와 자동 저장 기간의 미초기화를 혼동하지 않는다.

### 6. 원소의 읽기와 쓰기

다음은 초기화된 다섯 칸 배열이 있는 main 몸체의 **코드 조각**이다.

```c
a[2] = 7;
printf("%d\n", a[2]); // 7
```

인덱스와 원소 값을 분리해 읽는다. a[2]의 2는 세 번째 칸의 위치이며 저장된 7과 같은 역할이 아니다.

### 7. 배열 전체 대입과 원소별 복사

배열 전체를 `destination = source;`로 복사하는 것은 C의 일반 배열 대입이 아니다. 다음은 두 배열 모두 count개를 사용할 수 있는 범위 안의 **코드 조각**이다.

```c
for (size_t i = 0; i < count; ++i) {
    destination[i] = source[i];
}
```

복사를 시작하기 전에 목적 배열 용량과 초기화된 원본 길이를 확인한다. 선언 용량이 같다는 이유만으로 실제 사용 데이터 길이까지 같다고 추정하지 않는다.

### 8. sizeof의 단위와 결과 형

sizeof는 바이트 수를 구한다. 실제 고정 배열 객체가 있는 범위에서 `sizeof a / sizeof a[0]`는 전체 배열 바이트 수를 한 원소 바이트 수로 나눠 원소 수를 구한다.

결과는 size_t이므로 출력 형식은 %zu다. `sizeof(int)==4` 같은 숫자 가정이 필요하지 않다. 원소 값을 읽지 않는 sizeof를 실제 입력·초기화 검사로 오해하지 않는다.

`int values[20]`의 이 계산은 입력 n이 5여도 20이다. 사용 길이는 별도 변수로 유지한다.

### 9. 함수 매개변수의 배열 표기

`static int max_nonempty(const int values[], size_t count)`에서 배열 매개변수 표기는 원소를 가리키는 포인터 형으로 조정된다. 배열 객체 전체가 함수 안으로 복사되거나 길이가 자동 전달되지 않는다.

따라서 함수 안 `sizeof values`는 원래 배열 전체 크기가 아니다. 이 값으로 원소 개수를 추측하면 포인터 크기·원소 형에 따른 잘못된 결과를 얻는다. 호출자는 별도 count를 넘긴다.

### 10. const와 호출자 전제

const는 이 함수의 values 접근 경로로 원소를 수정하지 않는 약속이다. 원본 배열 전체를 항상 수정 불가능하게 바꾸는 마법이 아니다.

max_nonempty의 전제는 count>=1이고, values가 count개의 초기화된 int를 읽을 수 있게 가리킨다는 것이다. NULL 검사나 숫자 길이 하나만으로 실제 메모리 범위를 일반적으로 증명할 수 없다.

이번 main은 1~20 개수를 검사하고 입력된 앞 count개만 읽게 함수를 호출한다. 검증 책임을 입력/저장과 계산으로 구분한다.

### 11. 실제 첫 원소에서 후보 시작

전체 음수 `{-9,-3,-5,-10}`의 최댓값은 -3이다. 후보를 0으로 시작하면 데이터에 없는 0을 반환한다.

values[0]는 실제 원소이므로 후보로 사용할 수 있다. 단, 비어 있지 않고 읽기 가능하다는 전제를 먼저 만족해야 한다. count=1이면 비교를 반복하지 않고 첫 값을 반환한다.

### 12. 최댓값 추적 표

| 다음 비교 인덱스 i | 비교 전 maximum | 현재 값 | 비교 뒤 maximum |
| ---: | ---: | ---: | ---: |
| 1 | -9 | -3 | -3 |
| 2 | -3 | -5 | -3 |
| 3 | -3 | -10 | -3 |
| 4 | -3 | 범위 끝, 비교 없음 | -3 |

현재 후보와 현재 원소를 비교하며 더 큰 원소가 있으면 후보를 교체한다. 비교 뺄셈이나 합을 만들 필요가 없으므로 입력의 int 값에서 불필요한 signed 산술 넘침을 피한다.

### 13. 불변식·종료·복잡도

조건 검사 직전 maximum은 이미 처리한 접두 범위 `[0,i)`의 최댓값이다.

- 초기화: i=1이고 maximum=values[0]이므로 첫 원소 범위의 최댓값이다.
- 유지: values[i]와 비교한 뒤 i를 증가시키면 새 접두 범위의 최댓값이다.
- 종료: i=count에서 사용 원소 전부를 처리했다.

count가 양수이면 비교는 count-1회이며 계산 함수는 O(count) 시간·고정 개수의 보조 변수 공간을 쓴다. main의 입력 배열 저장 공간과 함수의 보조 공간은 구분한다. 테스트 횟수만으로 복잡도를 증명하는 것은 아니다.

### 14. 중복과 위치는 다른 계약

최댓값이 여러 번 나와도 값 하나의 결과는 같다. 현재 문제는 값만 출력하므로 첫 위치나 모든 위치를 출력하지 않는다.

위치를 요구하면 동등할 때 교체할지, 첫 위치를 유지할지, 별도 위치 목록을 만들지 명세를 먼저 정한다. 후속 구조체 배열의 첫 일치·안정 정렬 문제와 연결할 수 있다.

### 15. 입력 계약과 간단한 실패 정책

채점 입력은 n(1~20)과 int로 표현 가능한 정수 n개다. 기존 공개 입력·출력은 그대로다. 범위 밖 개수·변환 실패·조기 EOF·추가 토큰·표현 불가능한 숫자 텍스트는 이 입문 채점 대상 밖이다.

완성 프로그램은 표현 가능한 잘못된 개수와 실패한 변환에서 출력 없이 상태 1로 종료한다. 입력 예제 검증 범위를 채점 계약 확대로 오해하지 않는다.

scanf의 %d로 표현할 수 없는 숫자는 안전한 거부가 보장되지 않는다. 일반적인 신뢰하지 않는 텍스트 처리는 후속 fgets·strtol 단원의 변환 범위·잔여 문자 검사로 다룬다. 이번 프로그램은 임의 텍스트용 강건한 파서가 아니다.

## 정적 도식 읽기

독자 SVG의 `int a[5]={4,-2}`에서 값은 4·-2·0·0·0이다. 칸 아래 인덱스는 [0]부터 [4]까지다. 점선 [5]는 배열 원소가 아니며 접근 금지다.

유효 구간 [0,count)의 닫힌 시작과 열린 끝을 확인한다. 도식은 고정 상태 설명이며 런타임 애니메이션이 아니다.

## 단계별 예제

먼저 부분 초기화된 배열을 출력해 count와 인덱스를 관찰한다. 그 다음 입력을 실제 배열에 저장하고, 계산 함수가 읽을 범위를 count로 제한한다.

예제 A는 초기화와 순회만, B는 입력/계산 분리와 기존 채점 형식을 보여 준다. 코드를 보기 전에 출력과 마지막 유효 인덱스를 예상한다.

## 완성 프로그램 A: 초기화와 전체 원소 관찰

```c
#include <stddef.h>
#include <stdio.h>

int main(void) {
    int a[5] = {4, -2};
    size_t count = sizeof a / sizeof a[0];
    printf("count=%zu\n", count);
    for (size_t i = 0; i < count; ++i) {
        printf("a[%zu]=%d\n", i, a[i]);
    }
    return 0;
}
```

## 실행 결과

입력 없이 실행한 A는 다음을 출력한다.

```text
count=5
a[0]=4
a[1]=-2
a[2]=0
a[3]=0
a[4]=0
```

## 왜 이런 결과가 나오는가

초기화 목록에서 생략한 뒤 세 원소가 0이고 sizeof 비율은 원소 수 5다. i=5에서 조건이 거짓이므로 a[5] 출력은 없다.

예제를 바꾸어 실력 다지기: 초기값을 `{9,8,7}`로 바꾸었을 때 마지막 두 원소를 먼저 예상한다. 이 실험은 선언 용량 5를 유지한다. 다음에는 모든 0 초기화와 비교하되 미초기화 원소 읽기를 실험하지 않는다.

## 완성 프로그램 B: 배열 입력과 계산 함수

```c
#include <stddef.h>
#include <stdio.h>

static int max_nonempty(const int values[], size_t count) {
    int maximum = values[0];
    for (size_t i = 1; i < count; ++i) {
        if (values[i] > maximum) {
            maximum = values[i];
        }
    }
    return maximum;
}

int main(void) {
    enum { CAPACITY = 20 };
    int values[CAPACITY];
    int count_input;
    if (scanf("%d", &count_input) != 1 || count_input < 1 || count_input > CAPACITY) {
        return 1;
    }
    size_t count = (size_t)count_input;
    for (size_t i = 0; i < count; ++i) {
        if (scanf("%d", &values[i]) != 1) {
            return 1;
        }
    }
    printf("%d\n", max_nonempty(values, count));
    return 0;
}
```

| 입력 n과 원소 | 출력 | 이유 |
| --- | ---: | --- |
| 5 / 2 9 -3 4 1 | 9 | 기존 공개 예시 |
| 1 / -12 | -12 | 추가 비교 없음 |
| 4 / -9 -3 -5 -10 | -3 | 0이 아닌 실제 원소에서 시작 |
| 4 / 9 2 -3 1 | 9 | 첫 원소의 후보 보존 |
| 6 / -7 0 -7 0 -9 -2 | 0 | 중복과 음수/0 |
| 3 / -32767 0 32767 | 32767 | C 최소 int 범위 안의 대표 경계 |
| 20 / -20 -19 ... -1 | -1 | 마지막 물리 원소 포함 |

-32767과 32767은 모든 C11 int에 표현 가능한 대표 값이지 현재 환경의 INT_MIN/INT_MAX라는 뜻은 아니다. 값은 그대로 비교하므로 후보 갱신에서 덧셈이나 뺄셈을 수행하지 않는다.

이 함수의 static은 이 번역 단위 안에서 사용하는 이름이라는 뜻이다. 실제 배열은 복사하지 않고 유효 범위만 읽으며 원본을 바꾸지 않는다.

예제를 바꾸어 실력 다지기: 첫 위치가 최대인 배열을 끝 위치가 최대인 배열로 바꾸어 출력이 유지되는지 확인한다. 최솟값 함수로 바꿀 때는 비교 방향과 초기 후보를 함께 설명한다. 관찰용 중간 출력은 기존 채점 출력에 섞지 않는다.

## 흔한 오류

- `i<=count`는 사용 범위 뒤를 한 번 더 처리한다.
- 용량 전체를 순회하면 입력받지 않은 원소를 읽을 수 있다.
- count 검사 전에 values[0]부터 읽으면 빈 입력 경로에 위험이 있다.
- 후보 0은 전체 음수에서 잘못된 결과다.
- 함수 안 sizeof 비율은 원래 배열의 길이를 구하지 않는다.
- 입력 변환 실패를 무시하면 미초기화 원소를 읽을 수 있다.
- 배열 전체 대입과 원소별 대입을 혼동하지 않는다.
- 범위 밖 접근이 매번 충돌한다고 기대하지 않는다.

## 중간 점검

1. a[20]에 5개를 입력했을 때 용량·사용 길이·마지막 사용 인덱스는?
2. a[5]={4,-2}에서 a[4]는?
3. 최대 후보를 0으로 잡아도 되는가?
4. 배열 함수 매개변수에서 원소 수는 어떻게 아는가?
5. count=1이면 계산 함수의 비교는 몇 번인가?

확인: 20·5·4, 0, 일반적으로 아니오, 별도 길이 인수, 0번이다. 숫자뿐 아니라 전제와 검사 시점을 말한다.

## 개념 확인 퀴즈

`int a[5]`의 마지막 유효 인덱스는?

정답은 4다. 5는 개수이며 [0,5)에서 제외되는 경계다. 기존 화면 퀴즈의 정답 인덱스 2와 선택지는 유지한다.

## 핵심 요약

객체·원소·길이·용량·인덱스·초기화를 분리한다. 읽기 전에 유효 값을 저장하고 [0,count)를 지킨다. 함수에는 길이를 별도로 전달하며 실제 첫 원소에서 최대 후보를 시작한다.

## 기초 코딩 연습

기존 c-array를 풀고 공개 예시·단일 음수·전체 음수·첫/끝·중복·20개 입력을 확인한다. 한 입력만 통과했다고 전체 동작을 일반화하지 않는다.

## 응용 연습

원본 배열을 유지하면서 다른 고정 용량 배열에 원소별 복사를 구현한다. 사용 길이와 목적 용량을 따로 기록하고 복사 전후 출력을 비교한다.

최솟값 함수로 바꾸어 첫 원소 초기화와 접두 범위 불변식을 다시 설명한다.

## 도전 문제

최댓값의 첫 인덱스를 반환한다. `{7,2,7}`은 값 7과 첫 위치 0을 구분해야 한다. 같은 최댓값을 만났을 때 교체하지 않는 이유를 설명한다.

그 다음 모든 위치를 기록하는 문제로 확장한다. 결과 배열의 용량과 기록한 개수 계약을 먼저 정한다.

## Mini Project

1~7개 점수를 배열에 보관한다. 각 점수는 0~100으로 정하고 최고점·합·평균을 출력한다. 입력/저장·최대 계산·합 계산·출력을 나눈다.

합은 최대 700이므로 최소 int 범위 안이다. 평균은 나눗셈 전에 형을 변환하고 성공적으로 읽은 원소만 계산한다. `{70,90,80}`이면 최고점 90·합 240·평균 80.0이다.

최댓값 문제에 임의 점수 범위나 새로운 출력 형식을 섞지 않는다. 이 프로젝트는 별도의 연습이며 아직 새 자동 채점 문제를 등록하지 않았다.

## 테스트와 풀이 개선

완성 A/B를 각각 `gcc -std=c11 -Wall -Wextra -Werror -Wpedantic`으로 컴파일한다. A의 정확한 출력, B의 결과와 종료 상태를 확인한다.

비공개 사례는 기존 4개를 보존하고 첫 원소 최대·중복/0·대표 정수 경계 3개를 추가한다. 현재 GCC에서는 길이 1~20과 가능한 최댓값 위치를 조합한 210개 대표 음수 배열도 검사한다. 이것은 모든 정수 배열의 전수 검사가 아니다.

대표 오답은 후보 0과 마지막 원소 누락이다. 실패 사례를 최소화해 원인을 설명한 뒤 수정·재제출한다. C 하네스의 유한 검사는 모든 입력·메모리 안전·보안 격리를 증명하지 않는다.

## 복습 연결

다음 포인터 단원에서 주소·역참조·수명을 배운다. 기존 c-array-max-function은 NULL·0 길이·출력 포인터·실패 시 기존 값 보존을 추가한다. 이번 비어 있지 않은 함수와 그 후속 계약의 역할을 구분한다.

구조체 배열의 선형 탐색·안정 정렬·이진 탐색, 동적 배열의 length/capacity 구분으로 이어 간다. 문제 ID·스타터·공개 예시·초안·제출·백업 v1은 유지한다.

## 의미 검토 출처

원고·코드·문제·도식은 독자 작성했다. 공개 C11 위원회 초안 [N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)의 6.2.5(배열 형), 6.3.2.1(배열 표현식 변환), 6.5.2.1·6.5.6(첨자/경계), 6.5.3.4(sizeof), 6.7.6.3(배열 매개변수 조정), 6.7.9(초기화)로 의미를 검토했다. 최종 표준과 초안을 구분하며 원문을 복제하지 않았다. 제공 교재 본문 전체를 대조했다고 주장하지 않는다.
