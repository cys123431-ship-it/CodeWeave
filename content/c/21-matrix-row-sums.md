# 다차원 배열: 행·열과 안전한 행 합

이 원고와 예제·문제·정적 SVG는 CodeWeave용 독립 집필이다. 기존 진도·초안·제출 ID를 유지하며 `c-matrix-row-sums` 화면에 연결한다.

## 단원 개요

int matrix[2][3]는 int 세 개짜리 행 두 개로 이루어진 배열입니다. 표처럼 읽되 객체의 실제 중첩 구조, 두 첨자의 범위, 행 단위 포인터와 함수 계약까지 연결합니다. 고정 3열·최대 4행의 작은 합 실습으로 검증 범위를 명확히 합니다.

## 필요한 이유

성적표·좌표 격자·영상 조각은 행과 열이 있습니다. 1차원 배열의 길이만 바꾸면 int **나 열 크기 추측 오류가 생길 수 있습니다. 입력 객체의 모양, 함수가 접근할 범위와 결과를 공개하는 시점을 먼저 정하면 경계·부분 갱신 오류를 줄일 수 있습니다.

## 선수 지식

c-array의 객체·인덱스·초기화·sizeof, c-pointer의 주소/역참조·NULL·수명, c-array-max-function의 출력 포인터와 실패 보존을 복습합니다. 이번 예제는 const 입력 행렬을 사용하고 표준 입력 파싱은 새로 추가하지 않습니다.

## 학습 목표

2행×3열의 중첩 객체, 행 우선 배치와 순회, matrix와 matrix[0]의 서로 다른 포인터 변환을 설명합니다. 함수의 고정 열 폭과 별도 rows를 읽고 0..4행·3열·원소 범위·출력 capacity·실패 보존을 actual GCC와 반복 제출로 확인합니다.

## 행은 int 세 개짜리 배열 객체

matrix의 각 원소는 int[3]이고 matrix[0]는 첫 행 배열입니다. matrix[0][2]는 첫 행의 마지막 int 객체입니다. 행 수 2, 열 수 3을 뒤집지 않으며 그림 속 행/열 좌표를 코드의 [r][c]와 연결합니다. 아래는 완성 프로그램이 아닌 선언 코드 조각이며 size_t 원형에는 stddef.h가 필요합니다.

```c
const int matrix[2][3] = {
    {1, 2, 3},
    {4, 5, 6}
};
```

## 반열린 행·열 경계

이 객체의 유효 행은 [0,2), 각 행의 유효 열은 [0,3)입니다. matrix[1][2]는 마지막 원소이지만 matrix[0][3]은 첫 행을 벗어납니다. 다음 행이 연속 배치되어 있어도 잘못된 첨자가 허용되는 것은 아닙니다. 끝 바로 다음 주소 형성과 원소 읽기를 구분하고 잘못된 역참조 예제를 실행하지 않습니다.

## 행 우선 배치와 순회

행 배열의 원소가 연속되고 행들도 바깥 배열의 원소로 순서대로 이어집니다. 마지막 첨자인 열이 가장 빨리 변하는 행 우선 배치를 따릅니다. r을 바깥, c를 안쪽 반복으로 두면 각 행을 차례로 읽습니다. 이것이 모든 PC에서 같은 주소·int 바이트 수·성능을 보장하는 것은 아닙니다.

## 중괄호 초기화와 생략 칸

{{1,2,3},{4}}로 초기화하면 둘째 행의 나머지 두 칸은 0입니다. 행 중괄호를 표시해 모양을 읽기 쉽게 합니다. 초기화 없는 자동 배열은 값이 자동으로 0이라는 뜻이 아닙니다. 선언 시 행 수를 생략해 initializer로 추론할 수 있어도 내부 열 폭은 알려져 있어야 합니다.

## sizeof는 실제 배열 객체가 보일 때

sizeof matrix/sizeof matrix[0]는 행 수, sizeof matrix[0]/sizeof matrix[0][0]는 열 수입니다. 바이트 크기를 고정 숫자로 나누지 않습니다. 함수 매개변수로 조정된 matrix는 포인터이므로 sizeof matrix로 호출자 행 수를 복구할 수 없습니다.

## 두 단계 배열 변환

대부분의 식에서 matrix는 첫 행을 가리키는 포인터로 변환됩니다. 비const 행렬의 형으로 설명하면 int (*)[3]이며 matrix+1은 행 하나만큼 이동합니다. matrix[0]는 첫 int를 가리키는 포인터로 변환되어 matrix[0]+1은 같은 행의 다음 칸을 가리킵니다. &matrix는 행렬 전체의 주소라 형과 증가 단위가 또 다릅니다.

## 함수 매개변수와 고정 열 폭

const int matrix[][3]는 매개변수에서 const int (*matrix)[3]로 조정됩니다. 첫 차원의 행 수는 rows로 별도 전달하지만 내부 열 수 3은 행 하나의 형과 이동 단위에 필요합니다. int matrix[4][3]라고 적은 매개변수도 4행을 자동 검증하지 않습니다. 아래는 완성 프로그램이 아닌 선언 코드 조각이며 size_t 원형에는 stddef.h가 필요합니다.

```c
int sum_rows3(const int matrix[][3], size_t rows, long *out_sums);
```

## int **는 같은 모양이 아니다

int **는 int * 객체를 가리키는 포인터입니다. int[2][3]가 행 포인터 객체 두 개를 저장하는 구조는 아닙니다. 열 폭 2와 3인 배열 포인터도 다른 형이므로 임의 캐스트로 맞는 듯 보이게 만들지 않습니다. 포인터 배열·동적 행별 할당은 다른 계약의 후속 주제입니다.

## C11 const 배열 경계와 VLA 후속

이 단원의 입력 객체도 처음부터 const int 행렬로 선언합니다. C11에서 int (*)[3]를 const int (*)[3]로 암묵 변환하는 것은 단순 int *→const int *와 같다고 일반화할 수 없으며 GCC의 엄격 옵션에서 진단됩니다. C23의 배열 qualifier 규칙과 구분합니다. 런타임 열 수를 받는 VLA 매개변수는 C11 지원 차이와 양수 폭·수명 계약을 따로 설계할 후속이며 지금은 고정 3열입니다.

## 정적 도식 읽기

두 박스가 matrix[0]·matrix[1] 행 객체이고 각각 [0]·[1]·[2] 값을 포함합니다. 첫 행 1·2·3의 합은 6, 둘째 행 4·5·6의 합은 15입니다. 열 [3]은 접근 금지이며 행렬이 int **라는 주소 표처럼 그리지 않습니다.

## 단계별 예제와 호출자 계약

sum_rows3는 rows==0이면 NULL도 허용하고 1을 반환하며 아무것도 읽거나 쓰지 않습니다. 1..4행이면 실제 rows개의 const int[3] 행과 rows개 이상의 쓰기 가능한 long 출력 객체를 제공해야 하고 둘은 겹치지 않아야 합니다. NULL 검사나 행 개수 인수만으로 실제 객체 크기·주소·수명을 확인할 수는 없습니다.

## 수치 범위와 별도 누산형

각 원소는 [-10000,10000]이고 세 칸의 합/모든 중간 합은 [-30000,30000]입니다. 이 범위는 C의 최소 int 범위에도 들어가지만 결과 형은 명시적으로 long, 출력 형식은 %ld로 고정합니다. 열 수/범위를 확대하면 다시 수치 증명이 필요합니다. 이번 long 형 선택이 모든 크기의 합이나 signed overflow를 자동 해결하지 않습니다.

## 모든 검증 뒤 출력 공개

실패한 행 뒤 이미 앞 행 결과가 바뀌면 실패 보존 계약에 맞지 않습니다. long totals[4]라는 작은 자동 배열에 각 행의 합을 준비하고 모든 행·원소를 검증한 뒤 out_sums[0..rows)를 기록합니다. rows 이후의 미사용 출력은 그대로 유지합니다. 4는 과제 정책이지 C의 일반 행 상한이 아닙니다.

## 완성 프로그램 A: 초기화·행 우선 순회

완성 C11 프로그램입니다. 실제 객체가 보이는 main에서 sizeof 비율로 2행/3열을 계산하고 {{1,2,3},{4}}의 생략된 칸을 확인합니다. 코드 조각과 달리 헤더와 main을 포함하므로 그대로 컴파일할 수 있습니다.

```c
#include <stddef.h>
#include <stdio.h>

int main(void) {
    const int matrix[2][3] = {{1, 2, 3}, {4}};
    size_t rows = sizeof matrix / sizeof matrix[0];
    size_t columns = sizeof matrix[0] / sizeof matrix[0][0];
    printf("rows=%zu cols=%zu\n", rows, columns);
    for (size_t r = 0; r < rows; ++r) {
        printf("row %zu:", r);
        for (size_t c = 0; c < columns; ++c) {
            printf(" %d", matrix[r][c]);
        }
        putchar('\n');
    }
    return 0;
}
```

## 실행 결과 A와 가까운 변형 연습

행 0은 1·2·3, 행 1은 4·0·0입니다. 둘째 초기화 행을 {4,5,6}으로 바꾸고 결과를 먼저 예측하세요. 전체 행 수를 3으로 늘리고 마지막 행을 {7}로 추가하면 남은 칸이 어떻게 초기화되는지 가까이서 확인합니다.

```text
rows=2 cols=3
row 0: 1 2 3
row 1: 4 0 0
```

## 완성 프로그램 B: 행 합과 실패 보존

아래 완성 프로그램은 정상 두 행을 계산한 뒤 마지막 셀이 10001인 요청을 같은 출력 배열로 시도합니다. 함수 본문은 임시 결과를 사용해 앞 행도 보존합니다. 제출에는 main·입력/출력을 넣지 않고 sum_rows3와 필요한 stddef.h만 사용합니다.

```c
#include <stddef.h>
#include <stdio.h>

int sum_rows3(const int matrix[][3], size_t rows, long *out_sums) {
    if (rows == 0) {
        return 1;
    }
    if (rows > 4 || matrix == NULL || out_sums == NULL) {
        return 0;
    }
    long totals[4];
    for (size_t r = 0; r < rows; ++r) {
        long sum = 0;
        for (size_t c = 0; c < 3; ++c) {
            if (matrix[r][c] < -10000 || matrix[r][c] > 10000) {
                return 0;
            }
            sum += (long)matrix[r][c];
        }
        totals[r] = sum;
    }
    for (size_t r = 0; r < rows; ++r) {
        out_sums[r] = totals[r];
    }
    return 1;
}

int main(void) {
    const int valid[2][3] = {{1, 2, 3}, {4, 5, 6}};
    const int invalid[2][3] = {{9, 8, 7}, {1, 2, 10001}};
    long sums[3] = {77, 77, 77};
    int status = sum_rows3(valid, 2, sums);
    printf("valid status=%d sums=%ld,%ld tail=%ld\n",
           status, sums[0], sums[1], sums[2]);
    status = sum_rows3(invalid, 2, sums);
    printf("invalid status=%d sums=%ld,%ld tail=%ld\n",
           status, sums[0], sums[1], sums[2]);
    status = sum_rows3(NULL, 0, NULL);
    printf("empty status=%d\n", status);
    return 0;
}
```

## 실행 결과 B와 가까운 변형 연습

정상 합은 6·15, 세 번째 미사용 출력은 77입니다. 뒤 행의 잘못된 셀 때문에 실패하면 정상 결과와 미사용 값 모두 유지됩니다. invalid의 마지막 값을 -10001과 -10000으로 바꾸고 각각 실패/성공과 결과를 예측하세요. 행이 0인 요청은 성공하지만 결과 원소가 없습니다.

```text
valid status=1 sums=6,15 tail=77
invalid status=0 sums=6,15 tail=77
empty status=1
```

## 흔한 오류

행/열 뒤집기, c<=3 또는 r<=rows, sizeof 포인터로 길이 추측, int ** 혼동, C11 qualifier 경고 무시, 잘못된 마지막 셀 전에 앞 결과 공개, rows 뒤 출력 지우기, 디버그 출력이 대표 오류입니다. bounds 오류를 실제 역참조로 실행하지 말고 올바른 반열린 반복을 검토합니다.

## 핵심 요약과 개념 확인

2차원 배열은 배열의 배열입니다. 각 첨자의 범위·고정 열 폭·행 포인터와 int ** 차이를 구분합니다. sizeof는 객체가 보일 때만 개수를 구하며 C11 const 규칙을 최신 C 규칙과 혼동하지 않습니다. 입력 전체 검증 뒤 결과를 공개하고 사용하지 않는 출력도 보존합니다.

## 기초·응용·도전 연습과 Mini Project

기초: 2×3 값을 [r][c]로 읽고 초기화 빈 칸을 예상합니다. 응용: 1행/4행·음수·±10000과 뒤 행 오류를 비교합니다. 도전: 모든 성공 합을 기준 이중 반복과 비교하고 함수 선언의 열 폭 오류를 컴파일 단계에서 구분합니다. Mini Project: 작은 주간 기록 표를 행 합으로 요약하되 값 범위와 빈 표/실패 정책을 먼저 정하고 출력은 main에 둡니다.

## 테스트·풀이 개선·복습 연결

20개 하네스 사례는 최소/최대 행·열별 기여·음수/0·±30000·부분 초기화·빈 범위/NULL·SIZE_MAX·앞/마지막 셀 오류·전체/미사용 출력 보존·연속 호출을 확인합니다. 결과 비교가 잘못된 포인터나 모든 메모리 안전을 증명하지는 않습니다. 실패를 고쳐 재제출하고 이론 읽기·퀴즈·실습·숙달을 따로 확인한 뒤 파일 I/O의 표 읽기/오류 계약으로 연결합니다.

## 왜 이런 결과가 나오는가

A에서 바깥 배열의 두 원소는 각각 세 개의 int를 포함한 행 객체다. {4}는 그 행의 첫 칸만 명시적으로 초기화하며 나머지 두 칸은 0으로 초기화한다. 이는 초기화되지 않은 자동 객체의 값을 읽는 규칙과 다르다. 행 전체 크기/행 하나 크기는 2, 행 하나 크기/원소 크기는 3이다. 특정 sizeof(int)의 바이트 수를 가정하지 않는다.

B의 첫 호출은 두 행의 6과 15를 출력하고 세 번째 출력 칸 77은 그대로 둔다. 두 번째 호출은 앞 행의 합을 임시 저장하지만 뒤 행의 10001 때문에 0을 반환한다. 아직 출력 공개 단계에 진입하지 않았으므로 앞서 성공한 두 합과 미사용 칸이 전부 보존된다. 빈 범위는 입력이나 출력이 NULL이어도 아무 원소도 접근하지 않고 성공한다.

## 개념 확인

1. int a[2][3]의 원소 a[0]은 어떤 객체인가? — int 세 개를 포함한 행 배열 객체.
2. a + 1의 이동 단위는? — 행 하나. 바이트 수를 상수로 암기하지 않고 sizeof a[0]과 연결한다.
3. 다음 행이 연속 배치되어 있으니 a[0][3]도 허용되는가? — 아니다. 첫 행의 열 [3]은 원소가 아니며 읽으면 정의되지 않은 동작이다.
4. 함수 안의 sizeof matrix로 행 수를 알 수 있는가? — 아니다. 배열 매개변수는 행을 가리키는 포인터로 조정되므로 호출자가 rows를 제공한다.
5. 뒤 행에서 오류가 발견됐을 때 앞 행 합을 이미 출력에 쓴 구현은 계약을 만족하는가? — 아니다. 함수 실패는 전체 출력 보존을 약속한다.
6. 이 C11 예제의 호출 배열을 const로 선언한 이유는? — int (*)[3]에서 const int (*)[3]로의 변환을 평범한 int *의 const 추가와 혼동하지 않기 위해서다. C23의 변경을 C11 보장으로 설명하지 않는다.

## 기초 연습

A를 실제 컴파일한 뒤 두 번째 행을 {4, 5}로 바꿔 출력 4 5 0을 예측하고 검증한다. 다음에는 바깥 행 수를 3으로 바꿔 sizeof의 비율과 모든 인덱스 경계를 다시 계산한다. 두 번째 중괄호를 생략하는 평탄한 초기화가 가능하다는 사실과 행 경계를 명확히 보이는 집필 스타일을 구별한다.

## 응용 연습

B의 행 합을 음수만 있는 한 행, 세 칸 모두 10000인 행으로 바꾼다. 각각 합을 -6, 30000으로 예측한다. 출력 배열을 네 칸으로 늘리고 사용 행 수를 줄인 뒤 미사용 칸이 유지되는지 확인한다. 마지막 행의 마지막 칸을 범위 밖 값으로 바꾸고 모든 출력이 그대로인 이유를 설명한다.

## 도전 문제

열 수 3은 그대로 유지하면서 열 합을 구하는 별도 함수를 설계한다. 행·열 반복 순서, 빈 범위에서 결과를 어떻게 표현할지, 출력 세 칸이 항상 필요한지, 실패 보존과 입력/출력 비중첩을 먼저 문서로 결정한다. 이 문제의 sum_rows3 시그니처·채점 계약을 바꾸지 않는다. 가변 열 폭과 VLA 지원 문제는 후속 단원으로 남긴다.

## Mini Project

최대 네 번의 측정마다 세 센서 값을 저장한 const int[][3] 표를 만든다. 모든 행 합이 유효할 때만 요약표를 공개하는 작은 콘솔 프로그램을 작성한다. 측정 횟수 0·1·4, 세 값 모두 하한/상한, 두 번째 측정의 마지막 값 오류를 준비한다. 아직 파일이나 임의 경로를 읽지 않으며 저장소의 실행 도구는 신뢰하는 개인 코드용 loopback 개발 도구일 뿐 샌드박스가 아니다.

## 테스트 및 풀이 개선

공개 예시의 설명용 호출 표기는 C 소스 문장이 아니다. 하네스는 long 출력 네 칸을 모두 77로 시작하고 함수 상태 뒤 네 칸을 출력하므로 두 행이 성공하면 1 6 15 77 77이다. 제출 함수는 출력하지 않는다.

| 사례 | 관찰할 결과 |
| --- | --- |
| 0행, NULL 입력/출력 | 1 반환, 접근·쓰기 없음 |
| 1행/4행, 음수/0/부분 초기화 | 각 행의 세 칸만 합산 |
| 세 칸 모두 ±10000 | ±30000, 중간 합도 표현 가능 |
| 5행/SIZE_MAX/양수 NULL | 0 반환, 원소 읽기 이전 거부 |
| 첫 칸/뒤 행 마지막 칸 범위 오류 | 모든 출력의 이전 값 유지 |
| 같은 출력의 반복 호출 | 상태를 다음 호출로 잘못 누적하지 않음 |
| 미사용 칸/서로 다른 출력 객체 | 사용 범위 밖 값을 보존 |

20개 서버 사례는 반환값·출력·미사용 칸을 관찰한다. 이 유한한 fixture가 모든 포인터 유효성이나 악성 제출 격리를 증명하지는 않는다. 호출자는 충분한 수명의 실제 행 객체와 long 출력 객체를 제공하고 입력/출력이 겹치지 않게 해야 한다. 실제 자료 범위나 행 정책을 늘리면 저장소·수치 범위·시간 비용을 다시 검토한다.

기능 검사 통과 뒤 불필요한 printf와 공유 static 상태를 제거한다. 전체 프로그램 B에는 main이 있지만 제출 칸에는 sum_rows3 함수와 필요한 include만 넣는다. 화면의 실패→수정→재제출 이력을 보존하고 이론 읽기·퀴즈 통과·실습 통과·복습 표시를 별개로 기록한다.

## 복습 연결

배열 입문에서 객체/용량/사용 길이와 sizeof를, 포인터 입문에서 유효성·수명과 별칭을 다시 확인한다. find_max 함수형 실습에서 출력 포인터와 실패 보존을 연결한다. 이후 파일 입출력에서 “입력 전체 검증 뒤 결과 공개” 원칙을 확장하되 새 스트림·오류 계약을 별도로 설계한다.
