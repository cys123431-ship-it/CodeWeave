# C05 파일 스트림: 읽기·EOF·오류와 소유권

## 1. 개요·필요성·선수 지식·목표
예상 25분. 함수·포인터·반복과 fgets 단원을 먼저 학습한다. 파일의 끝을 정상 종료로 판단하되 읽기 오류를 성공으로 숨기지 않는 것이 목표다. 이번 범위는 바이트 입력과 빌린 스트림이며 문자열 해석·임의 경로 탐색·파일 복사기는 별도 단원이다.

## 2. 상세 이론: FILE 포인터와 수명
FILE은 표준 입출력 스트림의 상태를 관리한다. 연 쪽이 닫을 책임을 가지며 NULL은 열린 스트림이 아니다. 함수가 FILE 포인터를 인수로 받았다고 소유권까지 넘겨받는 것은 아니다. 이번 함수는 호출자가 계속 사용할 스트림을 빌리므로 fclose·freopen을 호출하지 않는다.

## 3. 열기와 닫기의 책임
일반 파일을 읽을 때 fopen("data.bin", "rb")의 반환값을 먼저 검사한다. "wb"는 기존 파일 내용을 잃을 수 있는 쓰기 모드다. 아래 예제는 사용자 파일을 건드리지 않도록 tmpfile로 이름을 직접 지정하지 않는 임시 스트림만 쓴다. fclose 뒤 포인터를 다시 사용하지 않으며 닫기의 실패도 검사한다. fclose 성공을 정전에도 보존되는 저장 보장으로 확대하지 않는다.

## 4. fgetc의 int 결과와 EOF
fgetc의 결과는 int로 받는다. EOF는 파일에 저장된 특별한 바이트가 아니라 읽기 결과다. char에 먼저 좁혀 담으면 바이트와 종료 신호를 잘못 구분할 수 있다. 반복을 끝낸 뒤 ferror로 읽기 오류 여부를 확인한다. feof를 미리 검사하는 것만으로 다음 읽기의 성공을 알 수는 없다.

## 5. 독자 정적 도식
화면용 도식은 src/figures.js의 stream-eof-error다: 호출자가 열기 → 빌린 함수가 현재 위치부터 읽기 → EOF에서 오류 판정 → 성공 때만 결과 기록 → 호출자가 닫기. EOF/오류 분기는 서로 다르며 함수가 닫기 책임을 가져가지 않는다.

## 6. 단계별 예제: 완성 프로그램
아래 전체 코드를 example.c로 저장한다. 고정된 네 바이트만 세는 예제이며 임의 크기 파일의 범용 집계기가 아니다.
```c
#include <stdio.h>
#include <stddef.h>

int main(void) {
    const unsigned char sample[] = {0x00, 0xff, 0x0a, 0x42};
    FILE *stream = tmpfile();
    if (stream == NULL) return 1;
    if (fwrite(sample, 1, sizeof sample, stream) != sizeof sample
        || fflush(stream) != 0 || fseek(stream, 0, SEEK_SET) != 0) {
        fclose(stream);
        return 1;
    }
    size_t count = 0;
    int ch;
    while ((ch = fgetc(stream)) != EOF) {
        ++count;
    }
    int ok = !ferror(stream);
    if (fclose(stream) != 0) return 1;
    if (!ok) return 1;
    printf("1 %zu\n", count);
    return 0;
}
```
컴파일: `gcc -std=c11 -Wall -Wextra -Wpedantic -Werror example.c -o example`.
성공 출력: `1 4` 다음 줄바꿈. 함수형 과제와 달리 main이 있는 완성 프로그램이다.

## 7. 실제 출력과 이유
| 읽은 값 | 누적 바이트 | 의미 |
|---|---:|---|
| 00 | 1 | NUL도 파일 데이터 |
| FF | 2 | EOF와 비교하기 전에 char로 좁히지 않기 |
| 0A | 3 | 데이터 값 0x0A |
| 42 | 4 | 데이터 값 0x42 |
| EOF | 4 | 더 세지 않고 ferror 확인 |
쓰기 뒤 fflush와 fseek를 거쳐 읽기로 전환했다. 일반 텍스트 모드는 환경에 따라 개행 표현이 변환될 수 있으므로 원본 바이트 집계는 바이너리 스트림을 약속한다. 바이트 수와 한글 글자 수는 다른 값이다.

## 8. 흔한 오류와 심화
NUL에서 멈추는 문자열 반복, EOF 자체를 한 번 더 세기, 함수 안에서 rewind하기, 읽기 오류인데 누적값을 공개하기가 흔한 오류다. NULL 검사 없이 ferror를 호출하면 안 된다.

## 9. 중간 점검·핵심 요약·퀴즈
빈 파일은 성공과 0바이트인가, 오류인가? 정상 EOF라면 성공과 0바이트다. 읽기 함수가 EOF를 반환했을 때 추가로 확인할 것은? ① 파일 이름 ② ferror ③ 저장한 char의 부호. 정답은 ②이며 EOF와 읽기 오류를 나누기 위해서다. 열기·읽기·판정·결과 공개·닫기의 책임을 구별하자.

## 10. 직접 풀기: 함수 계약
다음은 선언 조각이며 단독 실행 프로그램이 아니다.
```c
int count_stream_bytes(FILE *stream, size_t *out_count);
```
현재 위치부터 정상 EOF까지 바이트를 세어 성공 1과 결과를 기록한다. 허용 입력 길이는 최대4096바이트다. 빈 스트림·이미 정상 EOF인 스트림은 성공과 0이다. NULL 인수·기존 읽기 오류·도중 읽기 오류·4097번째 바이트 발견은 실패 0이며 유효한 out_count의 기존 값을 보존한다. NULL 인수·기존 오류는 읽기 전에 거부한다.
함수는 rewind·clearerr·fclose·freopen을 하지 않고 출력도 하지 않는다. 길이 초과 판정에는 4097번째 바이트를 읽을 수 있다. 실패 때 스트림 위치를 되돌리는 계약은 아니며 결과 객체만 보존한다. 성공 결과는 마지막에 한 번 공개한다.

## 11. 기초·응용·도전 연습과 Mini Project
기초: 빈 스트림과 한 바이트의 반환값·결과를 먼저 예상한다. 응용: 앞 두 바이트를 이미 읽은 스트림의 남은 길이를 계산한다. 도전: 4096/4097 경계와 읽기 오류에서 출력 값777이 보존되는지 확인한다. Mini Project는 tmpfile 임시 스트림에 만든 작은 테스트 자료 세 종류의 예상 바이트 수와 실제 결과를 표로 남기는 것이다. 소중한 실제 파일로 쓰기 실험을 하지 않는다.
