# CodeWeave — 교과서처럼 배우고 Exercism처럼 풀다

**C언어 · Rust · 자료구조 · 알고리즘 통합 학습 PWA** 초기 버전 (`v0.1`).

한국어 교과서형 이론 설명, 독자 제작한 SVG 그림, 대화형 퀴즈, 코드 작성·진도 관리, C언어 로컬 자동 채점 기능을 포함합니다. **AI 개인 멘토링과 코드 동작 애니메이션은 포함하지 않습니다.**

## 현재 구현됨

- PC·모바일 반응형 PWA, 정적 콘텐츠 캐시
- C언어 21개, Rust/자료구조/알고리즘 각 1개 학습 단원 **샘플**
- 개념 그림, 자세한 설명, 코드 예제, 개념 확인 퀴즈 24개
- 첫 C 프로그램은 전처리→번역→목적 파일→링크→실행·종료 상태를 독자 정적 도식, 경고 없는 완성 예제, 오류·점검·세 단계 연습과 함께 연결
- 변수·자료형 단원은 초기화·대입·최소 보장·나눗셈·변환 시점·입출력 계약을 상세 원고와 비교 도식, 실제 GCC로 검사하는 두 완성 프로그램으로 연결
- 조건문·반복문 단원은 0/비0 조건·분기·반복 상태·불변식·종료·off-by-one·long 누산을 22절 화면과 독립 원고·정적 흐름 도식·컴파일 예제·0/1/1000 경계 실습으로 연결
- 배열 입문은 객체·0 기반 인덱스·초기화·용량/사용 길이·sizeof·별도 길이 함수·최댓값 불변식을 24절 화면과 독립 원고·정적 경계 도식·두 GCC 완성 예제로 연결
- 학습 진도·모든 트랙의 코드·제출 이력을 한 JSON 파일로 백업/복원
- 이론 읽기·퀴즈 통과·실습 통과·복습 필요·전체 숙달을 분리해 단원과 트랙에 표시
- 메인 C 단원에서 최근 10회 제출 코드·테스트 결과 확인, 이전 코드 복원 후 재제출
- 메인 단원과 별도 연습장의 제출 이력 공유 (기존 v1 저장 형식 유지)
- Concept/Practice 유형, 언어, 선수 단원, 개념, 채점 가능 여부와 선수 그래프 순환을 검증하는 문제 메타데이터
- **C언어 21개 문제에 대해 실제 GCC 컴파일 및 테스트** (전체 프로그램 입출력형 8개 + 함수 직접 호출형 11개 + 다중 파일형 2개, 로컬 서버만 가능)
- GCC 실패 원문을 보존하면서 누락 헤더·선언/정의 불일치·미정의 참조·중복 정의·일반 컴파일/링크 오류를 한국어 학습 피드백으로 구분

## 빠른 시작

- Node.js 20 이상과 C 자동 채점용 GCC가 필요합니다.
- Node 의존 패키지가 없어 `npm install`은 필요하지 않습니다.

```bash
npm start
```

브라우저에서 **http://127.0.0.1:4173** 열기.

**반복 제출 연습장:** 대시보드의 `반복 제출 연습장` 메뉴 또는 **http://127.0.0.1:4173/workbench.html**로 접속할 수 있습니다. 메인 C 단원의 코딩 실습에서도 최근 10회 제출 코드와 테스트 결과를 확인하고 이전 코드를 복원할 수 있습니다. 별도 연습장과 같은 제출 이력을 공유합니다. 대시보드의 학습 기록 관리와 연습장 모두 진도·모든 트랙의 코드 초안·제출 이력을 `codeweave-full-backup.json` 하나로 내보냅니다. 기존 진도 v1과 제출 이력 v1 파일도 계속 복원할 수 있습니다.

단원 숙달은 **이론 읽음 + 퀴즈 통과 + C 실습 통과 + 복습 불필요**를 모두 만족할 때만 표시합니다. 과거 통과 기록은 유지하되 최신 퀴즈 또는 실습이 실패하면 복습이 필요한 상태가 되며, 학습자가 수동으로 복습 표시를 켜고 끌 수도 있습니다. 아직 자동 채점이 없는 트랙은 실습과 전체 숙달을 완료로 표시하지 않습니다.

정적 호스팅(GitHub Pages 등)에서는 단원·퀴즈·코드 작성과 저장만 사용할 수 있으며 **코드 컴파일·자동 채점 버튼은 연결 실패를 안내**합니다.

## 꼭 확인할 제한

**주의:** 이 로컬 서버는 작성한 C 소스 코드를 사용자의 OS에서 실행하며 실행 격리가 되지 않습니다. **신뢰하는 본인의 코드만 제출하고 서버를 공용 네트워크에 절대 공개하지 마세요.** 공개 채점 기능은 별도 샌드박스 시스템 구축 후 제공해야 합니다. Rust 채점과 자료구조/알고리즘 전용 문제 채점도 아직 연결되지 않았습니다.

로컬 정적 서버는 `server/static-files.mjs`에 명시한 학습 화면·브라우저 모듈·PWA 자산만 제공합니다. Git 메타데이터, 환경 파일, 서버 코드, 테스트, 문서와 미등록 파일은 HTTP로 제공하지 않으며 심볼릭 링크와 잘못된 경로도 차단합니다. 새 학습 자산을 추가할 때는 허용 목록과 `tests/static-server.test.mjs`도 갱신하세요. 이 파일 접근 정책은 C 실행을 격리하지 않습니다.

공개 문제 정보는 `src/exercises.js`, 브라우저에 노출하지 않는 GCC 사례와 함수 테스트 하네스는 `server/grading-exercises.mjs`에서 관리합니다. 채점 가능 여부는 트랙 이름이 아니라 검증된 문제 정의를 기준으로 계산합니다. `stdin-output`은 제출 프로그램 전체를 실행합니다. `fgets` 실습은 빈 줄·정확한 7바이트 경계·여러 조각·개행 없는 EOF·즉시 EOF·첫 줄 이후 입력 무시를 구분하고, 후속 `strtol` 실습은 정상 음수·숫자 없음·잔여 문자·`ERANGE`·정확한 63바이트/초과 줄을 분리합니다. `c-function`은 학습자가 작성한 함수 소스와 서버 전용 `main` 하네스를 별도 파일로 컴파일·링크해 함수를 직접 호출합니다. 현재 `clamp`, 배열 최댓값, 널 종료 문자열의 문자 세기, 용량 제한 문자열 길이, `struct Student` 점수 갱신·구조체 배열 학번 검색·학번 안정 정렬·첫 위치 이진 탐색·동적 학생 배열 생성/해제·`realloc` 용량 확장·기하급수 push 문제로 반환값, 배열 길이, 출력 포인터, 종료 경계, 첫 일치, 구조체 전체 이동, 동등 키 순서, 빈 범위, 유효 상태, 실패 시 원본 보존과 불필요한 출력 부작용을 검사합니다. 기본 `c-multi-file`은 `main.c`·`functions.c`·`functions.h`를, 학생 명부 프로젝트는 `main.c`·`student.c`·`student.h`를 각각 보존해 함께 컴파일합니다.

여덟 번째 함수형 문제는 정렬된 구조체 배열에서 학번의 첫 위치를 이진 탐색합니다. 반열린 구간 `[left, right)`, 오버플로를 피하는 중간점 계산, 중복을 만난 뒤에도 왼쪽 경계를 좁히는 lower-bound 방식, 실패 시 출력값 보존을 12개 사례로 검사합니다. 정렬 상태와 실제 포인터 범위는 호출자 전제이며, 유한한 채점 사례만으로 모든 입력에서의 `O(log n)` 복잡도를 수학적으로 증명하지는 않습니다.

아홉 번째 함수형 문제는 `size_t` 곱셈을 수행하기 전에 `count > SIZE_MAX / sizeof *students`를 검사하고 `malloc`으로 구조체 배열을 만듭니다. 12개 사례가 점수 경계, 0개 정책, 잘못된 포인터, 크기 오버플로, 할당 실패, 초기화, `free`와 포인터 초기화를 검사합니다. 할당 실패는 메모리 고갈에 기대지 않고 GCC/ld의 제한된 `--wrap=malloc`·`--wrap=free` 하네스로 결정적으로 주입합니다. 이 래퍼도 교육용 회귀 검사일 뿐 실행 샌드박스가 아닙니다.

열 번째 함수형 문제는 `length`와 `capacity` 불변식을 검증하고 임시 포인터로 `realloc` 결과를 받은 뒤 새 슬롯을 0으로 초기화합니다. 13개 사례가 정상 성장, 빈 배열 첫 성장, 같은 용량, 성장 전용 정책, 정규 상태, 곱셈 오버플로와 결정적으로 주입한 재할당 실패를 검사하며 실패 시 포인터·용량·기존 레코드 보존을 요구합니다. 제한된 `--wrap=realloc`도 로컬 교육용 회귀 검사이며 공개 실행 격리가 아닙니다.

열한 번째 함수형 문제는 검증된 `reserve_students`를 재사용해 학생 한 명을 추가합니다. 17개 사례가 여유 슬롯, 마지막 슬롯, 0→4, 1→2, 3→6과 반복 성장, 정수 극값 레코드, NULL·상태 불변식, 두 단계 오버플로, 주입된 예약 실패를 검사합니다. 실패 뒤 포인터·길이·용량·기존 원소가 보존되고 성공한 뒤에만 새 레코드와 길이가 공개되어야 합니다.

학생 명부 Mini Project는 앞선 안정 정렬과 첫 위치 이진 탐색을 분할 컴파일 프로그램으로 조립합니다. 10개 사례가 정렬 전/후, 동등 키 순서, 첫·마지막·중복·미발견·한 원소·빈 입력, 현재 GCC 환경의 `int` 극값, 잘못된 개수와 불완전한 입력을 구분합니다. 별도 회귀는 불안정 정렬, 중복의 중간 반환과 정의 누락 링크 실패를 실제 GCC로 거부합니다.

컴파일이 실패하면 `src/compiler-feedback.js`가 GCC/링커 원문을 수정하지 않고 초보자가 먼저 확인할 한국어 범주와 점검 항목을 덧붙입니다. 이 안내는 정답 추론이나 AI 멘토링이 아니라 결정적인 진단 패턴의 고정 분류이며, 알 수 없는 오류는 일반 컴파일 또는 링크 오류로 남깁니다. 피드백은 제출 이력과 통합 백업 v1의 선택 필드로 보존되고 과거 기록은 그대로 읽을 수 있습니다.

다중 파일 초안은 `src/multi-file.js`의 버전 표식이 있는 문자열 하나로 직렬화합니다. 따라서 기존 `codeweave.drafts.v1`, `codeweave.iterations.v1`, 통합 백업 v1 형식을 바꾸지 않습니다. 파일명은 경로가 아닌 허용 목록과 정확히 일치해야 하며, 누락·중복·추가 파일과 파일별/전체 크기 초과는 GCC 실행 전에 거부합니다. 이 입력 검증도 제출 C 코드 자체를 격리하지는 않습니다.

**교재 PDF는 저장소에 포함하지 않습니다.** 제공받은 두 책은 강의 구성과 설명 방식의 참고 자료이며 콘텐츠 초안은 독자 집필했습니다. 전체 책의 본문 분석/통합은 미완성 상태입니다.
