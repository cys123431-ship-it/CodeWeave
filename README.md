# CodeWeave — 교과서처럼 배우고 Exercism처럼 풀다

**C언어 · Rust · 자료구조 · 알고리즘 통합 학습 PWA** 초기 버전 (`v0.1`).

한국어 교과서형 이론 설명, 독자 제작한 SVG 그림, 대화형 퀴즈, 코드 작성·진도 관리, C언어 로컬 자동 채점 기능을 포함합니다. **AI 개인 멘토링과 코드 동작 애니메이션은 포함하지 않습니다.**

## 현재 구현됨

- PC·모바일 반응형 PWA, 정적 콘텐츠 캐시
- C언어 9개, Rust/자료구조/알고리즘 각 1개 학습 단원 **샘플**
- 개념 그림, 자세한 설명, 코드 예제, 개념 확인 퀴즈 12개
- 학습 진도·모든 트랙의 코드·제출 이력을 한 JSON 파일로 백업/복원
- 이론 읽기·퀴즈 통과·실습 통과·복습 필요·전체 숙달을 분리해 단원과 트랙에 표시
- 메인 C 단원에서 최근 10회 제출 코드·테스트 결과 확인, 이전 코드 복원 후 재제출
- 메인 단원과 별도 연습장의 제출 이력 공유 (기존 v1 저장 형식 유지)
- Concept/Practice 유형, 언어, 선수 단원, 개념, 채점 가능 여부를 검증하는 문제 메타데이터
- **C언어 9개 문제에 대해 실제 GCC 컴파일 및 테스트** (전체 프로그램 입출력형 6개 + 함수 직접 호출형 2개 + 다중 파일형 1개, 로컬 서버만 가능)
- GCC 실패 원문을 보존하면서 누락 헤더·선언/정의 불일치·미정의 참조·중복 정의·일반 컴파일/링크 오류를 한국어 학습 피드백으로 구분

## 빠른 시작

- Node.js 20 이상과 C 자동 채점용 GCC가 필요합니다.
- Node 의존 패키지가 없어 `npm install`은 필요하지 않습니다.

```bash
npm start
```

브라우저에서 **http://127.0.0.1:4173** 열기.

**반복 제출 연습장:** 대시보드의 `반복 제출 연습장` 메뉴 또는 **http://127.0.0.1:4173/workbench.html**로 접속할 수 있습니다. 메인 C 단원의 코딩 실습에서도 최근 10회 제출 코드와 테스트 결과를 확인하고 이전 코드를 복원할 수 있습니다. 별도 연습장과 같은 제출 이력을 공유합니다. 대시보드의 학습 기록 관리와 연습장 모두 진도·모든 트랙의 코드 초안·제출 이력을 `codeweave-full-backup.json` 하나로 내보냅니다. 기존 진도 v1과 제출 이력 v1 파일도 계속 복원할 수 있습니다.

단원 숙달은 **이론 읽음 + 퀴즈 통과 + C 실습 통과 + 복습 불필요**를 모두 만족할 때만 표시합니다. 과거 통과 기록은 유지하되 최신 퀴즈 또는 실습이 실패하면 복습이 필요한 상태가 되며, 학습자가 수동으로 복습 표시를 켜고 끌 수도 있습니다. 아직 자동 채점이 없는 트랙은 실습과 전체 숙달을 완료로 표시하지 않습니다.

정적 호스팅(GitHub Pages 등)에서는 단원·퀴즈·코드 작성과 저장만 사용할 수 있으며 **코드 컴파일·자동 채점 버튼은 연결 실패를 안내**합니다.

## 테스트

```bash
npm test
```

선택적인 실제 브라우저 검사(Playwright/Chromium/GCC 필요):

```bash
npm install --no-save --package-lock=false playwright@1.62.1
npx playwright install --with-deps chromium
npm run test:browser
```

브라우저 검사에는 테스트용 프로필을 사용합니다. 함수 단원과 배열·출력 포인터 함수 실습, `main.c`·`functions.c`·`functions.h` 다중 편집기, 문제 유형·선수 단원·함수 하네스/다중 파일 채점 연결, 컴파일·링크 학습 피드백, 두 화면의 이력 공유·복원·백업 호환성·학습 상태와 숙달 전환·키보드 이동·390px 화면·오프라인 재로딩을 확인합니다. 특히 다중 파일 실습은 390px에서 세 편집기의 실제 경계를 검사하고, 성공·실패 제출 복원과 통합 백업 왕복 뒤 세 파일 및 이력이 유지되는지 확인합니다. GitHub Actions의 `browser` 작업에서 실행합니다. `npm test`의 DOM fixture 성공과 실제 Chromium E2E 성공은 별도로 확인하세요.

코드 초안은 저장 직전에 최신 데이터를 읽고 해당 문제만 갱신합니다. 다른 문제/트랙의 초안은 유지되며, 퀴즈를 풀 때 코드 저장 snapshot을 덮어쓰지 않습니다. 같은 문제를 두 탭에서 동시에 편집하면 마지막 저장이 적용되므로 한 화면에서 편집하세요.

통합 복원은 최대 5MB의 JSON을 받으며 알려진 단원 데이터만 정규화합니다. 저장 도중 오류가 나면 이미 쓴 키를 원래 값으로 되돌립니다. 기존 제출 이력 v1 파일을 가져올 때는 C 연습 범위만 교체하고 Rust 등 다른 트랙과 퀴즈 진도를 보존합니다. 복원 범위의 현재 데이터는 교체되므로 먼저 최신 통합 백업을 내려받으세요.

## 꼭 확인할 제한

**주의:** 이 로컬 서버는 작성한 C 소스 코드를 사용자의 OS에서 실행하며 실행 격리가 되지 않습니다. **신뢰하는 본인의 코드만 제출하고 서버를 공용 네트워크에 절대 공개하지 마세요.** 공개 채점 기능은 별도 샌드박스 시스템 구축 후 제공해야 합니다. Rust 채점과 자료구조/알고리즘 전용 문제 채점도 아직 연결되지 않았습니다.

로컬 정적 서버는 `server/static-files.mjs`에 명시한 학습 화면·브라우저 모듈·PWA 자산만 제공합니다. Git 메타데이터, 환경 파일, 서버 코드, 테스트, 문서와 미등록 파일은 HTTP로 제공하지 않으며 심볼릭 링크와 잘못된 경로도 차단합니다. 새 학습 자산을 추가할 때는 허용 목록과 `tests/static-server.test.mjs`도 갱신하세요. 이 파일 접근 정책은 C 실행을 격리하지 않습니다.

공개 문제 정보는 `src/exercises.js`, 브라우저에 노출하지 않는 GCC 사례와 함수 테스트 하네스는 `server/grading-exercises.mjs`에서 관리합니다. 채점 가능 여부는 트랙 이름이 아니라 검증된 문제 정의를 기준으로 계산합니다. `stdin-output`은 제출 프로그램 전체를 실행하고, `c-function`은 학습자가 작성한 함수 소스와 서버 전용 `main` 하네스를 별도 파일로 컴파일·링크해 함수를 직접 호출합니다. 현재 `clamp`와 배열 최댓값 문제로 반환값, 배열 길이, 출력 포인터, 실패 시 출력 보존과 불필요한 출력 부작용을 검사합니다. `c-multi-file`은 지정된 `main.c`·`functions.c`·`functions.h`를 각각 보존해 함께 컴파일합니다.

컴파일이 실패하면 `src/compiler-feedback.js`가 GCC/링커 원문을 수정하지 않고 초보자가 먼저 확인할 한국어 범주와 점검 항목을 덧붙입니다. 이 안내는 정답 추론이나 AI 멘토링이 아니라 결정적인 진단 패턴의 고정 분류이며, 알 수 없는 오류는 일반 컴파일 또는 링크 오류로 남깁니다. 피드백은 제출 이력과 통합 백업 v1의 선택 필드로 보존되고 과거 기록은 그대로 읽을 수 있습니다.

다중 파일 초안은 `src/multi-file.js`의 버전 표식이 있는 문자열 하나로 직렬화합니다. 따라서 기존 `codeweave.drafts.v1`, `codeweave.iterations.v1`, 통합 백업 v1 형식을 바꾸지 않습니다. 파일명은 경로가 아닌 허용 목록과 정확히 일치해야 하며, 누락·중복·추가 파일과 파일별/전체 크기 초과는 GCC 실행 전에 거부합니다. 이 입력 검증도 제출 C 코드 자체를 격리하지는 않습니다.

**교재 PDF는 저장소에 포함하지 않습니다.** 제공받은 두 책은 강의 구성과 설명 방식의 참고 자료이며 콘텐츠 초안은 독자 집필했습니다. 전체 책의 본문 분석/통합은 미완성 상태입니다.
