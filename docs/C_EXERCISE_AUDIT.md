# C 20문제 교차 품질 감사

감사 기준일: 2026-10-13
대상: `src/exercises.js`의 실제 채점 가능한 C 문제 20개와 `server/grading-exercises.mjs`의 비공개 사례

## 판정 기준

- 공개 예시가 비공개 GCC 사례에 같은 입력·기대 출력으로 포함되는가
- 문제 ID, 채점 방식, 필수 파일, 선수 문제가 서로 일치하는가
- 정상값뿐 아니라 문제에 해당하는 최소·최대·빈 값·중복·실패 보존·출력 부작용을 검사하는가
- 함수형 문제는 사용자 함수와 서버 하네스를 별도 번역 단위로 링크하는가
- 콘텐츠가 C 표준의 보장, 구현 의존 동작, 호출자 전제를 구분하는가
- Node fixture, 실제 GCC 검사, Chromium 시나리오의 책임을 구분하는가

공개 예시 20개는 모두 비공개 사례와 일치했다. 이번 감사 뒤 전체 GCC 사례는 164개이며, 같은 문제 안에서 중복된 사례 설명이나 함수 하네스 인수는 없다.

## 이번 감사에서 수정한 결함

1. 선수 문제 검증이 직접 자기 참조와 없는 ID만 거부하고 `A → B → C → A` 같은 간접 순환을 허용했다. 깊이 우선 탐색으로 전체 그래프의 순환과 실제 순환 경로를 검출하도록 수정했다.
2. `c-loops`는 입력 범위를 `0~1000`으로 선언했지만 상한 1000을 검사하지 않았다. `500500` 결과를 실제 GCC 사례로 추가했다.
3. `c-array`는 원소 수를 `1~20`으로 선언했지만 20개 경계를 검사하지 않았다. 20개 전체가 음수인 사례를 추가해 길이 상한과 잘못된 0 초기화를 함께 압박한다.
4. 세 `clamp` 경로가 `low < high`만 사실상 검사했다. `low == high == value` 사례를 전체 프로그램형, 함수형, 다중 파일형에 각각 추가했다.

## 남은 품질 부채와 다음 순서

- 첫 다섯 기초 단원은 화면 3절짜리 시범 콘텐츠다. 콘텐츠 정책의 개요·필요성·선수 지식·목표·상세 이론·오류·점검·요약·세 단계 연습·복습 연결을 충족하는 전체 교과서 단원으로 순차 확장해야 한다.
- `c-types`의 두 `int` 덧셈과 `c-pointer`의 1 증가 문제는 허용 입력 범위를 더 명확히 적어 signed overflow가 생기지 않는 계약을 고정해야 한다.
- 초기 입출력형 문제는 유효 입력 중심이다. 잘못된 입력, 초과 토큰, 조기 EOF를 어떤 출력/종료 상태로 처리할지 문제별 정책을 먼저 정한 뒤 사례를 추가해야 한다.
- 함수 하네스의 출력 비교와 시간 제한은 임의 포인터 유효성, 메모리 안전, 복잡도를 증명하지 않으며 보안 격리도 아니다. 공개 실행과 분리된 로컬 개인 도구 경계를 유지한다.
- Chromium CI는 대표 학습 흐름을 검사하지만 Windows·Android·iPad 실기기와 설치형 PWA의 터치·오프라인 동작은 별도 검증이 필요하다.

다음 구현 단위는 위 계약 부채 중 하나를 테스트 우선으로 정리한 뒤, `reserve_students`를 재사용하는 `push_student`와 기하급수적 성장 정책을 별도 문제로 추가하는 것이다.
