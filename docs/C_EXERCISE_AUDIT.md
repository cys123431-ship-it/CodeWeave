## 이번 감사에서 수정한 결함

1. 선수 문제 검증이 직접 자기 참조와 없는 ID만 거부하고 `A → B → C → A` 같은 간접 순환을 허용했다. 깊이 우선 탐색으로 전체 그래프의 순환과 실제 순환 경로를 검출하도록 수정했다.
2. `c-loops`는 입력 범위를 `0~1000`으로 선언했지만 상한 1000을 검사하지 않았다. `500500` 결과를 실제 GCC 사례로 추가했다.
3. `c-array`는 원소 수를 `1~20`으로 선언했지만 20개 경계를 검사하지 않았다. 20개 전체가 음수인 사례를 추가해 길이 상한과 잘못된 0 초기화를 함께 압박한다.
4. 세 `clamp` 경로가 `low < high`만 사실상 검사했다. `low == high == value` 사례를 전체 프로그램형, 함수형, 다중 파일형에 각각 추가했다.
5. `c-types`와 `c-pointer`가 signed overflow를 피하는 입력 범위를 선언하지 않았다. 각각 `[-10000, 10000]` 두 정수와 `[-10000, 9999]` 한 정수로 계약을 고정하고, C가 최소로 보장하는 `int` 범위 안에서 결과가 유지되는 이유와 양쪽 경계 사례를 추가했다.

## 남은 품질 부채와 다음 순서

- `c-hello`·`c-types`·`c-loops`·`c-array`·`c-pointer`는 콘텐츠 정책의 개요·필요성·선수 지식·목표·상세 이론·오류·점검·요약·세 단계 연습·복습 연결과 실제 컴파일 예제를 갖췄다. 반복문의 500500 합은 최소 int 범위를 넘으므로 화면·원고·참조 풀이를 long/%ld로 고정했고, n=1 및 마지막 항 누락·누산값 초기화 오답 회귀를 추가했다. 완성 합 프로그램은 현재 GCC에서 허용 n=0~1000을 모두 수학적 기대값과 대조한다. 배열 입문은 용량/사용 길이·초기화·배열 매개변수·sizeof 한계·최댓값 접두 불변식을 연결하고 210개 길이/최댓값 위치 조합을 현재 GCC에서 검사한다. 포인터 입문은 NULL 검사와 객체 유효성·수명·읽기/쓰기 계약을 구분하고 세 완성 프로그램으로 별칭/재대입·기존 증가·NULL/상한 실패 보존을 검사한다. 첫 다섯 기초 단원 확장은 전체 교과서 완성으로 계산하지 않는다.
- 초기 `c-types`·`c-pointer`는 계산 개념에 집중하도록 유효한 정수 개수와 범위를 입력 계약으로 고정했다. 범위 밖 값, 변환 실패, 추가 토큰과 조기 EOF는 채점 대상에서 제외하며, 이를 다루는 강건한 입력 처리는 후속 `fgets`·`strtol` 단원과 중복하지 않는다.
- 함수 하네스의 출력 비교와 시간 제한은 임의 포인터 유효성, 메모리 안전, 복잡도를 증명하지 않으며 보안 격리도 아니다. 공개 실행과 분리된 로컬 개인 도구 경계를 유지한다.
- Chromium CI는 대표 학습 흐름을 검사하지만 Windows·Android·iPad 실기기와 설치형 PWA의 터치·오프라인 동작은 별도 검증이 필요하다.

함수 단원은 범위/저장기간/연결·가림·자동/static 객체를 29절로 확장하고 세 완성 프로그램/두 함수 조각과 작은 clamp 경계 조합 375개를 실제 GCC로 검사한다. 기존 여섯 채점 사례는 그대로이며 반환값을 버리는 오답은 별도 API 회귀로 검사한다. 원고의 오래된 다중 파일 미구현 문장을 현재 세 채점 경로와 연결해 수정했다. 재귀 입문은 별도 c-recursion-factorial에서 종료/진행 척도·호출별 자동 상태·최대 13개 helper 활성 호출·0..12 수치 범위·실패 보존을 구현했다. 기능 채점은 재귀 사용 자체를 증명하지 않으며 올바른 반복형도 허용한다.

`push_student`는 검증된 `reserve_students`를 다른 번역 단위에서 제공받아 재사용한다. 하네스는 0→4와 이후 두 배 요청, 여유 슬롯의 무할당 경로, 함수 합성, 실패 시 포인터·길이·용량·원소 보존을 관찰한다. 다음 감사 우선순위는 재귀 활용·다차원 배열·파일 입출력 등 남은 C 핵심 콘텐츠 확장과 전체 23문제의 실제 Chromium 흐름 유지다.

재귀 추가 감사: 기준값 0 오류·실패 전 출력 덮어쓰기·공유 static 누산 상태·13 허용·디버그 출력을 실제 GCC API로 거부하고 올바른 반복형은 승인했다. 반복 호출 오답은 개별 18개 사례를 통과해도 같은/다른 출력 객체 시나리오에서 실패한다. 전체 사례 229개는 기능 회귀 범위이며 전체 입력 메모리 안전이나 알고리즘 구현 방식 증명이 아니다.

다차원 배열 추가 감사: 마지막 열·마지막 행 누락, 전체 검증 전 출력 공개, 미사용 출력 덮어쓰기, 빈 범위 거부, 원소 범위 초과 허용을 독립 오답으로 검사한다. C11 const 행 포인터 변환·열 폭 불일치·int ** 혼동은 컴파일 제약 검사에서만 사용하며 잘못된 포인터 프로그램은 실행하지 않는다. 행 합의 ±30000은 최소 int 범위에도 들어가며 long이 이 값에 꼭 필요하다고 주장하지 않는다. 229개 기능 사례는 임의 포인터 안전성이나 보안 격리를 증명하지 않는다.

### 채점 경로와 주요 문제 계약

공개 문제 정보는 `src/exercises.js`, 브라우저에 노출하지 않는 GCC 사례와 함수 테스트 하네스는 `server/grading-exercises.mjs`에서 관리합니다. 채점 가능 여부는 트랙 이름이 아니라 검증된 문제 정의를 기준으로 계산합니다. `stdin-output`은 제출 프로그램 전체를 실행합니다. `fgets` 실습은 빈 줄·정확한 7바이트 경계·여러 조각·개행 없는 EOF·즉시 EOF·첫 줄 이후 입력 무시를 구분하고, 후속 `strtol` 실습은 정상 음수·숫자 없음·잔여 문자·`ERANGE`·정확한 63바이트/초과 줄을 분리합니다. `c-function`은 학습자가 작성한 함수 소스와 서버 전용 `main` 하네스를 별도 파일로 컴파일·링크해 함수를 직접 호출합니다. 현재 `clamp`, 배열 최댓값, 널 종료 문자열의 문자 세기, 용량 제한 문자열 길이, `struct Student` 점수 갱신·구조체 배열 학번 검색·학번 안정 정렬·첫 위치 이진 탐색·동적 학생 배열 생성/해제·`realloc` 용량 확장·기하급수 push 문제로 반환값, 배열 길이, 출력 포인터, 종료 경계, 첫 일치, 구조체 전체 이동, 동등 키 순서, 빈 범위, 유효 상태, 실패 시 원본 보존과 불필요한 출력 부작용을 검사합니다. 기본 `c-multi-file`은 `main.c`·`functions.c`·`functions.h`를, 학생 명부 프로젝트는 `main.c`·`student.c`·`student.h`를 각각 보존해 함께 컴파일합니다.

여덟 번째 함수형 문제는 정렬된 구조체 배열에서 학번의 첫 위치를 이진 탐색합니다. 반열린 구간 `[left, right)`, 오버플로를 피하는 중간점 계산, 중복을 만난 뒤에도 왼쪽 경계를 좁히는 lower-bound 방식, 실패 시 출력값 보존을 12개 사례로 검사합니다. 정렬 상태와 실제 포인터 범위는 호출자 전제이며, 유한한 채점 사례만으로 모든 입력에서의 `O(log n)` 복잡도를 수학적으로 증명하지는 않습니다.

아홉 번째 함수형 문제는 `size_t` 곱셈을 수행하기 전에 `count > SIZE_MAX / sizeof *students`를 검사하고 `malloc`으로 구조체 배열을 만듭니다. 12개 사례가 점수 경계, 0개 정책, 잘못된 포인터, 크기 오버플로, 할당 실패, 초기화, `free`와 포인터 초기화를 검사합니다. 할당 실패는 메모리 고갈에 기대지 않고 GCC/ld의 제한된 `--wrap=malloc`·`--wrap=free` 하네스로 결정적으로 주입합니다. 이 래퍼도 교육용 회귀 검사일 뿐 실행 샌드박스가 아닙니다.

열 번째 함수형 문제는 `length`와 `capacity` 불변식을 검증하고 임시 포인터로 `realloc` 결과를 받은 뒤 새 슬롯을 0으로 초기화합니다. 13개 사례가 정상 성장, 빈 배열 첫 성장, 같은 용량, 성장 전용 정책, 정규 상태, 곱셈 오버플로와 결정적으로 주입한 재할당 실패를 검사하며 실패 시 포인터·용량·기존 레코드 보존을 요구합니다. 제한된 `--wrap=realloc`도 로컬 교육용 회귀 검사이며 공개 실행 격리가 아닙니다.

열한 번째 함수형 문제는 검증된 `reserve_students`를 재사용해 학생 한 명을 추가합니다. 17개 사례가 여유 슬롯, 마지막 슬롯, 0→4, 1→2, 3→6과 반복 성장, 정수 극값 레코드, NULL·상태 불변식, 두 단계 오버플로, 주입된 예약 실패를 검사합니다. 실패 뒤 포인터·길이·용량·기존 원소가 보존되고 성공한 뒤에만 새 레코드와 길이가 공개되어야 합니다.

학생 명부 Mini Project는 앞선 안정 정렬과 첫 위치 이진 탐색을 분할 컴파일 프로그램으로 조립합니다. 10개 사례가 정렬 전/후, 동등 키 순서, 첫·마지막·중복·미발견·한 원소·빈 입력, 현재 GCC 환경의 `int` 극값, 잘못된 개수와 불완전한 입력을 구분합니다. 별도 회귀는 불안정 정렬, 중복의 중간 반환과 정의 누락 링크 실패를 실제 GCC로 거부합니다.

재귀 입문 `c-recursion-factorial`은 종료 조건·진행 척도·호출별 자동 상태·수치/깊이 계약을 25절과 독립 원고·정적 세로 호출/반환 도식·두 GCC 완성 프로그램으로 연결합니다. 20개 하네스 사례는 0..12 전체, 13·UINT_MAX, NULL과 반복 호출·실패 보존을 검사합니다. 기능 채점은 재귀 사용 자체를 증명하지 않으며 올바른 반복형도 통과할 수 있습니다. 실제 Chromium 시나리오는 공유 상태 오답→수정→숙달·390px 가독성/경계·오프라인을 다룹니다.

열세 번째 함수형 문제 `c-matrix-row-sums`는 열 폭 3과 행 수 0..4를 고정한다. 원소 범위 ±10000, 빈 범위/NULL 정책, 실패 시 전체 출력 보존, 미사용 칸 보존과 반복 호출을 20개 사례로 검사한다. 호출자는 실제 행 객체·충분한 출력 용량·수명·입출력 비중첩을 보장해야 하며 C11 예제의 입력 배열은 const로 선언한다. 390px/오프라인 검사는 Windows·Android·태블릿 실기기/PWA 설치 검증을 대신하지 않는다.
