# CodeWeave 지속 개발 실행 지침

사용자가 2026-10-11에 승인한 장기 개발 요구사항을 다음 실행이 이어받기 위한 운영 문서다. 실제 상태와 다음 작업은 `docs/DEVELOPMENT_LOG.md`에서 확인한다. 예약 활성화 여부와 다음 시각은 예약 도구의 조회 결과로 확인하며 이 문서 자체가 예약이나 실행 성공의 증거는 아니다.

## 목표와 경계

- 저장소: https://github.com/cys123431-ship-it/CodeWeave, 기본 브랜치 `main`. 다른 CodeStep 저장소를 변경하거나 혼합하지 않는다.
- 슬로건: **교과서처럼 깊게 배우고, Exercism처럼 직접 풀다.**
- C·Rust·자료구조·알고리즘을 연결하는 한국어 개인 학습 웹앱/PWA. Windows PC, 스마트폰, 태블릿에서 같은 학습과정을 제공한다.
- 이론 → 예제 → 개념 확인 → 코드 작성 → 실제 테스트 → 오류 수정 → 재제출 → 숙달 → 다음 단원의 흐름을 만든다.
- AI 개인 멘토·챗봇·튜터와 복잡한 런타임 메모리 애니메이션은 구현하지 않는다. 정적인 독자 제작 SVG·표·도식은 사용한다.
- 기존 브라우저 기본 기술과 Node.js 구조를 점진적으로 발전시킨다. 정상 기능을 프레임워크 유행 때문에 재작성하지 않는다.
- GitHub 저장, 정적 호스팅, 서버 측 코드 실행은 다른 역할이다. GitHub 커밋을 실제 사이트 배포나 공개 채점 완료로 보고하지 않는다.
- 학습 기록은 브라우저 로컬 데이터다. 퀴즈 정답, 코딩 실습 통과, 이론 읽기, 복습 필요, 전체 숙달을 혼동하지 않는다. 서버 인증 없는 로컬 통과 기록은 신뢰할 수 있는 외부 성적 증명이 아니다.

## 실행마다 수행할 절차

1. GitHub 연결·최신 HEAD·CI·열린 관련 PR을 조회한다. 로컬 체크아웃이 있으면 먼저 미커밋 변경을 확인한다. 없다면 최신 저장소를 가져온다. 웹 예약은 이전 실행의 scratch 체크아웃이 유지된다고 가정하지 않는다.
2. `README.md`, `docs/ROADMAP.md`, `docs/ARCHITECTURE.md`, `docs/CONTENT_POLICY.md`, `docs/DEVELOPMENT_LOG.md`, 이 문서를 읽는다. 작업 관련 소스·테스트와 실제 트리를 확인한다.
3. CI 실패나 심각한 장애를 먼저 해결한다. 이전 실행에서 완료된 기능을 중복 생성하지 않고 미완료 작업 중 하나를 선정한다.
4. 변경 전 검증 가능한 성공 조건을 정한다. 허용된 실행 시간에 마칠 수 있는 의미 있는 작업 단위를 선택한다. 한 시간 간격은 한 시간 내내 가동하라는 의미가 아니다.
5. 필요한 코드·콘텐츠·테스트를 실제 생성·수정한다. 기존 데이터 형식·UI·문제·PWA를 보존한다. 오류를 발견하면 재현 검사부터 추가한다.
6. 논리·문법·보안·호환성을 검토하고 `npm test`, 변경된 JS/MJS의 `node --check`, `git diff --check`를 실행한다. 가능하면 C 예제·문제를 GCC로 컴파일한다. GCC 없는 환경의 통합 검사 skip을 성공으로 보고하지 않는다.
7. UI 변경은 사용 가능한 브라우저 도구로 실제 확인한다. 브라우저 도구가 없으면 그 한계를 기록하고 기능/DOM fixture 검사와 실제 브라우저 E2E를 구분한다. HTTP 200이나 CI 성공을 E2E 성공으로 보고하지 않는다.
8. 실패를 수정하고 필요한 검사를 다시 실행한다. 테스트가 실패한 변경을 main에 반영하지 않는다. 정상 통과 후 불필요하게 같은 검사를 반복하지 않는다.
9. 검증된 작은 변경을 이해하기 쉬운 커밋으로 반영한다. 위험 변경은 브랜치/PR로 분리한다. 기존 사용자 작업과 원격 HEAD가 달라졌다면 새 HEAD를 검토하고 다시 합친다. 강제 푸시하지 않는다. 연결 도구에서는 base tree를 보존하는 atomic tree/commit/ref 업데이트를 사용할 수 있다.
10. 개발 일지에 사실을 기록하고 원격 HEAD·변경 파일·CI를 다시 조회한다. 다음 실행이 이어받을 구체적인 우선 작업을 지정한다.

### 일지 필드

실행 일시(KST), 시작 커밋, 목표와 성공 조건, 수정/생성 파일, 구현 기능, 실행한 검사와 성공/실패/skip, 발견/해결/미해결 문제, GitHub 커밋 또는 PR, 다음 작업.

커밋에 포함된 일지는 자신의 SHA를 미리 알 수 없으므로 시작 SHA와 커밋 제목을 기록할 수 있다. 실제 결과 SHA·원격 재조회·CI 상태는 실행 보고서로 남긴다. 테스트와 CI를 수행하지 않았으면 미실행/대기라고 기재한다.

포인터는 주소/값, 선언/역참조, 호출자 값 변경, 배열과의 차이, 초기화/NULL/수명/잘못된 역참조/정의되지 않은 동작까지 설명해야 한다. 모든 주제에서 짧은 요약+문제만 대량 생성하는 방식을 피한다. 예제는 실제 컴파일 가능한 부분과 조각 코드를 구분하고 구현 의존/정의되지 않은 동작을 언어의 보장으로 가르치지 않는다.

## 채점 및 보안

`dev-server.mjs`는 loopback의 **신뢰하는 개인 코드만 실행하는 로컬 개발 서버**다. 임의 C/Rust 코드를 호스트 OS에서 실행하는 공개 API로 배포하지 않는다. 시간/출력 제한은 파일·네트워크 격리나 샌드박스가 아니다.

문제는 입출력·함수·자료구조·다중 파일·Rust 전용 유형을 점진적으로 지원한다. 문제에 맞는 정상/경계/최소/빈 입력/음수/중복/최대 크기/반환값/부작용/잘못된 입력/시간 초과/메모리 검사를 설계한다. Rust는 Cargo와 유닛 테스트를 따로 고려한다. 컴파일 오류·실행 오류·오답·정답과 전송 실패를 구분한다.

공개 실행기가 필요하면 격리·네트워크 차단·CPU/메모리/시간/프로세스 제한·파일 접근·비루트·결과 위변조·악성 코드 대응을 별도로 설계하고 검증한다. 사용자 승인 없이 유료 API, 유료 서비스, 인증/보호 해제, 기밀 공개, 저장소 이전, 대규모 삭제, 강제 덮어쓰기/푸시, 사용자 데이터 삭제, 미검증 공개 실행 서버를 활성화하지 않는다.

## 예약과 실패 처리

사용자가 요청한 시간대는 `Asia/Seoul`, 주기는 매 1시간, 이름은 **CodeWeave 자동 개발**이다. 이미 승인된 안전한 코드/문서/콘텐츠/테스트/커밋은 매번 승인받지 않고 진행한다. 예약 생성 성공과 개발 실행 성공을 구분하고 다음 시각·활성화를 도구로 확인한다. 한 번 실패했다고 사용자가 요청하지 않은 예약 중단을 하지 않는다.

GitHub 오류는 정확한 메시지, 읽기/쓰기 구분, 새/기존 파일 구분, 실행 환경·테스트 범위를 기록한다. 합리적인 일시 오류 재시도는 허용하되 정책/보호를 우회하지 않는다. 반영되지 않은 결과는 패치/검사 기록으로 보존하고 다음 실행이 이어받게 한다. 본질적인 장애일 때 정확한 제한과 대안을 보고한다.

예약이 지원되지 않으면 설정 완료라고 쓰지 않는다. GitHub Actions의 hourly schedule만으로 AI 개발이 되지는 않으며 별도 에이전트·자격 증명·실행/비용 제한·테스트·반영 정책이 필요하다. 승인 없이 유료 대안을 활성화하지 않는다.

한국어로 실행 시각(KST), 작업 목표, 완료 기능, 파일/역할, 실행 검사/성공/실패/미실행 이유, 발견·수정·재검토, SHA/URL/브랜치/CI, 실제 미완료와 위험, 다음 개발 목표, 분야별 상태를 기록한다. 근거 없는 전체 진행률을 만들지 않는다. 결과 보고나 계획이 실제 코드 작업을 대체하지 않는다.
