# CodeWeave 아키텍처 (2026-10 초기 제안)

## 목적

개인용 PWA에서 C·Rust·자료구조·알고리즘을 **교과서 수준으로 학습하고 Exercism처럼 직접 풀고 실제 테스트로 검증**한다. AI 개인 멘토링 및 런타임 메모리 애니메이션은 제외한다. 필요할 때 정적인 교육 그림과 표를 사용한다.

## v0.1 범위

- 의존성 없는 브라우저 UI: `index.html` + `styles.css` + ES modules
- 로컬 진도·풀이 코드 저장, 백업·복원, 네 트랙과 아홉 개 시범 단원
- 자동 채점: 브라우저 개념 퀴즈 9개 + **개인 PC용 C 컴파일/테스트 API 6개**
- PWA: service worker가 정적 자산을 저장하고 네트워크가 없어도 이론/퀴즈/임시 코드를 제공
- 모바일 브라우저: 반응형 콘텐츠/읽기/퀴즈/임시 코드 작성. 모바일 단독 로컬 컴파일 불가

## 중요한 보안 경계

`dev-server.mjs`는 제출된 임의 C 코드를 운영체제에서 직접 실행한다. **컨테이너 샌드박스가 아니다.** 오직 신뢰할 수 있는 본인의 코드만 입력하는 개발 환경에서 사용해야 한다. 서버는 `127.0.0.1`로만 바인딩한다. 공용 인터넷/캠퍼스 네트워크에 노출하지 않는다. 시간 초과와 출력 크기 제한은 보조 조치일 뿐 파일 접근이나 네트워크 통신을 막지 않는다.

인터넷에서 모든 사용자가 C/Rust 코드를 자동 채점하도록 하려면 별도의 격리된 제출 워커/큐/저장소를 구축한다. 예시: 컨테이너 기반 실행 (비루트, seccomp, 네트워크 비활성, CPU/메모리/시간 제한, 읽기 전용 파일시스템, 프로세스 수 제한, 실행 결과 검증). 사전 검증 완료까지 외부 코드 실행 API는 공개하지 않는다.

### 로컬 정적 파일 접근 정책

`server/static-files.mjs`는 현재 브라우저가 사용하는 17개 파일을 정확한 경로로 허용한다. `/`는 `index.html`로 연결하고 정상 query와 GET/HEAD를 지원한다. 디렉터리 전체를 공개하지 않으므로 `.git`, `.env`, 서버/테스트/문서/원고와 미등록 `src`·`assets` 파일은 404다. 새로운 학습 자산은 허용 목록과 정적 서버 회귀 검사에 함께 등록해야 한다.

원래 요청 경로를 URL 정규화 전에 검사하여 점 경로, 중복 구분자, 역슬래시, 인코딩된 구분자/중복 인코딩, 잘못된 UTF-8/퍼센트 인코딩과 제어 문자를 400으로 거부한다. 허용된 파일도 부모 디렉터리와 파일의 심볼릭 링크를 거부하고 실제 경로를 확인한다. 지원되는 OS에서는 최종 파일을 `O_NOFOLLOW`로 열며 열린 파일의 메타데이터와 스트림을 사용한다. HEAD와 연결 종료 시 파일을 닫고 읽기 오류는 응답 연결을 종료한다.

이 정책은 신뢰하는 로컬 체크아웃의 HTTP 파일 제공 범위를 좁히는 조치다. 악의적인 프로세스가 파일시스템을 동시에 교체하는 환경이나 제출된 C 프로그램의 파일·네트워크 접근을 격리하는 경계가 아니다. `tests/static-server.test.mjs`는 실제 비밀 대신 임시 프로젝트의 합성 파일로 차단을 재현하고 모든 PWA shell 자산과 기존 API 경로를 검사한다. 브라우저 동작은 별도 Chromium CI로 확인한다.

## 향후 권장 구조

```text
apps/web        → React + TypeScript PWA (UX 안정화 후 전환 가능)
apps/api        → 제출 수집·인증·점수 판정 API
workers/runner  → C/Rust 컨테이너 기반 격리 컴파일·실행
packages/content → 구조화된 MDX, 코드 예제, 그림, 체크 문제
packages/tests   → 언어별 공개/비공개 테스트 정의
supabase         → 계정·진도·풀이 동기화 (선택)
```

현 프로토타입은 모든 학습 경로·점수·코드가 브라우저에만 있으므로 **로그인, 모바일과 PC 동기화, 중앙 저장, 채점 기록 검증** 등은 미구현 상태다.

## Exercism에서 차용할 교육 설계

- Track 별 강의·연습문제
- Concept / Practice Exercise 구분
- Starter code → 자체 작성 → 테스트 실행 → 실패를 수정하여 재제출
- 같은 문제의 반복 제출(iterations) 및 테스트 주도 학습(TDD)
- Learning Mode / Practice Mode, 선수 개념과 복습 큐
- 오류를 정답 코드 제공이 아니라 피드백과 설명으로 연결

**참고할 학습 방식과 재사용 가능한 소스의 구분:** Exercism 트랙별 LICENSE, 콘텐츠 출처, 개별 코드를 사전 확인한다. 현재 저장소에는 타 프로젝트의 코드나 교재 원문을 복제하지 않는다.

## 초안 공유 안정화와 검증 (2026-10-11 후속)

`src/practice.js`의 `readExerciseDrafts`/`saveExerciseDraft`는 기존 `codeweave.drafts.v1`을 보존하면서 저장 직전에 최신 데이터를 읽고 해당 문제만 갱신합니다. 단원과 연습장 모두 이 경로를 사용합니다. 퀴즈 진도 저장은 초안을 다시 쓰지 않고, 백업 복원/사용자 초기화에서만 명시적인 전체 교체를 합니다. 다른 탭의 저장 이벤트는 활성 편집기를 다시 만들지 않습니다. localStorage 트랜잭션이나 여러 기기 동기화가 아니므로 같은 문제의 동시 편집은 마지막 저장이 적용됩니다.

PWA shell v7은 함수 단원·도식·문제를 포함한 갱신된 카탈로그를 배포합니다. 별도 `npm run test:browser`와 GitHub Actions browser 작업으로 실제 Chromium/GCC, 함수 화면 연결, 공유 이력, 복원, 기존 백업, 모바일 너비, 오프라인 재로딩을 검사합니다. PWA 설치·실제 Windows/Android/iPad 기기는 이 검사 범위 밖입니다.

## 통합 백업과 기존 형식 호환

`src/backup.js`는 `full-backup` v1 형식으로 퀴즈 진도, 모든 트랙의 코드 초안, 문제별 최근 제출 이력을 한 파일에 저장한다. 두 화면은 내보내기 직전에 localStorage의 최신 세 키를 다시 읽으므로 열려 있던 화면의 오래된 메모리 상태를 백업하지 않는다. 가져오기는 알려진 단원만 허용하고 코드·진단·테스트 수와 길이를 기존 제한으로 정규화한다. UI는 5MB보다 큰 파일을 JSON으로 읽기 전에 거부한다.

기존 `CodeWeave version:1` 진도 파일은 진도·초안만 교체하고 독립 제출 이력을 유지한다. 기존 `kind:attempt-history version:1` 파일은 C 연습 범위의 초안·제출만 교체하고 퀴즈 진도와 Rust 등 다른 트랙 데이터를 유지한다. 새 통합 형식은 세 범위를 모두 교체한다. 세 localStorage 키를 쓰는 도중 오류가 나면 이미 변경한 키를 이전 원문으로 되돌리며, 자동 복구까지 실패한 경우 이를 별도 오류로 알린다. localStorage 자체는 트랜잭션 데이터베이스가 아니므로 복원 전 파일 백업을 계속 권장한다.

PWA shell v7은 통합 백업 및 숙달 계산 모듈과 함수 단원 카탈로그를 오프라인 자산에 포함한다. 실제 Chromium CI는 연습장에서 통합 파일을 내려받아 다시 복원하고, 기존 진도 v1도 메인 화면에서 복원하며, 이후 오프라인 재로딩까지 검사한다.

## 학습 상태와 숙달 판정

기존 `codeweave.progress.v1` 키를 유지하면서 `theoryRead`와 수동 `review` 단원 ID 배열을 추가한다. 필드가 없는 기존 기록은 빈 배열로 정규화하므로 퀴즈 통과만으로 이론 읽기나 숙달을 추정하지 않는다. 퀴즈 통과는 기존 `completed`, 실습 통과는 `codeweave.iterations.v1`의 성공 제출에서 각각 계산한다.

`src/mastery.js`는 저장 형식과 UI 사이의 순수 계산 경계다. C 단원은 이론·퀴즈·성공 제출을 모두 갖고 복습이 불필요할 때만 전체 숙달이다. 최신 퀴즈 결과나 최신 실습 제출이 실패했거나 수동 복습 표시가 있으면 과거 통과 이력을 지우지 않고 숙달만 보류한다. 채점기가 없는 Rust·자료구조·알고리즘 단원은 실습 통과와 전체 숙달을 주장하지 않는다. 통합 백업 v1은 새 배열을 선택 필드로 보존하며 두 기존 v1 파일은 빈 배열로 안전하게 이관한다.
