# 로컬 개발·검사·학습 기록 관리

README의 실행·복원·제한 상세를 모은 안내다. 문제별 사례와 콘텐츠 검사 범위는 [C 문제 감사](C_EXERCISE_AUDIT.md), 개발 순서는 [운영 지침](AUTONOMOUS_DEVELOPMENT.md)을 따른다.

## 실행과 검사

Node.js 20 이상과 PATH에서 실행 가능한 GCC를 준비하고 저장소 루트에서 실행한다. 일반 실행과 단위 검사는 외부 Node 의존 패키지가 필요 없다.

```bash
npm start
```

학습 화면은 http://127.0.0.1:4173, 별도 연습장은 http://127.0.0.1:4173/workbench.html 이다. 페이지가 받은 시작별 토큰으로 채점 요청을 인증하므로 서버 재시작 후에는 페이지를 새로고침한다. Host·Origin·정확한 application/json 검사와 토큰 검사를 우회하지 않는다.

```bash
npm test
```

## 선택적 Rust 로컬 서버 구성

일반 `npm start`는 C 채점만 활성화한다. 같은 서버의 `/api/grade/rust`는 인증 후503을 반환하며 `CODEWEAVE_RUST_ENABLED` 같은 환경 변수로는 활성화되지 않는다. Windows Rust 실행은 지원하지 않는다.

신뢰된 운영 코드에서는 `server/learning-server.mjs`의 `createLearningServer({root, rustService})`로 명시적 구성을 만들 수 있다. `rustService`는 `createLocalRustGradingService({enabled:true, definitions, sysroot, parent})`로 생성한다. 기존 F01은 `server/rust-exercises.mjs`의 `createRustGradingDefinitions()`가 반환하는 서버 전용 Map으로 제공한다. sysroot는 고정 버전/호스트의 실제 도구 설치 경로, parent는 조상 Cargo 설정이 없는 신뢰된 작업 공간 부모여야 한다. 다운로드나 임의 경로를 HTTP 입력으로 받지 않는다. 아직 F01 클라이언트 제출/기록 경로는 연결하지 않았으므로 이 구성만으로 화면의 F01 실습이 열리지는 않는다.

factory 생성/import는 서버를 시작하지 않는다. 반환 객체의 `await app.listen(4173)`으로 열고 `app.address()`로 실제 포트를 확인하며 `await app.close()`로 닫는다. 포트0은 테스트용 임의 포트다. 바인딩은 항상127.0.0.1이며 두 번째 호스트 인수는 거부한다. 페이지의 시작별 토큰·Host/Origin/JSON 제한, C/Rust 공유 슬롯과 취소/정리는 계속 적용된다. Rust의 inspect/recover는 운영자 객체에만 있고 HTTP 경로로 제공하지 않는다. 이 구성도 신뢰하는 본인 코드용이며 샌드박스나 공개 배포 수단이 아니다.

## 브라우저 검증 경로

자동 개발 환경의 고정 경로는 [운영 지침의 상시 제약](AUTONOMOUS_DEVELOPMENT.md#상시-제약)에 기록한다. 이후 실행에서는 같은 환경의 브라우저 설치나 실행 파일 탐색을 반복하지 않는다. 일반 `npm test`와 GCC/API 검사는 로컬에서 계속 실행한다.

실제 Chromium/GCC 검사는 [GitHub Actions 설정](../.github/workflows/ci.yml)의 `browser` 작업에서 `npm run test:browser`로 실행한다. [실행 목록](https://github.com/cys123431-ship-it/CodeWeave/actions/workflows/ci.yml)에서 반드시 결과 커밋 SHA를 대조하고, 전체 실행과 `test`·`browser`·`macos-resources` 작업의 성공을 확인한다. `browser` 로그의 실제 검사 결과와 `codeweave-browser-qa` 아티팩트를 함께 검토한다. 다른 SHA의 성공이나 대기 중인 작업으로 현재 변경을 완료 처리하지 않는다.

브라우저 검사가 실패하면 로그의 첫 오류를 확인해 다음 작업의 우선순위로 삼는다. CI 다운로드 장애와 UI/채점 회귀를 구별하고, 재시도했다면 원래 실패와 재시도 결과를 모두 남긴다. 테스트를 skip하거나 인증·격리를 해제해 성공으로 만들지 않는다. 별도 개발자의 이미 준비된 Playwright/Chromium 환경에서는 같은 npm 명령을 사용할 수 있지만, 그것이 이 자동 개발 환경의 설치 재시도를 허용하는 뜻은 아니다.

DOM fixture 통과, 실제 Chromium 통과, 실제 기기의 PWA 설치 검증은 서로 다른 증거다.

## 진도·제출·백업

**반복 제출 연습장:** 대시보드의 `반복 제출 연습장` 메뉴 또는 **http://127.0.0.1:4173/workbench.html**로 접속할 수 있습니다. 메인 C 단원의 코딩 실습에서도 최근 10회 제출 코드와 테스트 결과를 확인하고 이전 코드를 복원할 수 있습니다. 별도 연습장과 같은 제출 이력을 공유합니다. 대시보드의 학습 기록 관리와 연습장 모두 진도·모든 트랙의 코드 초안·제출 이력을 `codeweave-full-backup.json` 하나로 내보냅니다. 기존 진도 v1과 제출 이력 v1 파일도 계속 복원할 수 있습니다.

단원 숙달은 **이론 읽음 + 퀴즈 통과 + C 실습 통과 + 복습 불필요**를 모두 만족할 때만 표시합니다. 과거 통과 기록은 유지하되 최신 퀴즈 또는 실습이 실패하면 복습이 필요한 상태가 되며, 학습자가 수동으로 복습 표시를 켜고 끌 수도 있습니다. 아직 자동 채점이 없는 트랙은 실습과 전체 숙달을 완료로 표시하지 않습니다.

코드 초안은 저장 직전에 최신 데이터를 읽고 해당 문제만 갱신합니다. 다른 문제/트랙의 초안은 유지되며, 퀴즈를 풀 때 코드 저장 snapshot을 덮어쓰지 않습니다. 같은 문제를 두 탭에서 동시에 편집하면 마지막 저장이 적용되므로 한 화면에서 편집하세요.

통합 복원은 최대 5MB의 JSON을 받으며 알려진 단원 데이터만 정규화합니다. 저장 도중 오류가 나면 이미 쓴 키를 원래 값으로 되돌립니다. 기존 제출 이력 v1 파일을 가져올 때는 C 연습 범위만 교체하고 Rust 등 다른 트랙과 퀴즈 진도를 보존합니다. 복원 범위의 현재 데이터는 교체되므로 먼저 최신 통합 백업을 내려받으세요.

다중 파일 초안은 `src/multi-file.js`의 버전 표식이 있는 문자열 하나로 직렬화합니다. 따라서 기존 `codeweave.drafts.v1`, `codeweave.iterations.v1`, 통합 백업 v1 형식을 바꾸지 않습니다. 파일명은 경로가 아닌 허용 목록과 정확히 일치해야 하며, 누락·중복·추가 파일과 파일별/전체 크기 초과는 GCC 실행 전에 거부합니다. 이 입력 검증도 제출 C 코드 자체를 격리하지는 않습니다.

## 요청·컴파일·실행 제한

C 컴파일 옵션은 `-std=c11 -Wall -Wextra -Werror -Wpedantic`으로 고정한다. 활성 경고는 컴파일 실패이며 사례를 실행하지 않는다. 세부 정책은 [시스템 설계](ARCHITECTURE.md)를 참조한다.

Linux/macOS 제출은 별도 프로세스 그룹과 Bash `ulimit`(프로세스당 CPU 2초·파일당 2MiB·UID 프로세스 Linux128개/macOS512개), 사례별 벽시계 1.3초·stdout/stderr 각각 30,000바이트를 적용하며 제한 설정 실패 시 실행하지 않습니다. 가상 주소 공간은 Linux에서 전체 64MiB, macOS에서 기동 Bash의 실제 매핑 크기 + 64MiB를 상한으로 설정합니다(macOS 공유 영역의 큰 초기 매핑 포함; RSS/전체 그룹 메모리 제한이 아님). 더 엄격한 상속 soft/hard 제한은 유지합니다. 프로세스 제한은 같은 UID 전체에 적용되며 Linux root/권한 보유 프로세스에는 강제되지 않으므로 일반 계정으로 실행하세요.

Windows에서는 POSIX 프로세스 그룹 및 위 CPU·가상 메모리·파일 크기·프로세스 수 제한이 적용되지 않습니다. 벽시계/출력 제한과 직접 자식 종료만 적용됩니다.

채점 코드는 기존 JavaScript 문자열 길이 기준 25,000단위까지 허용합니다(한글 한 글자 1단위, 이모지 등 보조 평면 문자 2단위). JSON 요청 본문은 UTF-8 **104,096바이트 = 25,000 × 4 + 4,096**까지이며 JSON 이스케이프·메타데이터·공백도 포함합니다. 코드 길이 초과는 400, 본문 바이트 초과는 413으로 GCC 실행·임시 소스 생성 전에 거부합니다. 다중 파일의 파일별·전체·v1 직렬화 길이 제한은 그대로 유지합니다.

**주의:** 이 로컬 서버는 작성한 C 소스 코드를 사용자의 OS에서 실행하며 실행 격리가 되지 않습니다. **신뢰하는 본인의 코드만 제출하고 서버를 공용 네트워크에 절대 공개하지 마세요.** 공개 채점 기능은 별도 샌드박스 시스템 구축 후 제공해야 합니다. Rust는 위의 명시적 신뢰 로컬 구성에서만 실행 가능하고 F01 학습자 실습은 아직 연결되지 않았습니다. 자료구조·알고리즘의 등록된 C 문제는 기존 GCC 함수형 채점을 사용합니다.

## 정적 서비스와 진단

정적 호스팅(GitHub Pages 등)에서는 단원·퀴즈·코드 작성과 저장만 사용할 수 있으며 **코드 컴파일·자동 채점 버튼은 연결 실패를 안내**합니다.

로컬 정적 서버는 `server/static-files.mjs`에 명시한 학습 화면·브라우저 모듈·PWA 자산만 제공합니다. Git 메타데이터, 환경 파일, 서버 코드, 테스트, 문서와 미등록 파일은 HTTP로 제공하지 않으며 심볼릭 링크와 잘못된 경로도 차단합니다. 새 학습 자산을 추가할 때는 허용 목록과 `tests/static-server.test.mjs`도 갱신하세요. 이 파일 접근 정책은 C 실행을 격리하지 않습니다.

컴파일이 실패하면 `src/compiler-feedback.js`가 GCC/링커 원문을 수정하지 않고 초보자가 먼저 확인할 한국어 범주와 점검 항목을 덧붙입니다. 이 안내는 정답 추론이나 AI 멘토링이 아니라 결정적인 진단 패턴의 고정 분류이며, 알 수 없는 오류는 일반 컴파일 또는 링크 오류로 남깁니다. 피드백은 제출 이력과 통합 백업 v1의 선택 필드로 보존되고 과거 기록은 그대로 읽을 수 있습니다.
