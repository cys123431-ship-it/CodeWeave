# 통합 교육과정 로드맵 (초안)

> 아래 장 구성은 최종 목차가 아닙니다. 두 교재의 전체 내용 분석과 주제 매핑을 거쳐 확정해야 합니다.

## 퀴즈 및 코딩 문제 정책

- **Concept Check:** 2~5문항 짧은 퀴즈, 직접 판단하는 문제
- **Concept Exercise:** 해당 단원에 대한 작은 코드 작성 문제와 공개된 예시
- **Practice Exercise:** 단원 복합 문제와 여러 입력·경계값 자동 테스트
- **Challenge:** 스스로 자료구조·알고리즘 설계/구현, 난도 별 학습 목표
- **Capstone:** 새로 배운 내용을 묶어 사용하는 완성형 프로젝트

## 시제품의 구현 범위

현재 시제품에는 C 12개 샘플, Rust 1개, 자료구조 1개, 알고리즘 1개만 작성되어 있음. C 함수 단원은 상세 원고·정적 호출 도식·퀴즈·전체 프로그램형 `clamp` 실습을 연결했다. 함수 본문만 제출하는 실습은 `clamp`, 배열 최댓값, 문자열 문자 세기, 용량 제한 문자열 길이 네 개다. 배열 실습은 길이·출력 포인터·실패 시 출력 보존을, 문자열 실습은 널 종료·읽기 경계·`const`·종료 문자 제외 계약을 검사한다. 용량 제한 실습은 `[0, capacity)`의 정확한 경계를 다루고, 후속 전체 프로그램형 `fgets` 실습은 8칸 버퍼의 여러 조각을 소비해 빈 줄·정확한 7바이트 경계·개행 없는 마지막 줄·즉시 EOF·첫 줄 종료를 구분한다. 다중 파일 실습은 `main.c`·`functions.c`·`functions.h`를 나누어 컴파일·링크한다. 대규모 본문/문제 생성은 별도 후속 작업이 필요하다.

현재 진도 화면은 이론 읽기, 퀴즈 통과, C 실습 통과, 복습 필요, 전체 숙달을 서로 다른 상태로 계산한다. 이는 교육과정 완성도를 뜻하지 않으며, 자동 채점이 없는 트랙은 실습·숙달을 완료로 표시하지 않는다.

15개 시범 연습은 Concept/Practice, 언어, 선수 단원, 개념, 채점기, 공개 예시 메타데이터를 갖는다. 실제 채점 가능한 C 문제는 전체 프로그램 입출력형 7개, 함수 직접 호출형 4개, 다중 파일형 1개다. 함수형은 사용자 소스와 서버 전용 하네스를 별도 번역 단위로 링크해 반환값과 불필요한 출력 부작용을 검사한다. 배열 문제는 음수·중복·한 원소·`INT_MIN`/`INT_MAX`와 세 가지 잘못된 입력 계약을, 문자열 문자 세기 문제는 빈 문자열·대소문자·없는 문자·`target == '\0'`·`NULL` 계약과 출력 보존을 포함한다. 용량 제한 문자열 문제는 정확한 마지막 칸, 범위 밖 종료 문자, 비종료 버퍼, 용량 0과 포인터 오류를 포함한다. `fgets` 문제는 9개 입력으로 조각 누적과 줄/EOF 경계를 검사하지만 일반 파이프로 재현하기 어려운 입력 오류 분기의 실제 발생까지 검증했다고 주장하지 않는다. 다중 파일형은 고정 파일 계약과 크기를 먼저 검증하고 두 `.c` 파일을 헤더 검색 경로와 함께 컴파일한다. 컴파일 실패는 원문을 보존하면서 누락 헤더·선언/정의 충돌·미정의 참조·중복 정의·일반 컴파일/링크 오류로 구분하여 재제출 때 확인할 항목을 안내한다. Rust 채점은 아직 구현하지 않았다.
